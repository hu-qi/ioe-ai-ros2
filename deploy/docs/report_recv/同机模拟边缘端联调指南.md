# 同机模拟边缘端联调指南

> 适用场景：在没有真实边缘端设备（touch_ui_plugin）的情况下，在同一台主机上模拟边缘端，完成与 app_mgr 平台侧 report_recv 插件的端到端联调。
> 关联文档：[报告接收插件使用指南](./报告接收插件使用指南.md)、[配置说明](./配置说明.md)、doc/70、doc/38、doc/45

---

## 1. 方案概述

### 1.1 原理

report_recv（报告接收插件）是**纯 HTTP 链路**，不走 ROS2 话题订阅。因此"模拟边缘端"本质上是模拟一个 HTTP 客户端，往 app_mgr 平台侧的 9183 端口发请求。

```
┌──────────────────────────────────────────────────────────┐
│  同一台主机                                               │
│                                                          │
│  ┌───────────────────┐    HTTP     ┌──────────────────┐ │
│  │ 模拟边缘端        │ ───────────→ │ app_mgr 平台     │ │
│  │ simulate_edge_   │  127.0.0.1   │ report_recv 插件 │ │
│  │ device.py        │   :9183      │ (9 个端点)       │ │
│  └───────────────────┘             └──────────────────┘ │
└──────────────────────────────────────────────────────────┘
```

### 1.2 可行性判断

| 条件 | 要求 | 说明 |
|---|---|---|
| 平台 HTTP 服务已启动 | 9183 端口监听 0.0.0.0 | `web_monitor.yaml` 的 `enabled: true` |
| report_recv 路由已注册 | 9 个 `/api/v1/*` 端点可达 | 随 Web 服务器自动注册 |
| 边缘端模拟工具 | curl 或 python3 | 仅需 HTTP 客户端能力 |
| 网络连通性 | `127.0.0.1` 回环 | 同机模拟无需跨网段 |

### 1.3 适用范围

| 可验证 | 不可验证 |
|---|---|
| ✅ 订阅→增量→整包完整 HTTP 链路 | ❌ 真实 touch_ui_plugin 的攒批策略 |
| ✅ report_recv 六表入库正确性 | ❌ 边缘端订阅轮询时机 |
| ✅ 整包幂等去重 | ❌ 跨网段延迟/丢包 |
| ✅ 增量事件追加与存根报告创建 | ❌ 真机抓拍图上传的硬件行为 |
| ✅ 多设备并发订阅 | ❌ ROS2 话题链路（仓位检测） |

> **注意**：仓位检测链路（`bay_status_fusion` 插件，ROS2 话题 `/dev01_object_status`）不能用本方案模拟，需要发布 `BayStatus` 消息，详见 `config/plugin_configs/bay_status_fusion.yaml`。

## 2. 前置准备

### 2.1 确认 app_mgr 服务状态

```bash
# 服务是否运行
systemctl is-active app_mgr                    # 期望: active

# 9183 端口是否监听
ss -tlnp | grep 9183                           # 期望: LISTEN 0.0.0.0:9183

# report_recv 路由是否注册
curl -s -o /dev/null -w "HTTP %{http_code}\n" http://127.0.0.1:9183/api/v1/reports
# 期望: HTTP 200
```

### 2.2 确认代码版本一致

**关键**：运行中的 app_mgr 必须使用包含 report_recv 插件的最新代码。如果工作区代码与运行中代码不一致，需要重新部署。

```bash
# 检查工作区是否有 report_recv_plugin.py
ls app_mgr_object/components/web/report_recv_plugin.py

# 检查 ros2_ws/src 是否指向工作区（符号链接方式）
ls -la /root/ros2_ws/src/app_mgr_object
# 期望: -> /root/ioe-ai/code-workspace
```

如果 `ros2_ws/src/app_mgr_object` 不是符号链接指向工作区，按以下步骤处理：

```bash
# 1. 备份/移除旧的 src/app_mgr_object
mv /root/ros2_ws/src/app_mgr_object /root/ros2_ws/src/app_mgr_object.bak.$(date +%s)

# 2. 创建符号链接
ln -s /root/ioe-ai/code-workspace /root/ros2_ws/src/app_mgr_object

# 3. 重新编译
cd /root/ros2_ws
source /opt/ros/jazzy/setup.bash          # 根据实际 ROS 版本调整
colcon build --packages-select app_mgr_object --symlink-install

# 4. 重启服务
systemctl restart app_mgr
sleep 8                                    # 等待 Web 服务器启动
ss -tlnp | grep 9183                       # 确认端口监听
```

## 3. 联调脚本使用

### 3.1 脚本位置

```
scripts/simulate_edge_device.py
```

### 3.2 命令参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--host` | `127.0.0.1` | 平台 IP（同机模拟用回环） |
| `--port` | `9183` | 平台端口 |
| `--device` | `dev_sim01` | 模拟设备 ID |

### 3.3 运行示例

```bash
# 同机模拟（默认）
python3 scripts/simulate_edge_device.py

# 指定设备 ID
python3 scripts/simulate_edge_device.py --device dev02

# 真机联调时，换平台 IP 即可
python3 scripts/simulate_edge_device.py --host 192.168.31.249 --port 9183 --device dev01
```

### 3.4 脚本执行的 5 个步骤

| 步骤 | HTTP 调用 | 验证点 |
|---|---|---|
| ① 订阅设备 | `POST /api/v1/subscriptions` | 返回 `active: true` |
| ② 轮询订阅状态 | `GET /api/v1/subscriptions/{device_id}` | 返回 `active: true` |
| ③ 上报增量事件 | `POST /api/v1/events` | 返回 `delta_events: 2` |
| ④ 上报整包报告 | `POST /api/v1/reports` | 返回 `report_id` |
| ⑤ 验证入库结果 | `GET /api/v1/reports` + `GET /api/v1/reports/{report_id}` | 列表 total ≥ 1，详情 events 数正确 |

### 3.5 预期输出


```bash
print('\n--- report_progress 表 ---')

"
```

## 5. 手动联调（curl 方式）

如果不想用脚本，也可以手动逐条发 curl 验证：

```bash
# ① 订阅设备
curl -s -X POST http://127.0.0.1:9183/api/v1/subscriptions \
  -H "Content-Type: application/json" \
  -d '{"device_id":"dev_manual","note":"手动联调"}'

# ② 查询订阅状态
curl -s http://127.0.0.1:9183/api/v1/subscriptions/dev_manual

# ③ 上报增量事件
curl -s -X POST http://127.0.0.1:9183/api/v1/events \
  -H "Content-Type: application/json" \
  -d '{
    "schema_version": "1.1", "device_id": "dev_manual",
    "round_start_ms": 1788789482488, "ts_upload_ms": 1788789483000,
    "events": [{"ts": 1000, "kind": 0, "step": 1, "sub": 1}]
  }'

# ④ 上报整包报告
curl -s -X POST http://127.0.0.1:9183/api/v1/reports \
  -H "Content-Type: application/json" \
  -d '{
    "schema_version": "1.0", "device_id": "dev_manual",
    "ts_upload_ms": 1788789484000,
    "round": {"start_ms": 1788789482488, "finish_reason": "completed",
              "duration_ms": 87000, "events": [], "steps": [], "substeps": []}
  }'

# ⑤ 验证
curl -s "http://127.0.0.1:9183/api/v1/reports?device_id=dev_manual"

# 清理（退订）
curl -s -X DELETE http://127.0.0.1:9183/api/v1/subscriptions/dev_manual
```

## 6. 常见问题

### 6.1 HTTP 404 — 路由不存在

**根因**：运行中的 app_mgr 是旧版本代码，没有 report_recv 插件。

**排查**：
```bash
# 检查运行中代码是否有 report_recv
ls /root/ros2_ws/install/app_mgr_object/lib/python3*/site-packages/app_mgr_object/components/web/report_recv_plugin.py
# 如果不存在，说明运行的是旧代码
```

**修复**：按 §2.2 步骤重新部署代码并重启服务。

### 6.2 HTTP 连接被拒绝

**根因**：app_mgr 服务未运行，或 9183 端口未监听。

**排查**：
```bash
systemctl status app_mgr
ss -tlnp | grep 9183
journalctl -u app_mgr --no-pager -n 50
```

### 6.3 脚本报 `HTTP -1` 或超时

**根因**：`--host` 参数填错，或平台防火墙拦截。

**排查**：
```bash
# 确认 host 可达
ping <host>
curl -v http://<host>:9183/api/v1/reports
```

### 6.4 数据库查询不到数据

**根因**：app_mgr 运行时使用的工作目录与查找 app.db 的路径不一致。

**排查**：
```bash
# 查找所有 app.db 文件
find /root/ros2_ws -name "app.db" 2>/dev/null

# 检查 app_mgr 进程的工作目录
ls -la /proc/$(pgrep -f app_mgr_node | head -1)/cwd
```

## 7. 从同机模拟迁移到真机联调

### 7.1 差异对比

| 维度 | 同机模拟 | 真机联调 |
|---|---|---|
| 平台 IP | `127.0.0.1`（回环） | 平台实际 IP，如 `192.168.31.249` |
| 边缘端 | Python 脚本模拟 | 真实 touch_ui_plugin |
| 网络环境 | 回环，零延迟 | 跨网段/跨主机，有延迟 |
| 数据落库 | 同机 SQLite | 同机 SQLite（平台侧） |

### 7.2 迁移步骤

1. **确认平台 IP**：在平台主机上执行 `hostname -I` 获取实际 IP
2. **边缘端配置**：在 touch_ui_plugin 的 `params.yaml` 中填入平台 IP
3. **防火墙放行**：平台侧放行 9183 端口入站
4. **网络连通性测试**：边缘端执行 `curl http://<平台IP>:9183/api/v1/reports` 确认可达
5. **按 §3.3 真机联调示例跑脚本**：`--host` 换成平台 IP，验证链路

### 7.3 边缘端配置项（touch_ui_plugin 侧）

| 配置项 | 真机联调示例值 | 说明 |
|---|---|---|
| `report_enabled` | `true` | 开启整包上报 |
| `report_upload` | `"http-post"` | 上报方式 |
| `report_upload_url` | `http://<平台IP>:9183/api/v1/reports` | 整包接收端点 |
| `report_subscribe_api` | `http://<平台IP>:9183/api/v1/subscriptions/{device_id}` | 订阅状态查询端点 |
| `realtime_events_api` | `http://<平台IP>:9183/api/v1/events` | 增量事件接收端点 |
| `subscribe_poll_sec` | `5` | 订阅状态轮询间隔 |
| `realtime_upload_sec` | `2` | 增量事件攒批上报间隔 |

> **关于边缘端如何"知道"平台 IP**：边缘端是 HTTP 客户端，必须知道服务端地址才能发请求。常见的获取方式有三种：(1) 配置文件写死（当前方案）；(2) DNS 解析（适合多设备有内网 DNS 的场景）；(3) 服务发现如 mDNS/Consul（适合大规模动态部署）。无论哪种方式，边缘端在发请求时必须持有目标地址——这是 HTTP 协议的基本要求，无法绕过。
