### 0.3 后端 API 数据形状

**GET /api/bay/status** → `{bays:[{bay_id, cargo_type, bind_status, bind_status_label, ai_detected, in_task, bind_time, bind_duration, last_seen}], total, bound_count, in_task_count, by_type}`

**GET /api/dest/status** → `{bays:[{bay_id, cargo_type, floor_no, is_empty, update_time}], total, empty_count, by_floor}`

**GET /api/agv/status** → `{robots:[{robot_id, status, battery, position_code, current_task_id}], available_count, total}`

**GET /api/task/instances** → `{instances:[{task_id, status, current_state, src_bay, dst_bay, robot_id, created_at}], count}`

**GET /api/task/queue** → `{queue:[...], size}`

**GET /api/task/history?limit=5** → `{history:[{task_id, status, current_state, src_bay, dst_bay, created_at, completed_at}], total}`

**GET /api/alarms?limit=5&acknowledged=false** → `{success, alarms:[{id, type, level, message, timestamp, time_str, acknowledged, resolved, source}]}`

## 2. 各区域详细设计

### 2.1 ROW 0: 系统状态条

- 高度 36px，深色背景 `#1a2736`，底部 1px 边框
- 左侧：运行模式 + 节点数/通道数/AGV 数，各带绿色状态圆点
- 右侧：告警角标（红色气泡） + 实时时钟
- 数据源：WS `status_periodic` 每 5s 推送，`GET /api/status` 首屏加载
- 告警角标：WS `alarm_update` 增量更新计数

### 2.2 ROW 1 左侧：仓位热力图区 (col-lg-9)

**2.2.1 起始仓 4 个区（A/B/C/D）**

每个仓位区是一个 `.bay-zone-card`：
- 卡片标题：带彩色区号标签（A=蓝、B=绿、C=橙、D=紫）
- 卡片内容：6 个矩形仓位 `.bay-cell` 横向排列（`flex-wrap: nowrap`）
- 每个仓位格显示：bay_id（如 "A1001"）+ cargo_type 背景色 + bind_status 状态标记

**仓位格子渲染规则**：

```javascript
const CARGO_COLORS = {
    1: '#2980b9', // 蓝
    2: '#27ae60', // 绿
    3: '#e67e22', // 橙
    4: '#8e44ad', // 紫
    5: '#16a085', // 青
    6: '#c0392b', // 红
};

function renderBayCell(bay) {
    const color = CARGO_COLORS[bay.cargo_type] || '#555';
    let cssClass = 'bay-cell';
    if (bay.bind_status === 1) cssClass += ' bay-bound';
    else if (bay.bind_status === 2) cssClass += ' bay-binding';
    else cssClass += ' bay-idle';
    if (bay.in_task) cssClass += ' bay-in-task';

    return `<div class="${cssClass}" style="background:${color}"
        data-bay-id="${bay.bay_id}" data-cargo-type="${bay.cargo_type}"
        title="${bay.bay_id} | type:${bay.cargo_type} | ${bay.bind_status_label}${bay.in_task ? ' | 执行中' : ''}">
        <span class="bay-label">${bay.bay_id}</span>
        ${bay.bind_status === 1 ? '<span class="bay-dot"></span>' : ''}
    </div>`;
}
```

**交互**：点击仓位格 → Modal 弹窗 → 下拉选择 cargo_type（1~6）→ PUT /api/config/bay → Toast "已更新"

**2.2.2 目的仓 3 个楼层（2F/3F/4F）**

每层一个 `.dest-zone-card`：
- 卡片标题：楼层标签（2F=绿、3F=蓝、4F=橙）
- 卡片内容：6 个矩形仓位 `.dest-cell` 横向排列
- 填充色按 is_empty：绿色（空可用）/ 灰色（占用中）
- 右下角数字角标显示 cargo_type

**2.2.3 AGV 状态卡片**

横向排列的 AGV 状态卡片 `.agv-card`：
- 左侧彩色竖条（绿色=空闲、橙色=充电、红色=离线）
- 主体：AGV ID + 状态文字 + 电量进度条
- 电量 < 20% 时红色闪烁动画

### 2.3 ROW 1 右侧：任务操作控制区 (col-lg-3)

垂直排列的 4 个操作区块：

| 区块 | 内容 | API |
|---|---|---|
| 强制触发 | src 下拉 + dst 下拉 + [执行] 按钮 | POST /api/task/control force_trigger |
| 查询任务 | task_id 输入框 + [查询] 按钮 | POST /api/task/control query |
| 取消/重试 | task_id 输入框 + [取消][重试] 并排按钮 | POST /api/task/control cancel/retry |
| 刷新 | [刷新全部状态] 按钮 | GET /api/business/summary |

交互细节：
- 强制触发前校验 src ≠ dst，否则 Toast 警告
- 操作结果：成功 Toast 绿色 "操作成功"，失败 Toast 红色错误信息
- [执行] 按钮点击后显示 2s loading 状态（`fa-spinner fa-spin`）

### 2.4 ROW 2: 任务面板

Tab 切换三面板：
- **活跃任务**（默认）：`GET /api/task/instances` → 表格列：task_id / 路线(src→dst) / 状态 / AGV / 时间 / 操作
- **任务队列**：`GET /api/task/queue` → 表格列：候选编号 / src / dst / cargo_type / 入队时间
- **历史最近 5 条**：`GET /api/task/history?limit=5` → 表格列：task_id / 路线 / 最终状态 / 创建时间 / 完成时间

**表格样式**：

```css
.task-table { font-size: 13px; }

```

### 2.5 ROW 3: 告警信息栏

- 最多显示 5 条未确认告警（`GET /api/alarms?limit=5&acknowledged=false`）
- 每条告警行：左侧彩色竖线 + 告警级别图标 + 消息 + 时间 + [确认][解决] 按钮
- 底部 [查看全部告警 →] 链接跳转到 `/control`（运维控制页的告警管理标签）
- 收到 WS `alarm_update` 时，在列表顶部插入新告警（淡入动画）
- 0 条告警时显示 "✅ 暂无告警" 绿色文字

### 4.2 初始化流程

```
DOMContentLoaded
  → WS.connect()            ← 建立 WebSocket 连接
  → loadAllData()           ← 并行请求 5 个 API
      → API.getBayStatus()    → renderBayGrid()
      → API.getDestStatus()   → renderDestGrid()
      → API.getAgvStatus()    → renderAgvCards()
      → API.getTaskInstances()→ renderTaskTable('active')
      → API.getAlarms(5)      → renderAlarmList()
  → WS 事件注册
      → WS.on('business_update', (msg) → refreshBayDestAgvTask(msg.data))
      → WS.on('alarm_update',      (msg) → prependAlarms(msg.new_alarms))
      → WS.on('status_periodic',   (msg) → updateSystemBar(msg.data))
      → WS.on('config_updated',    (msg) → toast('配置已更新: ' + msg.section))
  → setInterval(updateClock, 1000)
```

### 4.3 数据驱动渲染

```javascript
// 仓位分组映射
const BAY_GROUP_MAP = {
    'bay-zone-a': ['A1001','A1002','A1003','A1004','A1005','A1006'],
    'bay-zone-b': ['B1001','B1002','B1003','B1004','B1005','B1006'],
    'bay-zone-c': ['C1001','C1002','C1003','C1004','C1005','C1006'],
    'bay-zone-d': ['D1001','D1002','D1003','D1004','D1005','D1006'],
};

function renderBayGrid(bays) {
    const bayMap = {};
    bays.forEach(b => { bayMap[b.bay_id] = b; });

    Object.entries(BAY_GROUP_MAP).forEach(([zoneId, ids]) => {
        const container = document.getElementById(zoneId);
        if (!container) return;
        container.innerHTML = ids.map(id => {
            const bay = bayMap[id];
            return bay ? renderBayCell(bay) : `<div class="bay-cell bay-idle" style="background:#333">
                <span class="bay-label">${id}</span></div>`;
        }).join('');
    });
}
```
