|---|---|

## 3. 问题 2：首页状态/任务/告警主动推送修复

### 3.1 根因分析

**根因 A —— 任务完成事件在实例移除前采集（悬空显示的真正原因）**

`workflow/engine.py` 的 `_run_instance` 执行顺序：

```python
await instance.run()
# ↓ 终态回调（此时实例仍在 self._instances 中！）
if self.on_instance_completed and ...:
    self.on_instance_completed(instance)   # → 发布 workflow.task_completed
finally:
    self._instances.pop(instance.id, None) # ← 之后才移除
```

事件链：

```text
workflow.task_completed
  → web EventBridge._on_business_event（同步采集）
  → business_collector.get_active_instances()
  → 实例仍在 _instances（status='completed'）→ 首页"活跃"Tab 渲染该终态任务
  → engine finally pop（无任何新事件）→ 页面悬空，需手动刷新才消失
```

**根因 B —— 轮询类状态没有推送事件**

- `status_poller` 每 3s/10s 轮询更新 `RobotCache`/`DestBayCache`，无事件发布 → 首页 AGV 卡片、目的仓状态只有业务事件或手动刷新才更新；
- `TaskQueue` 入队/出队无事件 → 队列面板只在业务事件附带时更新；
- `status_periodic`（5s）与 `status_update`（10s）均只推系统状态，**不含业务数据**。

**根因 C —— 任务级告警未接入 alarm_update**

`rcs.alarm_logged` / `rcs.critical_alarm` 有发布无订阅（文档 41 第 5 章方案未在 0.1.5 落地）。

### 3.2 解决思路

```text
方案 A（前端防御，必做）：dashboard.js 渲染"活跃"时过滤终态实例
  → completed/failed/cancelled 不显示在活跃栏（由"最近完成"承载）

方案 B（事件时序修复，必做）：web EventBridge 业务事件改为"防抖 + 延迟采集"
  → 事件触发后 0.4s 再采集推送，确保引擎已完成实例移除
  → 多个事件合并为一次推送，降低 WS 压力

方案 C（周期快照变更检测，推荐）：web_monitor 监控线程周期采集业务快照
  → 对 bay/dest/agv/queue/instances 计算轻量 hash，变化才推送 business_update
  → 覆盖轮询类状态（AGV/目的仓/队列）与事件丢失兜底

方案 D（可选深修）：engine 终态回调移到 _instances.pop 之后
  → 从根上消除"回调时实例仍存在"的时序问题

方案 E（可选补全）：任务级告警接入 alarm_update（文档 41 §5.3 落地）
```

### 3.4 方案 B：业务事件防抖延迟采集（`components/web/event_bridge.py`）

```python
class EventBridge:
    def __init__(self, node, web_server):
        ...
        self._subscribed = False
        # ===== 新增：业务刷新防抖标记 =====
        self._refresh_pending = False
        self._refresh_delay = 0.4   # 秒；等待引擎实例移除完成

    def _on_business_event(self, data: dict):
        """业务事件回调 → 防抖延迟采集推送。

        延迟原因：workflow.task_completed 等事件在引擎 _instances.pop 之前发布，
        若立即采集会把已终态实例带进 active_instances，导致首页悬空显示。
        """
        self._schedule_business_refresh()

    def _schedule_business_refresh(self):
        """合并事件：已有待执行刷新则不再调度（采集发生在执行时，取最新状态）"""
        if self._refresh_pending:
            return
        self._refresh_pending = True
        loop = getattr(self.node, 'asyncio_loop', None)
        if loop is None or loop.is_closed():
            self._refresh_pending = False
            return

        async def _delayed_refresh():
            try:
                await asyncio.sleep(self._refresh_delay)
                bc = getattr(self.node, 'business_collector', None)
                if bc:
                    summary = bc.collect_business_status()
                    self.broadcast('business_update', summary)
            except Exception as e:
                self.logger.debug(f"业务事件推送失败: {e}")
            finally:
                self._refresh_pending = False

        try:
            asyncio.run_coroutine_threadsafe(_delayed_refresh(), loop)
        except Exception as e:
            self._refresh_pending = False
            self.logger.debug(f"业务刷新调度失败: {e}")
```

> 说明：`_on_business_event` 可能运行在 ROS 回调线程，因此使用 `run_coroutine_threadsafe` 投递到 `node.asyncio_loop`（线程安全）；防抖 0.4s 远小于人工感知，多个事件合并为一次推送。

### 3.5 方案 C：周期业务快照 + 变更检测推送（`plugins/web_monitor_plugin.py`）

```python
# __init__ 或 _activate_impl 中初始化：
self._last_business_hash = None

def _snapshot_hash(self, summary: dict) -> str:
    """业务快照轻量指纹：仅比较前端关注的字段"""
    import hashlib, json
    compact = {
        'bay': [(b.get('bay_id'), b.get('bind_status'), b.get('in_task'),
                 b.get('cargo_type'))
                for b in (summary.get('bay') or {}).get('bays', [])],
        'dest': [(b.get('bay_id'), b.get('is_empty'))
                 for b in (summary.get('dest') or {}).get('bays', [])],
        'agv': [(r.get('robot_id'), r.get('status'), r.get('battery'))
                for r in (summary.get('agv') or {}).get('robots', [])],
        'queue': [(q.get('src_bay'), q.get('dst_bay'), q.get('cargo_type'))
                  for q in (summary.get('task_queue') or {}).get('queue', [])],
        'instances': [(i.get('task_id'), i.get('status'), i.get('current_state'))
                      for i in (summary.get('active_instances') or {}).get('instances', [])],
    }
    return hashlib.md5(
        json.dumps(compact, sort_keys=True, default=str).encode()
    ).hexdigest()

def _start_monitoring(self):
    """启动状态监控线程"""
    def monitoring_loop():
        monitor_interval = self.plugin_config.get('monitor_interval', 5.0)
        while not self._stop_event.is_set():
            try:
                status = self._get_system_status()
                # 告警检查 — alarm_manager 已启用
                self._check_and_generate_alarms(status)
                # 状态广播 — 通过 event_bridge
                if self.event_bridge:
                    self.event_bridge.broadcast_status_periodic(status)

                # ===== 新增：业务快照变更检测推送 =====
                try:
                    summary = self.business_collector.collect_business_status()
                    h = self._snapshot_hash(summary)
                    if h != self._last_business_hash:
                        self._last_business_hash = h
                        self.event_bridge.broadcast('business_update', summary)
                except Exception as e:
                    self.logger.debug(f"业务快照推送失败: {e}")
                # ======================================

            except Exception as e:
                self.logger.error(f"状态监控循环错误: {e}")
            self._stop_event.wait(monitor_interval)

    self._monitoring_thread = threading.Thread(target=monitoring_loop, daemon=True)
    self._monitoring_thread.start()
    self.logger.info(f"状态监控线程启动，间隔: {self.plugin_config.get('monitor_interval')}秒")
```

> 说明：该方案覆盖"轮询类状态变化"（AGV/目的仓/队列），并作为事件推送的兜底；`hash` 相同不推送，避免刷屏。前端 `business_update` 处理已就绪，无需改动。

### 3.6 方案 D（可选深修）：引擎终态回调后置（`components/workflow/engine.py`）

```python
async def _run_instance(self, instance: WorkflowInstance):
    """在协程中执行实例（带并发控制）"""
    self._logger.info(f"[Engine] _run_instance 开始: {instance.id}")
    async with self._semaphore:
        self._logger.info(f"[Engine] _run_instance 获取信号量: {instance.id}")
        error = None
        try:
            if self.on_instance_started:
                self.on_instance_started(instance)
            await instance.run()
        except Exception as e:
            self._logger.error(f"[Engine] _run_instance 捕获异常: {e}")
            import traceback
            self._logger.error(traceback.format_exc())
            try:
                await instance.run_on_error(e)
            except Exception as oe:
                self._logger.error(f"[Engine] on_error 兜底执行异常: {oe}")
            error = e
        finally:
            # 先移除实例，再分发终态回调：业务采集不再包含已终态实例
            self._instances.pop(instance.id, None)

        # 终态事件分发（实例已移除）
        if instance.status == WorkflowInstanceStatus.FAILED:
            if self.on_instance_failed and not instance.terminal_event_published:
                self.on_instance_failed(instance, error)
        elif (self.on_instance_completed
              and not instance.terminal_event_published):
            self.on_instance_completed(instance)
```

> 影响面：终态事件消费方（smart_trigger 释放续发、task_monitor 停表、web 刷新）均不依赖"实例仍在 _instances"，后置后语义更正确；需回归验证任务完成/失败闭环。

### 3.7 方案 E（可选补全）：任务级告警接入 alarm_update

参照文档 41 §5.3，将以下订阅加入 `components/web/event_bridge.py`：

```python
# subscribe_all 内追加：
event_bus.subscribe('rcs.alarm_logged', self._on_task_alarm_logged)
event_bus.subscribe('rcs.critical_alarm', self._on_task_critical_alarm)

TASK_ALARM_LEVEL_MAP = {
    'INFO': 'info', 'WARNING': 'warning', 'SEVERE': 'error', 'CRITICAL': 'critical',
}

def _on_task_alarm_logged(self, data: dict):
    try:
        task_code = data.get('task_code', '')
        wm = getattr(self.node, 'web_monitor', None)
        if not task_code or not wm or not getattr(wm, 'alarm_manager', None):
            return
        wm.alarm_manager.add_alarm(
            alarm_type='task',
            level=TASK_ALARM_LEVEL_MAP.get(
                str(data.get('alarm_level', '')).upper(), 'info'),
            message=f"[任务 {task_code}] {data.get('warn_code', '告警')}: {data.get('warn_msg', '')}",
            details={'task_id': task_code,
                     'warn_code': data.get('warn_code', ''),
                     'agv_code': data.get('agv_code', '')},
            source='rcs_warn_callback',
        )
    except Exception as e:
        self.logger.debug(f"任务告警展示失败: {e}")

def _on_task_critical_alarm(self, data: dict):
    try:
        task_code = data.get('task_code', '')
        wm = getattr(self.node, 'web_monitor', None)
        if not task_code or not wm or not getattr(wm, 'alarm_manager', None):
            return
        wm.alarm_manager.add_alarm(
            alarm_type='task', level='critical',
            message=f"[任务 {task_code}] 紧急告警: {data.get('warn_msg', '')}",
            details={'task_id': task_code, 'agv_code': data.get('agv_code', '')},
            source='rcs_critical_alarm',
        )
    except Exception as e:
        self.logger.debug(f"紧急告警展示失败: {e}")
```

> 配套：`alarm_manager.py` 的 `AlarmType` 增加 `TASK = "task"`（文档 41 §5.3.1）。

### 4.3 手工回归清单

1. **悬空问题复测**：连续执行 3 个任务，前两个完成、最后一个完成时观察——活跃栏应自动清空（≤1s），不再需要点击"刷新全部状态"；
2. **事件驱动**：强制触发任务 → 活跃栏出现新任务（<1s）；任务完成 → 自动移除并可在"最近完成"看到；
3. **轮询驱动**：手动切换某 AGV 状态（模拟脚本）→ 首页 AGV 卡片 5s 内更新；
4. **告警推送**：产生系统告警 → 徽标与列表实时更新；产生 warnCallback（若方案 E 落地）→ 告警面板出现 task 告警；

6. **WebSocket**：断开后自动重连，重连后页面数据经下一次推送恢复。

### 4.4 风险与回滚

- 方案 A/B/C 相互独立，均可单独提交与回滚；不涉及 SQLite/工作流定义变更；
- 方案 D 会改变终态事件发布时序，需重点回归 smart_trigger（释放续发）与 task_status_monitor（停表）；如回归异常可单独 revert，方案 A/B 已足以解决悬空问题；
- 方案 C 的 hash 只比对前端关注字段，新增字段需同步扩展 `_snapshot_hash`（防止"有变化但未推送"）。
