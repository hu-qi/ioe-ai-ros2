### 1.2 技术选型说明

| 组件 | 选型 | 理由 |
|------|------|------|
| Web 框架 | FastAPI | 异步高性能，自动生成 OpenAPI 文档，易于开发 |
| ORM | SQLAlchemy 2.0 | 成熟稳定，支持 SQLite |
| 数据库 | SQLite（WAL 模式） | 零配置，单文件，适合单机低并发 |
| 定时任务 | APScheduler | 轻量，无需额外中间件 |
| 前端 | Vue3 + Element Plus（按需）+ ECharts（按需） | 组件丰富，触屏友好，树摇优化后体积可控 |
| 构建工具 | Vite 5 | 极速冷启动，产物小 |
| 静态托管 | FastAPI StaticFiles + gzip | 无需 Nginx，减少部署复杂度 |
| 部署 | uvicorn + systemd | 单进程，开机自启，资源占用低 |
| 图片处理 | Pillow | BMP → JPG 转换，缩略图生成 |
| 配置驱动 | YAML | 诊断/评分规则可现场调整，无需改代码 |

### 3.2 整包报告接收与解析（增加 process_name 处理）

```python
@router.post("/api/v1/reports")
async def receive_report(data: dict, db: Session = Depends(get_db), background_tasks: BackgroundTasks = None):
    device_id = data.get("device_id")
    round_data = data.get("round", {})
    if not device_id or not round_data:
        raise HTTPException(400, "missing device_id or round")

    start_ms = round_data.get("start_ms")
    process_name = round_data.get("process_name")   # 关键：提取工序名称
    existing = db.query(Report).filter_by(device_id=device_id, start_ms=start_ms).first()
    if existing:
        return {"code": 0, "message": "duplicate", "data": {"report_id": existing.report_id}}

    student = data.get("student", {})
    student_id = student.get("id")
    report_id = str(uuid.uuid4())

    report = Report(
        report_id=report_id,
        device_id=device_id,
        student_id=student_id,
        process_name=process_name,                  # 存储工序名称
        finish_reason=round_data.get("finish_reason"),
        start_ms=start_ms,
        end_ms=round_data.get("end_ms"),
        duration_ms=round_data.get("duration_ms"),
        raw_data=json.dumps(data, ensure_ascii=False)
    )
    db.add(report)

    for sub in round_data.get("substeps", []):
        db.add(ReportSubstep(
            report_id=report_id,
            substep_index=sub.get("index"),
            substep_name=sub.get("name"),
            state=sub.get("state"),
            duration_ms=sub.get("duration_ms"),
            std_duration_ms=sub.get("std_duration_ms"),
            timeout=sub.get("timeout", 0),
            over_std=sub.get("over_std", 0),
            omitted=sub.get("omitted", 0),
            segments=json.dumps(sub.get("segments", []))
        ))

    for ev in round_data.get("evidence", []):
        exists = db.query(Evidence).filter_by(
            device_id=device_id, round_start_ms=start_ms,
            sub=ev.get("sub"), ts=ev.get("ts")
        ).first()
        if not exists:
            db.add(Evidence(
                device_id=device_id, round_start_ms=start_ms,
                sub=ev.get("sub"), ts=ev.get("ts"),
                file_path=ev.get("file")
            ))

    db.commit()

    if background_tasks:
        background_tasks.add_task(score_report, report_id)   # 评分时会读取 process_name
        background_tasks.add_task(refresh_dashboard_cache)

    return {"code": 0, "message": "ok", "data": {"report_id": report_id}}
```

**解析要点**：
- 从 `round.process_name` 提取工序名称（如“拆解”“组装”），存入 `reports.process_name`。
- 后续评分与诊断均基于该字段选择对应规则集。

其余接口（events、evidence、students）实现不变。

## 四、核心业务模块技术实现（按工序区分）

### 4.1 评分引擎（按 process_name 选择规则）

```python
def score_report(report_id: str):
    with SessionLocal() as db:
        report = db.query(Report).get(report_id)
        process_name = report.process_name or ""      # 工序名称
        substeps = db.query(ReportSubstep).filter_by(report_id=report_id).all()
        total_score = 0.0

        # 加载该工序的评分规则；若不存在则回退到通用规则（process_name=''）
        rules = db.query(ScoringRule).filter(
            ScoringRule.process_name.in_([process_name, ""]),
            ScoringRule.enabled == 1
        ).all()
        rule_map = {r.substep_index: r for r in rules if r.process_name == process_name}
        default_rules = {r.substep_index: r for r in rules if r.process_name == ""}

        for sub in substeps:
            rule = rule_map.get(sub.substep_index) or default_rules.get(sub.substep_index)
            if not rule:
                continue
            base = rule.max_score
            time_factor = min(1.0, rule.std_duration_ms / max(sub.duration_ms, 1))
            acc_factor = {0: 0.0, 1: 0.5, 2: 1.0, 3: 0.5}.get(sub.state, 0.0)
            seq_factor = 0.7 if sub.sequence_error else 1.0
            score = base * time_factor * acc_factor * seq_factor
            if sub.timeout:
                score *= rule.timeout_penalty
            sub.score = round(score, 2)
            total_score += score   # 【v1.3 修正】四系数直接累加；原 score×time_weight 存在双重计权

        # 整轮扣分（可配置，也可按工序区分）
        unexecuted_count = len(json.loads(report.unexecuted_list or "[]"))
        total_score -= unexecuted_count * 2
        repeat_count = count_repeats(report.raw_data)
        total_score -= repeat_count * 1
        if report.finish_reason == 3:
            total_score *= 0.9

        total_score = max(0, round(total_score, 2))
        report.total_score = total_score
        report.grade_level = get_grade_level(total_score)
        db.commit()

        refresh_student_stats(report.student_id)
        refresh_dashboard_cache()
```

**要点**：
- 先查 `process_name` 对应的规则，缺失则回退到 `process_name=''` 的通用规则。
- 评分规则可通过 YAML 配置，按工序分组。

## 九、总结

本技术方案在 v1.1 基础上，**重点补充了按操作名称（工序，如“组装”“拆解”）区分评分与诊断的能力**：

1. **数据模型**：`reports` 表已有 `process_name`，`scoring_rules` 和 `diagnosis_rules` 增加 `process_name` 字段，联合唯一键确保不同工序独立配置。
2. **YAML 配置**：按 `processes` 分组定义各工序的子步骤标准用时、满分、诊断阈值，并支持通用规则回退。
3. **评分引擎**：根据报告的 `process_name` 加载对应规则，缺失时回退通用规则。
4. **诊断引擎**：按工序筛选报告和规则，输出该工序特有的诊断结论。
5. **前端**：增加工序筛选，支持按工序查看看板、学员详情、诊断结果和配置规则。

这一改进使平台能够准确评价组装与拆解等不同工序的操作水平，满足机修培训中差异化教学评价的需求。方案完整覆盖“数据→洞察→行动”链路，轻量化部署，教官开箱即用，可作为开发、验收与合同交付的基准文档。
