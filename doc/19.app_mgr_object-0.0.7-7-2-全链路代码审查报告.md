## 6. 端到端数据流验证

### 6.1 正常运行流程

```
键盘模拟器 (A+1)
  → /dev01_object_status
  → bay_status_fusion (订阅+防抖)
  → rcs_adapter.bindCtnrAndBin
  → jmsy-server (绑定确认)
  → smart_trigger (扫描缓存)
  → trigger.task_created
  → workflow_engine.create_instance()
  → calling_rcs → monitoring → callback_completed → releasing → completed
```

### 6.2 异常告警流程 (新增)

```
warnCallback 到达 (L2: COLLISION)
  → callback_handler._on_warn_callback()
  → EventBus.rcs.warn_callback
  → event_bridge._on_rcs_warn_callback()
  → AlarmClassifier.classify() → SEVERE / callback_exception
  → engine.inject_event('callback_exception')
  → instance: monitoring → manual_intervention
  → log_manual_entry (记录时间戳)
  → task_monitor: 每 30s 轮询 manual 实例
      ├─ RCS 完成 → auto_resolved → auto_recovery → completed
      ├─ RCS 失败 → auto_failed → failed
      └─ 超时 600s → rcs.alarm_escalated
```

### 6.3 运维手动操作流程 (新增)

```
Web Panel / CLI
  → ros2 service call /task_control
  → workflow_engine._on_task_control()
      ├─ force_trigger → create_instance() + log_exception
      ├─ cancel → cancel_instance() + log_exception
      ├─ retry → inject_event('user_retry') + log_exception
      └─ query → get_instance() / DB lookup
```

### 6.4 日志追溯流程

```
Web Panel 查询任务诊断:
  → engine_plugin.query_alarms_by_task(task_id)
  → engine_plugin.query_exceptions_by_task(task_id)
  → engine_plugin.query_state_changes(task_id)
  
仪表盘:
  → engine_plugin.get_exception_summary()
  → {total_exceptions, by_event_type, alarms, recent_24h}
```

## 8. 优化建议

### 8.1 高优先级

#### 建议 1: 清理冗余的 task_monitor 插件

`task_monitor_plugin.py` 与 `task_status_monitor_plugin.py` 功能重叠。建议:
- 确认 `task_monitor_plugin.py` 是否为早期版本残留
- 若是: 从 `plugins/__init__.py` 移除导出, 或直接删除
- 保留 `task_status_monitor_plugin.py` 作为唯一任务监控插件

### 8.2 中优先级

#### 建议 2: 统一 web_monitor 配置

当前 `web_monitor` 配置分散在两处:
1. `plugin_configs` 中 `web_monitor: auto_start: true` (行内)
2. 独立 `web_monitor:` YAML section (行外)

建议统一到独立 section, 从 plugin_configs 中移除行内条目。

#### 建议 3: YAML version 更新

`agv_transport_atomic.yaml` 的 `version: 1` → `version: 2`, 反映 8 次重大增强。

#### 建议 4: 异常日志定期清理

`alarm_logs` / `state_change_log` / `exception_log` 三张表会随时间无限增长。建议:
- 在 `_init_db()` 中增加自动清理 (保留 90 天)
- 或在 task_monitor 中增加每周清理任务

### 8.3 低优先级

#### 建议 5: 增加插件健康检查

在 `get_status()` 中为每个插件增加 `health` 字段 (参考 doc 10 §10.1 建议 1):

```python
def get_status(self) -> dict:
    return {
        'health': 'healthy' if self._running else 'stopped',
        ...
    }
```

#### 建议 6: 增加 RCS 接口调用指标

在 `rcs_adapter_plugin.py` 中增加指标收集 (成功/失败/延迟), 供 Web 仪表盘展示。
