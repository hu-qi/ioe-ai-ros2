## 一、需求与目标

在 app_mgr 仪表盘（index.html）仓位热力图上，为任务配对绘制「始发仓 → 目标仓」连线：

| 阶段 | 表现 | 数据来源 |
|---|---|---|
| 匹配候选已生成、任务未触发 | **虚线**（灰蓝） | `task_queue.queue`（TaskCandidate） |
| 任务已触发、执行中 | **实线 + 流光动画**（亮蓝） | `active_instances.instances`（非终态） |
| 任务完成 / 失败 / 取消 | **连线淡出移除** | 实例从 active_instances 消失 |

### 1.1 视觉设计目标（v2 核心）
- **背景空间走线**：连线只存在于仓位卡片之间的空白背景（两列卡片之间的沟槽 gutter、卡片外侧边缘），**绝不覆盖/穿过任何仓位卡片本体**；
- **不交叉其他仓位**：任何一条线不与仓位卡片矩形相交（端点从卡片边缘引出/引入，路由限制在背景空白带内）；
- **不交叉其他连线**：多条连线在背景带内按**轨道（lane）**分配，垂直段彼此平行、水平段高度错开，无交叉无重叠；
- **曲线平滑**：三次贝塞尔（S 形），拐角圆弧过渡，无生硬折线；
- **干净整洁**：线宽克制但**深色背景高可见**（v3）；颜色克制但**亮色高对比**；端点小圆点在卡片边缘外侧。
- **深色背景高可见（v3 核心）**：仓位区为深色卡片背景，线条必须加粗 + 亮色 + 深色衬底光晕（drop-shadow 双层），保证任何深色背景上清晰可辨；流光动画保持。

成功标准：连线实时跟随任务状态变化；曲线路由不遮挡仓位、不与其他线交叉；坐标准确（resize 不漂移）；不拦截仓位卡片交互；不影响原业务渲染；无 console 错误。

```js
function cellRect(bayId) {
    var el = document.querySelector('[data-bay-id="' + bayId + '"]');
    if (!el) return null;
    var r = el.getBoundingClientRect();
    var s = svg.getBoundingClientRect();
    return { left: r.left - s.left, top: r.top - s.top,
             right: r.right - s.left, bottom: r.bottom - s.top,
             cx: (r.left + r.right) / 2 - s.left, cy: (r.top + r.bottom) / 2 - s.top };
}
```

## 四、背景空间曲线路由模型（v2 核心设计）

### 4.1 布局前提（已核实 index.html 仓位区）
```
card-body（position:relative）
├── 左列 col-md-6：起始仓 2×2（A/B 上排、C/D 下排）
│     [A区 6仓] [B区 6仓]
│     [C区 6仓] [D区 6仓]
└── 右列 col-md-6：目标仓 3 行（2F / 3F / 4F，d-flex column justify-content-between）
      [2F 6仓] / [3F 6仓] / [4F 6仓]
```
- 两列之间存在 Bootstrap `g-2` 沟槽（gutter，默认 0.5rem）；起始仓列右边缘 → 目标仓列左边缘横向相对，**gutter 即天然背景空白带**。
- 起始仓区只有左列上半，目标仓占右列全高——线主要从「左上（起始仓）」到「右侧（目标仓）」，垂直跨度可控。

### 4.2 端点规则（不穿卡片）
- **src 端点**：起始仓卡片**右边缘**中点 `(right, cy)`——线从卡片右侧引出，不覆盖卡片本体与仓位编号文字；
- **dst 端点**：目标仓卡片**左边缘**中点 `(left, cy)`——线从左侧引入；
- 端点在卡片边缘外侧 1px 起笔/收笔，端点小圆点绘制在卡片外侧（`cx ± (2~3px)` 偏移），不压卡片边框。

### 4.3 轨道（lane）分配——不交叉连线
- 背景带中心线：`m = (gutterLeft + gutterRight) / 2`（两列卡片之间的水平中心；实现时取 src 右边缘与 dst 左边缘的中点或固定列分界 x）；
- 每条连线分配**轨道序号** `laneIdx`：
  - 排序分配：同一时刻所有连线按 src 的 `cy` 升序排序 → `laneIdx = 排序位`（相邻 src 高度的线拿到相邻轨道，垂直段天然不交叉）；
  - 确定性：排序稳定（同 cy 按 dst 的 cy 次排序），避免抖动；
- 轨道水平偏移：`dx = (laneIdx - (n-1)/2) * LANE_GAP`，`LANE_GAP = 6px`（线宽 2px + 4px 间距）；背景带总宽需 ≥ `n * 6px`，n ≤ 6 时约 36px——gutter 不足时向两列卡片外侧各扩展（线在卡片**外侧**空白走，不越入卡片）；
- 垂直段：线在背景带内从 `y = src.cy` 到 `y = dst.cy` 的**垂直段位于 `x = m + dx`**——多条线的垂直段水平错开，**永不重叠/交叉**；
- 水平段（引出/引入）：`src.cy` 与 `dst.cy` 各自唯一（每仓一格），同高线至多一条 → 水平段不交叉。

### 4.4 曲线路径（v5 单段三次贝塞尔，无直线段）
```
M sx,sy                 -- src 右边缘中点
C mx,sy  mx,dy  dx,dy   -- 单段三次贝塞尔（全曲线）
```
- `sx=src.right, sy=src.cy, dx=dst.left, dy=dst.cy`；
- `mx = (sx + dx) / 2 + laneDx`（背景带中心 + 轨道偏移）；
- 几何性质：起点切线 = C1-start = 水平向右（从 src 右缘**水平引出**）；终点切线 = end-C2 = 水平向左（**水平引入** dst 左缘）；曲线最深处在 x=mx（背景带内）——**全程曲线、无 L 直线段、无折角**，同高（sy≈dy）退化为水平弓形，跨行自然成 S 弯；
- 轨道偏移 laneDx 使多线最深处水平错开（不交叉），路由仍限制在背景带（gutter + 卡片外侧），不进入任何卡片。

### 4.5 防交叉汇总
- 线 × 卡片：端点贴卡片边缘、路径全在背景带（gutter + 卡片外侧）→ 零相交；
- 线 × 线：垂直段轨道错开（dx）+ 水平段高度唯一（cy）→ 无交叉；
- 多线同 src（罕见，1:1 贪婪保证）→ 按 `laneIdx` 仍错开引出高度（从卡片右边缘不同 y 点引出）。

## 五、PairLineRenderer 设计规范

### 5.1 模块位置与单例
- 新增独立文件 `static/js/pair-lines.js`（职责单一，便于回归；index.html 引入）；
- 单例：`window.PairLines = new PairLineRenderer()`，初始化时查 `#pair-lines`。

### 5.2 状态表与 key
```js
this._lines = {};   // key: 'src→dst' -> { state: 'pending'|'active'|'error', path, nodeS, nodeD, laneIdx }
```
- key 唯一性：`src + '→' + dst`；同一 key 多状态 → **error > active > pending 覆盖**（异常优先，执行次之，候选垫底）。

### 5.3 update(pairs) 算法
1. 遍历入参 pairs：
   - 不存在 → 创建（pending 虚线 / active 实线+流光）；
   - 已存在且 state 变化（pending→active）→ 切换 class（`transition: stroke .3s` 平滑）；
   - 已存在且 state 相同 → 无操作（避免无谓 DOM 操作）。
2. **lane 重分配**：每条线按 4.3 规则计算 `laneIdx`（对**存在线集合**排序分配），并调用 `refresh()` 更新 path 坐标；
3. 收集当前 key 集合，与 `_lines` 比对：不在集合内的旧线 → `remove(key)`（加 `.pair-removing` 过渡 0.6s 后 `remove()` 并删除状态）；
4. 每次 update 后按需 `refresh()`（若新增线或 lane 变化）。

### 5.4 SVG 元素
```html
<path class="pair-line pair-line-active" d="M ... C ..." />
<circle class="pair-node" cx cy r="4" />
```
- 端点圆点：src 起点圆点 + dst 终点圆点，`r=4`（**JS 显式 `setAttribute('r','4')`——SVG circle 默认 r=0 不可见，v3 修复**），画在卡片边缘外侧 2px 处，亮色 + 蓝描边 + 光晕；
- 圆点随 line 一起 update/remove；
- 路径 `d` 由 4.4 公式生成（M + C + L + C）。

### 5.5 关键常量
```js
var LANE_GAP = 6;      // 轨道间距 px
var EDGE_EXT = 14;    // 引出/引入长度 px（窄 gutter 自动缩至 8）
var MAX_LANES = 8;    // 轨道上限（超过则 LANE_GAP 自适应缩小，保底 3px 不交叉）
```

### 7.1 buildPairs(d) —— 数据 → 连线输入（v5 含 error）
```js
function buildPairLines(d) {
    var out = [];
    var now = Date.now() / 1000;
    var tq = (d.task_queue && d.task_queue.queue) || [];
    tq.forEach(function(q) {
        if (q.src_bay && q.dst_bay) out.push({ src: q.src_bay, dst: q.dst_bay, state: 'pending' });
    });
    var inst = (d.active_instances && d.active_instances.instances) || [];
    inst.forEach(function(t) {
        if (TERMINAL_TASK_STATUS[(t.status || '').toLowerCase()]) return;   // completed/cancelled 终态不画
        if (t.src_bay && t.dst_bay) out.push({ src: t.src_bay, dst: t.dst_bay, state: 'active', robot_id: t.robot_id });
    });
    // v5：最近失败任务（event_bridge 缓存，60s 窗口）→ error 红色线
    var rf = (d.recent_failures || []).filter(function(x) {
        return x.src_bay && x.dst_bay && (now - (x.failed_at || 0)) < 60;
    });
    rf.forEach(function(x) {
        out.push({ src: x.src_bay, dst: x.dst_bay, state: 'error', robot_id: x.robot_id });
    });
    return out;
}
```
- 异常数据源：`workflow.task_failed` 事件 → event_bridge `_recent_failures`（deque maxlen=10，含 failed_at）→ business_collector 汇总进 `recent_failures` 字段（failed 实例已从 active_instances 移除，必须走事件缓存）。

## 八、验收标准（测试清单）

1. **状态切换**：仓位绑定→匹配候选出现→虚线（亮青蓝）；任务触发→变实线+流光（高亮蓝）；任务完成/失败→淡出移除，无残留。
2. **深色背景可见（v3 核心）**：在仓位区深色卡片背景上，虚线/实线/端点圆点**清晰可辨**（截屏核对：线条明显加粗、亮色、带衬底光晕，不与深色背景融为一体）；pending 与 active 状态肉眼可区分。
3. **不穿卡片（核心）**：任意连线路径不与任何 `data-bay-id` 卡片矩形相交（可截屏 + 逐条核对：线只在卡片边缘外侧与背景带内）；仓位编号文字/状态圆点不被遮挡。
4. **不交叉连线**：同时存在 ≥3 条连线时，垂直段水平错开（轨道），无两条线相交（截屏核对）；resize 后仍保持。
5. **曲线平滑**：贝塞尔拐角圆弧过渡、无生硬折角；src↔dst 同高时呈弓形曲线。
6. **坐标**：resize 后连线跟随不漂移；起始仓（A/B/C/D 区）与目标仓（2F/3F/4F 区）跨区连线端点贴齐卡片边缘。
7. **交互**：连线区鼠标悬停/点击仍可操作仓位卡片（pointer-events 生效）；无遮挡弹窗。
8. **健壮**：无 data-bay-id 的仓位不报错（cellRect 返回 null 则跳过该线）；业务数据缺失时 update 空数组 = 清空全部线；连线数 > MAX_LANES 时轨道自适应不重叠。
9. **回归**：仓位热力渲染、任务表、AGV 卡、告警列表、标定页不受影响；`node --check dashboard.js`、`node --check pair-lines.js` 通过。
10. **面板折叠（v6）**：默认折叠只显示标题栏 + 数量汇总（候选/进行/异常）；点击标题栏展开三组列表、再点收起；折叠状态在 business_update 刷新后保持；
11. **面板拖动（v6）**：按住标题栏可拖动面板到任意位置（clamp 在仓储卡内），松手停留；拖动不影响仓位卡片点击；
12. **面板透明度（v6）**：展开时仓位卡片透过面板仍可辨识（rgba .5 + blur）；标题栏文字清晰可读。

## 十一、风险与边界

- **gutter 宽度**：两列间 g-2 gap 默认 0.5rem（8px），轨道数 >3 时背景带需向两列卡片外侧扩展（线在卡片外侧空白走，仍不越入卡片）——`MAX_LANES=8` + `LANE_GAP` 自适应（6px→3px 保底）已覆盖；若实际渲染 gutter 过窄，可在实施时给仓位区 card-body 加 `padding-left/right`（8~16px）扩展背景带（纯样式，不动业务）。
- **dest cell 缺 data-bay-id**：本方案补齐；后续 dest 渲染改版需保持该属性（注释标记 P1 pair-line）。
- **坐标容器**：SVG 定位基于 `card-body`（含 padding p-2），`cellRect` 用 `getBoundingClientRect` 差值，padding 不影响（相对坐标系）。
- **性能**：线数量 = 队列候选 + 活跃实例，正常 ≤ 十几条；SVG path 元素轻量；无 requestAnimationFrame 常驻循环（仅事件驱动 + resize 重算）。
- **不依赖**：无第三方库（原生 SVG + CSS animation），与现有 jQuery/Bootstrap 无冲突。
- **布局变化**：若未来仓位区布局改版（如卡片换位/新增分区），lane 模型基于「两列间背景带」假设——需同步调整背景带中心 `m` 计算（封装为 `getBackgroundBand()` 函数，单一修改点）。

## 十二、数据链路根因与修复（v4，板端"全程无连线"）

### 12.1 问题现象
v3（加粗亮色）上传板端触发任务后，全程无任何连接线（含 active 实线流光）。任务日志显示业务链路正常：B1001 绑定 → 匹配 1 候选 → 入队 → 出队 → 下发 RCS → 35s 完成。

### 12.2 根因 1（主因，active 线永不渲染）：business_collector 字段丢失
- `engine.get_active_instances()`（workflow/engine.py L191-205）返回 **`Dict[str, dict]`**：值含 `task_id/current_state/status/rcs_task_no/src_bay/dst_bay/robot_id/cargo_type`；
- `business_collector.get_active_instances()` 原实现 `for item in active` 迭代 dict → item = key（str）→ 走 snapshot 分支 → `get_instance_snapshot()`（engine.py L207-218）返回 `{task_id, current_state, status, duration, rcs_task_no, context}`——**无顶层 src_bay/dst_bay**（在 context 内）；
- → `snap.get('src_bay','')` 恒为 `''` → 前端 `buildPairLines` 的 `if (t.src_bay && t.dst_bay)` 全过滤 → **active 线永不绘制**（任务执行 35s 期间 active_instances 一直推送但字段为空）。

### 12.3 根因 2（次要，pending 虚线几乎不可见）：候选窗口极短
日志：入队 +1 → 出队仅 ~6ms（有 idle AGV 立即分发）+ business_update 防抖延迟 → 前端收到推送时 queue 已空 → 虚线基本不显示（**业务固有特性**：候选即触发；有排队积压时虚线才可见）。

### 12.4 修复（v4）
- business_collector.py `get_active_instances`：改用 `engine.get_active_instances()` 的**字典值**（直接含 src_bay/dst_bay/robot_id/cargo_type）；兼容旧字符串列表分支从 `snapshot.context` 取；
- 返回结构不变（`{'instances': [...], 'count': n}`），前端零改动；
- pending 虚线：不做即时推送增强（候选即触发为业务特性），积压时自然显示。

### 12.5 验证
- `python -m py_compile business_collector.py` 通过；
- 板端回归：触发任务 → F12 console 应见 `[P1] pair lines: 1 B1001→T2003:active`；仓位区显示实线流光；任务完成淡出；有积压时显示虚线。

## 十三、v5 需求：三色线条 + 全曲线连接 + 浮动匹配信息面板

### 13.1 需求
1. 线型三色：pending **浅蓝虚线**、active **灵动科技深蓝实线（动态光亮）**、error **灵动红色实线**；线宽减细；
2. **全曲线连接**：背景空间曲线，无直线段（v4 跨行有 L 直线段）；
3. 仓储区**浮动半透明面板**：实时显示任务匹配信息（候选/进行中/异常），运营人员清晰。

### 13.2 视觉规范（三色）
| 状态 | 线型 | 颜色 | 效果 |
|---|---|---|---|
| pending 候选匹配 | 虚线 | 浅蓝 #93c5fd（1.5px） | 静态虚线 + 淡光晕 |
| active 任务中 | 实线 | 灵动科技深蓝 #2563eb（2px） | 双层亮蓝 glow（#60a5fa/#2563eb）+ dashoffset 流光 |
| error 任务异常 | 实线 | 灵动红 #ef4444（2px） | 红色 glow（#f87171）+ 流光 |

### 13.3 全曲线路由（单段三次贝塞尔）
- `M sx,sy C mx,sy mx,dy dx,dy`，`mx=(sx+dx)/2+laneDx`——起点水平引出、背景带内平滑转折、终点水平引入，**无 L 直线段、无折角**（同高退化为弓形，跨行自然 S 弯）。

### 13.4 异常数据链路（error 红色线）
- 根因：failed 实例 run() 结束即 `_instances.pop`（engine.py L300），**不留在 active_instances**；
- 方案：`workflow.task_failed` 事件（payload 含 src_bay/dst_bay/task_id/robot_id）→ event_bridge `_recent_failures`（deque maxlen=10，含 failed_at）→ business_collector 汇总进 `recent_failures` → 前端 60s 窗口显示红色线，超时移除。
