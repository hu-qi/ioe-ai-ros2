# 60. app_mgr_object-0.2.0 业务监控页今日任务统计计数-开发方案（修订版）

> 状态：**开发方案（修订版，供审核）**
> 工程：`app_mgr_object-0.2.0(标准版)`
> 日期：2026-09-01（修订）｜ 修订说明：**范围收窄为仅修复任务信息卡“今日完成”与“异常”两项统计正常显示**；不新增“总完成数/今日按类型”等统计与前端卡片，不新增 WebSocket 机制（现有 `business_update` 链路已覆盖）

## 1. 目标

任务信息栏（`index.html` `#task-stats`）中的两项统计恢复正确显示：

| 统计项 | 卡片字段 | 正确语义 |
|---|---|---|
| 今日完成 | `today_completed` | 今日（`date(completed_at)=今天`）已完成任务数 |
| 异常 | `failed` | 今日（`date(completed_at)=今天`）失败任务数 |

刷新链路（沿用现有，无需改动）：DB COUNT → `business_collector.get_task_statistics` → `GET /api/task/stats`（初始）与 WebSocket `business_update`（实时）→ 前端 `renderTaskStats`。

> 前端渲染代码（dashboard.js `renderTaskStats`，doc/58/59 已三态化）无需修改；修复后端数据正确性后两项自动正常显示。

---

## 2. 根因（状态值不一致 → 两项统计恒为 0）

- 工作流终态写入 `task_instances.status` 的值为 **`SUCCESS` / `FAILED`**（persistence.py:62-78 `_status_from_state`）；
- 统计查询按 **`completed` / `failed`** 匹配：
  - `engine.count_today_completed → count_by_date('completed', ...)`（engine.py:151-157）→ 查 `status='completed'` 永远为 0；
  - `business_collector` 回退遍历 `if status == 'completed'`（business_collector.py:257-261）同样不匹配 → 恒 0；
- 结论：即使数据源就绪（doc/58 已加 `ready` 语义），今日完成/异常仍恒 0。

---

## 3. 修复方案（仅后端，最小改动）

### P1：persistence.py — 状态值兼容集合 + `count_by_date` 支持集合

- 新增模块级常量（历史 `completed/failed` 与现行 `SUCCESS/FAILED` 并存）：

```python
STATUS_COMPLETED_SET = ('SUCCESS', 'completed')
STATUS_FAILED_SET    = ('FAILED', 'failed')
```

- `count_by_date(statuses, date_field, day)`：参数支持“单值字符串或集合”，内部归一为 tuple 并用 `status IN (?,...)` 查询；保留 `date_field` 白名单校验与 SQL 异常返回 -1 的既有语义（向后兼容旧调用）。

### P2：engine.py — 统计透传兼容集合

```python
from .persistence import WorkflowPersistence, STATUS_COMPLETED_SET, STATUS_FAILED_SET

def count_today_completed(self, day):
    return self._persistence.count_by_date(STATUS_COMPLETED_SET, 'completed_at', day)

def count_today_failed(self, day):
    return self._persistence.count_by_date(STATUS_FAILED_SET, 'completed_at', day)
```

### P3：business_collector.py — 回退遍历分支兼容

```python
if status in ('SUCCESS', 'completed'):
    today_completed += 1
elif status in ('FAILED', 'failed'):
    failed += 1
```

### P4：测试

- 新增真实 SQLite 用例（临时库写入 SUCCESS/completed/FAILED/failed 混合数据）验证：
  1. 今日完成只计今日 `SUCCESS`（兼容历史 `completed`）；
  2. 今日失败只计今日 `FAILED`（兼容历史 `failed`）；
  3. 昨日记录不计入；非法 `date_field` 返回 -1；单值字符串调用仍可用；
- 扩展 business_collector 用例：`count_*` 返回 -1 触发回退遍历时，混合状态行计数正确。

### P5：验收

- 任务信息卡“今日完成 / 异常”显示真实计数（非 0）；
- 任务完成/失败后 WebSocket 推送自动刷新 +1（现有链路验证）；
- 既有回归（doc/58 三态、触发测试）全部通过。

- 兼容集合同时覆盖现行 `SUCCESS/FAILED` 与更早 `completed/failed` 写法，历史数据无需迁移；
