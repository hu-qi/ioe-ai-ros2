# app_mgr_object-0.1.6 标定页 UI 统一与导航入口开发指南

> 文档版本：v1.0
> 编写日期：2026-08-09
> 适用工程：`app_mgr_object-0.1.6(标准版)-1`
> 需求：
>   1) `calibration.html`（视频显示 + 画布多边形/矩形/警戒线绘制）页面修改为与首页一致的卡片/文字 UI 风格；
>   2) 首页导航栏右侧、主题切换按钮之前增加"视频标定"入口按钮。

## 0. 结论摘要

1. `calibration.html` 当前是**独立页面**（不继承 `base.html`，自带 867 行 `style.css` 独立主题），与首页完全两套视觉体系；
2. 标定绘制逻辑 `calibration.js`（1377 行）**零改动**即可复用——只需保证 DOM ID 与动态生成类名的契约不变；
3. 页面改造方式：`calibration.html` 改为继承 `base.html`（自动获得导航栏/主题切换/Toast/WS），内容卡片化（`card` + `card-header` + `btn-accent/btn-outline` + `form-select`），`style.css` 精简为"画布/开关/弹窗/区域列表"专用样式并改用 `custom.css` 设计令牌；
4. 导航入口：`base.html` 导航栏右侧、主题切换按钮之前增加"标定"链接，全站页面统一可见；
5. 后端 `web_server.py` `/calibration` 路由已用 `Jinja2 TemplateResponse` 渲染模板，**无需改动**即可支持 `extends base.html`。

## 1. 现状审查

### 1.1 calibration.html（独立页面）

```html
<!DOCTYPE html><html lang="zh"><head>...
    <link rel="stylesheet" href="/static/calibration/style.css">
</head>
<body>
  <div class="container">
    <nav>...← 返回首页</nav>
    <div class="controls">...通道/绘制模式/按钮/开关...</div>
    <div class="canvas-container" id="canvasContainer">
        <button id="closeFullscreen" ...>✖ 关闭</button>
        <span id="fullscreenHint" ...>按 ESC 或点击 ✖ 关闭</span>
    </div>
    <div class="area-list"><h3>当前区域列表</h3><ul id="areaList"></ul></div>
  </div>
  <script src="/static/calibration/calibration.js"></script>
</body>
```

问题：无导航栏/主题切换；`.container`、`.controls`、`.btn`、`.area-list` 全部由独立 `style.css` 定义，与首页 `custom.css` 令牌不通用；`style.css` 中大量类（`.header-inner/.nav-links/.logout-btn/.param-*/.login-*`）为历史遗留死代码。

### 1.2 calibration.js 依赖契约（改造红线）

**必须保留的 DOM ID（页面静态提供）：**

| ID | 用途 |
|---|---|
| `canvasContainer` | 画布容器（JS 会清空其 innerHTML 并重建）|
| `channelSelect` | 通道下拉 |
| `drawMode` | 绘制模式下拉（polygon/rectangle/line）|
| `panModeBtn` / `clearBtn` / `saveBtn` / `loadBtn` / `refreshBtn` | 工具栏按钮 |
| `status` / `delayDisplay` / `wsStatusDisplay` | 状态/延迟/WS 状态文本 |
| `debugToggleCheckbox` | 视频订阅开关 |
| `closeFullscreen` / `fullscreenHint` | **必须放在 canvasContainer 之外**（见 1.3）|

**JS 动态生成/引用的类名（必须保留样式）：**

`canvas-wrapper`、`channel-canvas`、`toggle-fullscreen-btn`、`toggleBtn{i}`、`fullscreen-single`、`hidden`、`close-fullscreen-btn`、`fullscreen-hint`、`switch`、`slider`、`round`、`modal-overlay`、`modal-dialog`、`area-name`、`selectArea`、`editName`、`deleteArea`。

**实例化时机**：`calibration.js` 在 `DOMContentLoaded` 时 `new CalibrationTool()`——`base.html` 的 `{% block extra_js %}` 位于 body 末尾，时序兼容，无需改动。

**WebSocket 独立**：`ChannelCanvas.connectWebSocket()` 自行连接 `/ws/calibration/{channelId}`，与 `websocket.js` 的全局 `WS`（`/ws`）互不干扰。

### 1.3 关键坑：setupCanvas 清空 canvasContainer

```javascript
setupCanvas() {
    this.canvasContainer.innerHTML = '';   // ← 清空容器
    ...
    this.closeFullscreenBtn = document.getElementById('closeFullscreen');   // 重新查找
    if (this.closeFullscreenBtn) { ... }
    this.fullscreenHint = document.getElementById('fullscreenHint');
}
```

结论：**`closeFullscreen` / `fullscreenHint` 必须放在 `canvasContainer` 之外**（否则被 innerHTML 清掉，JS 拿到 null，全屏关闭按钮失效）。新模板将二者放在画布卡片的 `card-body` 内、`canvasContainer` 的同级位置。

### 1.4 后端路由（无需改动）

`web_server.py`：

```python
@self.app.get("/calibration", response_class=HTMLResponse)
async def calibration_page(request: Request):
    return self.templates.TemplateResponse("calibration.html", {"request": request})
```

Jinja2 渲染天然支持 `{% extends "base.html" %}`。
