## 一、背景与目标

当前诊断/评分规则完全由 YAML 驱动（`config/diagnosis_rules.yaml`、`config/scoring_rules.yaml`），
修改规则需要登服务器编辑文件，再调用 `POST /api/v1/config/reload` 热重载。
教官（非技术用户）无法自助调参，每次调整都依赖实施人员。

本方案目标：**为诊断规则（六类阈值）提供 Web 端查看与编辑能力**，教官可在页面上
查看当前生效规则、修改阈值/开关/建议文本、一键保存并热重载。

明确的非目标（有意不做）：

| 不做 | 理由 |
|---|---|
| 评分规则（四系数模型）编辑器 | 公式耦合（max_score × 用时×正确性×顺序系数 + 整轮扣分/超时乘子），表单化易产生非法组合且误配影响全量评分；变更频率极低，维持 YAML+热重载 |
| 评分规则页面编辑 | 同上；仅提供只读展示（见 §七 可选增强） |
| 设备连接配置页 | 连接配置在端侧一体机设置页（dev01 v3：填 baseURL + 开总闸），平台是被动接收方，无事可配 |

## 三、现状事实（代码位置核对）

| 事实 | 位置 |
|---|---|
| 规则加载与回退链（工序专属→common→内置默认） | `app_mgr_object/components/web/diagnosis_rules_loader.py`（`load_diagnosis_rules`，候选路径：CWD config/ → 包相对 config/） |
| 规则对象（type/threshold/enabled/suggestion/window_recent/window_history/substep_index） | 同上 `DiagnosisRule` dataclass |
| 六类规则类型枚举 | 同上 `RULE_TYPES = {bottleneck, error, sequence, interval, stddev, regression}` |
| 诊断引擎热重载入口 | `diagnosis_engine.py:67 reload_rules()` |
| 评分引擎热重载入口 | `scoring_plugin.py` / `scoring_engine.py:89 reload()` |
| 热重载 API（已有） | `web_server.py:1564 POST /api/v1/config/reload`，重载 scoring+diagnosis，返回各组件结果 |
| 现有 YAML 结构 | diagnosis_rules.yaml 121 行：`processes[name].rules[]` + `common_rules[]`；scoring_rules.yaml 59 行 |
| 新版 SPA | `apps/web-ui/src`（Vue3 + Element Plus），诊断页 `DiagnosisView.vue` 已有"热重载规则"按钮 |
| 现状认证 | web_server.py 无任何 auth 中间件/依赖（仅 .map 文件中间件），dev01 评估表已记"mock 免认证"缺口 |

关键约束：
- YAML 是**唯一事实源**（评估报告有意决策 3：不建数据库规则表）→ Web 编辑本质是"表单化回写 YAML"，不做数据库迁移；
- `regression` 规则额外有 `window_recent`/`window_history` 两个窗口参数，表单需支持；
- `substep_index: null` 表示对工序所有步骤生效，首版表单不开放按步骤配置（保持 null），降低复杂度。

## 四、接口设计（D1）

统一响应包裹沿用现有 `{code, message, data}` 约定（dev01 §2.1）。

### 4.1 读取规则

```
GET /api/v1/config/diagnosis-rules
```

响应 data（与 YAML 结构一一对应，不含内置默认）：

```json
{
  "version": "1.0",
  "processes": [
    {"name": "拆解", "rules": [
      {"type": "bottleneck", "substep_index": null, "threshold": 1.5,
       "enabled": true, "suggestion": "拆解该步骤平均用时过长…"}
    ]}
  ],
  "common_rules": [
    {"type": "regression", "window_recent": 3, "window_history": 5,
     "threshold": 0.85, "enabled": true, "suggestion": "…"}
  ],
  "meta": {
    "rules_path": "/root/ioe-ai/code-workspace/config/diagnosis_rules.yaml",
    "updated_at_ms": 1757660000000,
    "backup_dir": "config/backups"
  }
}
```

实现：直接 `yaml.safe_load` 规则文件返回（不经过 loader 的规则对象转换，保持与文件一致）。

### 4.2 保存规则

```
PUT /api/v1/config/diagnosis-rules
```

请求体 = 与 GET 相同的 `processes + common_rules` 结构（不含 meta）。
处理流程（D2 `diagnosis_rules_store.py`）：

1. **校验**（拒绝整次保存，返回逐条错误）：
   - `type` ∈ RULE_TYPES；每工序每 type 至多一条（对齐 loader 的"同类型后条覆盖前条"语义，表单直接禁止歧义）；
   - `threshold` 数值且在类型约束内：bottleneck/regression/stddev > 0（stddev 建议上限 5），error/sequence ∈ (0,1]，interval ∈ (0, 3600000] ms；
   - regression 的 `window_recent`/`window_history` 为正整数且 recent < history；
   - `suggestion` 非空且 ≤ 200 字；未知字段忽略并告警；
2. **备份**：写前复制当前 YAML 到 `config/backups/diagnosis_rules.yaml.bak_<yyyyMMdd_HHmmss>`，保留最近 20 份；
3. **原子写**：写临时文件后 `os.replace`，避免半写状态；
4. **自动热重载**：保存成功后自动调用 `DiagnosisEngine.reload_rules()`（复用 web_server.py:1588 的既有逻辑），响应中带重载结果，教官无需再点热重载按钮。

响应 data：`{"saved": true, "backup": "<备份文件名>", "reload": {"diagnosis": true}}`。

### 4.3 复用既有接口

`POST /api/v1/config/reload` 保持不变（诊断页已有按钮），作为"手工兜底重载"入口。

## 五、认证门禁（D3）

现状 9183 全部接口无认证（生产内网）。写接口引入配置后，必须加门禁，否则内网任何人可改教学标准。采用**最小实现**：

| 项 | 设计 |
|---|---|
| 方式 | 固定 Token：请求头 `X-Config-Token`，与 `config/web_monitor.yaml` 新增 `config_edit_token` 比对 |
| 覆盖范围 | 仅写接口：`PUT /api/v1/config/diagnosis-rules`（GET 只读放开，`POST /config/reload` 本期不动，避免影响端侧/看板联调） |
| 开关 | `config_edit_enabled: true/false`（默认 true）；false 时 PUT 返回 403 "规则编辑未启用" |
| 失败处理 | 401 + 连续 5 次失败记 warning 日志（含来源 IP），不做锁定（内网场景） |
| 前端 | 规则页首次保存时弹窗输入 Token，存 sessionStorage |
| 不做 | 用户体系/角色权限/CSRF——单教官场景过度设计，记入"后续演进" |

与 dev01 评估表缺口 #5（认证）的关系：本方案只给规则写接口上认证，是那个大缺口的**第一步**而非全部；其余接口放行策略维持现状，待现场确认认证策略后统一处理。

## 六、前端页面（D4）

新增新版 SPA 页面 `RuleConfigView.vue`（路由 `/ui/rules`，菜单名「规则配置」，放在「诊断中心」之后；旧版模板不做新页，按 P7 灰度约定旧路由 302 到新页）。

页面结构（单页两区）：

1. **顶部工具条**：`重新加载`（调 GET 刷新）、`保存`（PUT，成功 Toast 显示备份文件名与重载结果）、`热重载`（复用现有按钮逻辑，兜底）；
2. **工序规则表格**（每个工序一张卡，Tab 切换 拆解/组装/通用规则）：
   - 列：规则类型（中文标签+说明 tooltip）、阈值（数字输入，按类型显示单位：×SOP 倍数 / 比例 % / ms）、启用开关、建议文本（多行输入）、regression 额外显示两个窗口输入框；
   - 每行"恢复默认"链接（取 loader 的 `_builtin_common_rules()` 值，经 GET 一起下发）；
3. **校验提示**：行内红字即时校验（复用 §4.2 阈值约束），保存失败时后端逐条错误定位到行；
4. **底部说明卡**：只读展示"规则回退链（工序专属→通用→内置）"与各类型判据公式（从 diagnosis_engine.py 头注释提炼），帮助教官理解命中逻辑。

交互细节：保存采用全量 PUT（页面持有的就是整份规则），不做行级增量，与 YAML 整文件语义一致、无并发合并问题；若 `updated_at_ms` 与页面加载时不一致（他人已保存），保存前二次确认覆盖。

## 七、测试方案（D5）

### 7.1 pytest 接口测试（`test/test_rule_config_api.py`）

| 用例 | 断言 |
|---|---|
| GET 返回现有 YAML 结构 | processes 含"拆解/组装"，common_rules 含 regression 窗口参数 |
| PUT 合法全量规则 | 200；saved=true；reload.diagnosis=true；GET 回读与写入一致 |
| PUT 非法 type / 超范围 threshold / recent≥history | 422；错误信息定位到工序+类型 |
| PUT 后备份文件生成 | backups/ 出现 .bak_ 文件，内容为写前旧 YAML |
| YAML 损坏后 GET | 降级返回内置默认并标记 degraded（与 loader 回退链一致） |
| 认证：无头/错头 PUT | 401；正确 token 放行；config_edit_enabled=false 时 403 |
| 原子性：写入中途模拟异常 | 原 YAML 未被破坏（os.replace 语义） |

### 7.2 手工验证清单（生产 9183）

1. 页面打开 → 显示当前生效规则（与 YAML 对照）；

## 九、风险与对策

| 风险 | 对策 |
|---|---|
| 表单误改导致诊断失真 | 阈值类型约束 + 逐条校验 + 每次保存自动备份（保留 20 份）+ 保存响应明示备份名 |
| 并发编辑互相覆盖 | updated_at_ms 乐观检查，冲突时二次确认 |
| 9183 引入写接口扩大攻击面 | 仅 1 个写接口 + Token 门禁 + 可配置总开关；GET 只读不动 |
| 与"YAML 是唯一事实源"决策冲突 | 不引入数据库：编辑即回写 YAML，手工改文件与页面编辑并存，热重载统一生效 |
| ui_dist 构建引入 Node 依赖 | 构建仍只在开发机执行，产物随包部署（沿用 P7 方案 A 约定） |

## 十、验收标准

1. 教官在浏览器完成一次"查看→改阈值→保存→执行诊断验证"闭环，全程无需 SSH；
2. 所有 §7.1 用例通过，全量测试回归无新增失败（当前基线 142 项）；
3. 规则文件任何时刻损坏，可通过备份目录一键恢复；
4. 写接口在无 Token 时被拒绝（401），开关关闭时返回 403；
5. 评分规则、设备连接配置按 §一 非目标明确不做，避免范围蔓延。
