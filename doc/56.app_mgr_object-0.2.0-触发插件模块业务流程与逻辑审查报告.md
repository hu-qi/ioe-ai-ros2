## 1. 业务目标

触发机制要达成的业务闭环（无人值守自动调度）：

1. **自动检测**：AI 视觉（RTSP 推理）周期发布仓位状态，识别“有货/无货 + 货物类型 1~6”；
2. **自动绑定**：仓位稳定有货后自动调 RCS `bindCtnrAndBin` 绑定，绑定仓才可被调度；
3. **智能匹对**：按货物类型优先级 + 区域顺序（A→D）选始发仓，按巷道规则（类型/始发映射 + 最大占用+1）选目的仓，形成任务候选；
4. **节奏控流**：全局任务数（队列 + 运行中）≤ `max_total_tasks`（默认 4）、每轮派发 ≤ `dispatch_per_round`、候选老化 TTL 清理；
5. **AGV 调度**：从可用 AGV 中按策略（轮询/最少空闲/指定）选择，派发到 RCS `genAgvSchedulingTask`；
6. **执行闭环**：RCS 回调/超时补偿驱动工作流（下发→监控→释放→完成/失败/人工介入），任务完成/失败自动释放资源并触发下一任务；
7. **可观测与可运维**：Web 实时状态（四色仓位/任务队列/AGV）、告警分级、人工介入（retry/cancel/force_trigger）、断电恢复。

## 3. 业务流程（端到端）

### 3.1 主流程时序

```text
1) AI 检测（0.3s/帧）
   └─ bay_status_fusion：AreaStatusFilter 防抖（stable_threshold/filter_timeout）
        ├─ 稳定有货 → RCS bindCtnrAndBin（bay_status_fusion_plugin.py:278-315）
        │     成功 → BayCache.set_bound + 发布 bay.bound
        └─ 稳定无货 → 解绑 + 发布 bay.unbound（bay_status_fusion_plugin.py:395）

2) smart_trigger（订阅 bay.bound，smart_trigger_plugin.py:164）
   ├─ _scan_loop（2s 周期，smart_trigger_plugin.py:239）
   └─ _scan_and_dispatch_once（事件驱动，bay.bound 触发）
        ├─ schedule_checker.is_in_working_window（工作时间/节假日/开发模式）
        ├─ _task_capacity：max_total_tasks - 队列 - 运行中（smart_trigger_plugin.py:222）
        ├─ TriggerEngine.batch_scan_all → TaskBatchMatcher.greedy_scan_type：
        │     src = 已绑定且 in_task=False，按 cargo_priority + 区域/扫描顺序排序；
        │     dst = 空 + 排除集合（batch_matcher.py:148-165），按巷道规则 select_by_strategy；
        │     匹对即 mark_occupied(dst,'matched')（dest_bay_cache.py:252）
        ├─ TaskQueue.enqueue_all（入队即占用 'queued'，task_queue.py:57）
        └─ _dispatch_from_queue（smart_trigger_plugin.py:292）
              └─ try_dequeue（task_queue.py:105）→ StateCoordinator.dispatch_task
                    （锁定 AGV/始发/目的仓，'dispatched'）→ 发布 trigger.task_created（smart_trigger_plugin.py:326）

3) workflow_engine（订阅 trigger.task_created，workflow_engine_plugin.py:146）
   └─ _on_trigger_task_created → create_instance('agv_transport_atomic', ctx)
        ├─ 状态机：calling_rcs → monitoring → releasing → completed/failed
        ├─ calling_rcs：RCS gen_task（rcs_adapter_plugin.py:125）
        ├─ monitoring：等待 RCS agvCallback（9=完成/7=失败/8=取消）或超时补偿查询
        ├─ releasing：release_resources → coordinator.release_task（幂等）
        └─ 终态发布 workflow.task_completed / task_failed（去重：_terminal_event_published）

4) smart_trigger 事件联动（smart_trigger_plugin.py:473）
   ├─ task_completed / task_failed / resources_released → _release_via_coordinator
   └─ 立即 _dispatch_from_queue（释放容量后派发下一任务）

5) 观测：event_bridge.subscribe_all（event_bridge.py:49）→ 防抖采集 → WebSocket business_update
```

### 3.2 目的仓状态机（四色）

```text
empty（绿）─匹对─▶ matched（橙）─入队─▶ queued（橙）─派发─▶ dispatched（橙）
   ▲                    │                 │                 │
   │                    │                 │                 ├─ 完成：RCS 接管真实占用 → occupied（灰黑）
   │                    │                 │                 └─ 失败/取消：回 empty（绿）
   │                    │                 ▼
   │                    │         老化/remove_by_dst → empty（绿）
   │                    ▼
   │            解绑移出（remove_by_src，task_queue.py:222）
   │                    ▼
   │            unbind（蓝，is_empty=True，可再匹配，rematchable=True）
   └──再次匹对──mark_occupied 清除 unbind──▶ matched（橙）
```

### 3.3 任务工作流状态机（agv_transport_atomic.yaml）

```text
calling_rcs ──rcs_ack_ok──▶ monitoring ──callback_completed──▶ releasing ──done──▶ completed
     │                         │  │                              ▲
     │                         │  ├─ callback_exception ──▶ manual_intervention
     │                         │  ├─ warn_l1 ──▶ warn_pause（60s 自动恢复 monitoring）
     │                         │  └─ timeout ──▶ compensating_query ──rcs_completed─▶ releasing
     │                         │                    │ rcs_failed/max_retry_reached/timeout
     │                         │                    └─▶ manual_intervention（挂起态，可 user_retry/user_cancel/auto_resolved）
     └─rcs_ack_fail/timeout──▶ failed（on_exit：release_resources + publish_failed_event）
```

### 3.4 队列生命周期

```text
入队（enqueue_all，去重+容量约束）→ 排队（老化 TTL 计时）→ 出队（try_dequeue：AGV 感知+防御清理）
移除三路径：
  - 老化超时：_age_out_locked（task_queue.py:164）→ 清双集合 + 释放目的仓
  - 按目的仓移除：remove_by_dst → 清 queued_dst + 释放目的仓
  - 按始发仓移除：remove_by_src（task_queue.py:222）→ 清双集合 + 释放目的仓（蓝标）+ 幂等释放始发仓锁
防御：_purge_unbound_locked（task_queue.py:191）→ 事件丢失时出队前清理未绑定候选
```

## 5. 逻辑正常性审查

### 5.1 主线闭环（审查通过）

- **检测→绑定→匹配→派发→执行→释放→再派发** 全链路事件驱动完整：`bay.bound → trigger.task_created → workflow.* → resources_released → dispatch`；
- **匹对稳定**：匹对/入队/派发三阶段逐步 `mark_occupied`，排除集合同步维护，多源不抢同一空仓；
- **控流**：容量在扫描锁内计算并二次截断，入队层强制上限，杜绝超发；
- **释放一致性**：任务完成保留占用由 RCS 接管（`set_empty=False`），失败/取消/老化/解绑回空；
- **恢复机制**：启动 `_validate_and_recover` 对未完成实例做 RCS 状态校准（9→完结、7/8→失败、2→恢复监控），断电不悬挂（workflow_engine_plugin.py:159）；
- **配置化**：doc/52-53 已实现启动注入 + 事件驱动热加载 + 策略选择器（AGV/扫描顺序/状态映射/派发轮次/绑定重试）。

### 5.4 并发与线程模型

| 执行体 | 归属 | 职责 |
|---|---|---|
| rclpy MultiThreadedExecutor | main.py | ROS2 回调（订阅/定时器/服务） |
| node.asyncio_loop（独立线程） | main.py | 扫描协程、工作流实例协程、事件注入 |
| ROS2 定时器 | status_poller / bay_status_fusion | 轮询、绑定重试 |
| FastAPI/uvicorn + WS | web_monitor | 配置接口、实时推送 |
