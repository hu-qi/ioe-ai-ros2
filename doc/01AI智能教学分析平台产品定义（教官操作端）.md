## 二、产品定位与核心价值

**产品定义**：  
通过接收边缘端上传的学员操作报告（整包、实时事件、超时抓拍证据），自动进行多维度统计分析与五维教学诊断，识别全班性瓶颈与学员个体问题，为教官提供明确的数据管理平台与行动建议，实现“以数据驱动教学方法持续优化”。

**核心价值**：
- 从数据到行动：每个指标配有“教官该做什么”的建议。
- 教学闭环：诊断→改进→验证，形成优化循环。
- 轻量部署：SQLite 单文件、零配置、低内存，教官开箱即用。
- 个体追踪：每位学员成长轨迹清晰可见。
- 全员诊断：自动识别全班瓶颈，精准调整教案。
- 证据支撑：超时抓拍图关联诊断，课堂复盘有据可依。

## 三、最新端侧上报接口定义（平台必须实现 4 个 API）

端侧配置 `baseURL`（如 `http://192.168.31.191:8183`），自动拼接以下接口。平台严格实现：

| # | 接口 | 方法 | 功能 | 触发时机 | 幂等键 |
|---|---|---|---|---|---|
| 1 | `{base}/api/v1/reports` | POST | 接收轮次结束整包报告 | 训练轮次结束 | `device_id + round.start_ms` |
| 2 | `{base}/api/v1/events` | POST | 接收实时增量事件（每2秒攒批） | 训练进行中，有步骤/子步骤变化 | `device_id + round_start_ms + events[].ts` |
| 3 | `{base}/api/v1/evidence` | POST (multipart) | 接收超时抓拍证据图（BMP） | 实时通道 + 整包兜底 | `device_id + round_start_ms + sub + ts` |
| 4 | `{base}/api/v1/students` | GET | 提供学员台账，供端侧同步 | 端侧“从平台同步”按钮 | — |

**说明**：
- 订阅接口 `/subscriptions` 已彻底取消，平台无需实现。
- 实时上报为 `auto` 模式：端侧地址就绪 + 总闸开启即自动上报，无需平台订阅。
- 证据图两通道字段已统一，平台按幂等键自动去重。
- 学员台账返回格式：`{code:0, data:{total, students:[{tid, name, cls}]}}`。
- 报告解析兼容端侧 schema 1.0/1.1，核心提取 `round` 下的 `steps`、`substeps`、`events`、`evidence`。

## 五、数据模型（核心表）

- `students`：学员档案（支持 manual/platform/import/scan 来源）。
- `reports`：整包报告主表（设备、学员、轮次、完成率、得分、等级、原始 JSON）。
- `report_substeps`：子步骤明细（状态、耗时、标准用时、超时、得分）。
- `realtime_events`：实时增量事件（幂等去重）。
- `evidence`：证据图元数据（BMP/JPG 路径、幂等键）。
- `diagnosis_rules`：诊断规则配置（阈值、权重）。
- `scoring_rules`：评分标准配置（标准用时、满分、权重、扣分系数）。
- `dashboard_cache`：看板预聚合缓存。
- `teaching_actions`：教学调整事件（闭环验证）。

## 六、核心功能亮点实现逻辑

### 6.1 报告接收与解析
- **整包报告**：`POST /reports` 校验后写入 `reports` 和 `report_substeps`，`raw_data` 保留完整 JSON；触发评分与统计刷新。
- **实时事件**：`POST /events` 按幂等键写入 `realtime_events`，更新实时进度缓存；用于看板实时展示与整包校验。
- **证据图**：`POST /evidence` 落盘 BMP，写入 `evidence` 表，异步转 JPG；按幂等键去重。
- **学员台账**：`GET /students` 返回 JSON，供端侧同步。

### 6.2 五维教学诊断

| 维度 | 计算逻辑 | 行动建议 |
|---|---|---|
| 步骤平均用时 | AVG(duration_ms) 与 SOP 对比 | > SOP×1.5 → 重点讲解 |
| 步骤操作错误 | state=0/3 比例 | 遗漏率>30% → 专项训练 + 关键帧 |
| 顺序/遗漏/重复 | events 顺序比对，count>1 | 顺序错误率>20% → 强调依赖关系 |
| 步骤间隔平均用时 | 相邻子步骤间隔均值 | 间隔>阈值 → 明确逻辑 |
| 步骤用时标准差 | STDDEV 与均值比较 | 标准差>均值×0.5 → 分享经验 |

诊断结果关联证据图，前端课堂复盘可直接展示。

### 6.3 学员个体追踪
- 聚合考试次数、平均分、最高/最低分、趋势、薄弱步骤 TOP3。
- 退步预警：最近 3 次平均分 < 前 5 次×0.85。
- 前端展示成长曲线、历史报告。

### 6.4 教学改进闭环
- 教官标记“教学调整”事件。
- 平台自动对比调整前后班级平均分、完成率、诊断指标变化。
- 生成改进效果报告（如“步骤3平均用时从12.3s降至9.8s，降幅20%”）。

### 6.5 教官驾驶舱看板
- APScheduler 每日预计算：今日概览、高频错误 TOP5、需关注学员、近7天趋势。
- 写入 `dashboard_cache`，前端毫秒级读取。
- 实时数据（如今日考试人数）可实时查询。

### 6.6 轻量化部署
- SQLite 单文件，WAL 模式，每日自动备份。
- FastAPI 单进程 + 静态文件托管，无需 Nginx/Redis/Celery。
- 内存 < 200MB，适合办公台式机。

## 七、超时抓拍图像处理方案（新增详细设计）

### 7.1 接收与幂等
- 两通道（实时/整包兜底）均携带 `file + sub + ts + device_id + round_start_ms`。
- 平台按 `device_id + round_start_ms + sub + ts` 建立唯一约束，自动去重。

### 7.2 存储与转换
- 原始 BMP 落盘：`data/evidence/{device_id}/sub05_t12000.bmp`。
- 异步任务转 JPG：减小体积，便于 Web 展示，存 `jpg_path`。
- 列表页展示缩略图，详情页展示原图。

### 7.3 与诊断关联
- 诊断规则触发“操作错误”或“顺序混乱”时，自动关联该子步骤抓拍图。
- 前端诊断结果中直接展示关键帧，支持课堂复盘。

### 7.4 清理策略
- 默认保留 90 天，定时清理；重要轮次可标记永久保留。

## 八、单轮评分标准方案（新增详细设计）

### 8.1 评分模型
单轮总分 = Σ（子步骤得分 × 权重） + 整轮加分/扣分

**子步骤得分** = 基础分 × 用时系数 × 正确性系数 × 顺序系数

| 系数 | 计算方式 | 说明 |
|---|---|---|
| 基础分 | `max_score`（默认10分/子步骤） | 可配置 |
| 用时系数 | `min(1.0, std_duration_ms / actual_duration_ms)` | 用时≤标准得满分，超时按比例扣 |
| 正确性系数 | 完成=1.0；中断=0.5；未执行=0 | 状态决定 |
| 顺序系数 | 顺序正确=1.0；顺序错误=0.7 | 从 events 比对 |
| 超时扣分 | 超时则额外 × `timeout_penalty`（默认0.5） | 可配置 |

**整轮扣分**：
- 遗漏子步骤：每个扣 2 分。
- 重复操作：每次扣 1 分。
- 轮次超时：总分 × 0.9。

### 8.2 等级划分
| 总分 | 等级 |
|---|---|
| ≥90 | 优秀 |
| 75-89 | 良好 |
| 60-74 | 合格 |
| <60 | 不合格 |

### 8.3 配置化
- 评分规则存 `scoring_rules` 表，教官可在界面调整标准用时、权重、扣分系数。
- 支持按工种/模板导入不同评分标准。

## 九、操作记录与评分实现（实时+整包合并）

### 9.1 数据合并策略
- 实时事件用于看板进度与整包校验；整包报告为准，含完整 `events` 与 `substeps`。
- 按 `device_id + round_start_ms + event_ts` 幂等合并，去重排序。

### 9.2 操作记录生成
- 生成完整时间线：每步开始/完成/超时/中断 + 关联抓拍图。
- 时间线存入报告详情，供教官复盘。

### 9.3 评分触发
- 整包到达后立即触发评分引擎，计算单轮总分、子步骤得分、等级。
- 结果写入 `reports` 与 `report_substeps`，随后刷新学员累计、班级诊断、看板缓存。

### 9.4 前端展示
- 报告详情页：时间线 + 子步骤得分 + 抓拍图 + 总分等级。
- 学员详情页：得分趋势 + 薄弱步骤 + 历史报告。
- 看板：今日平均分、通过率、高频错误 TOP5。

## 十一、关键风险与应对

| 风险 | 应对 |
|---|---|
| 报告缺少 student_id | 提供“未关联报告”列表，支持手动关联或批量补录 |
| SQLite 并发写入 | WAL 模式；单机写入频率低，未来可迁 PostgreSQL |
| 评分标准不合理 | 配置化，默认值 + 界面可调，支持按工种导入 |
| 证据图 BMP 体积大 | 异步转 JPG，缩略图 + 原图分级展示 |
| 前端触屏兼容性 | Element Plus 响应式布局，控件 ≥44px |
| 实时事件与整包冲突 | 以整包为准，实时用于进度与校验；幂等键去重 |

## 十二、总结

本方案是对合同定义产品《面向机修培训的AI智能教学分析平台-教官操作端》的完整产品定义与规划。它严格对齐端侧最新 4 接口（reports / events / evidence / students），去除 ROS2 与订阅机制，并补充了用户确认的三大关键能力：

产品完整覆盖“数据→洞察→行动”链路，形成“感知→记录→分析→诊断→改进→验证”的教学优化闭环，轻量化部署，教官开箱即用。本方案可作为后续开发、验收与合同交付的基准文档。
