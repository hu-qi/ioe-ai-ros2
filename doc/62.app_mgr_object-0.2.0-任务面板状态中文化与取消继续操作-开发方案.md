# 62. app_mgr_object-0.2.0 任务面板状态中文化与取消/继续操作-开发方案

> 状态：**开发方案（供审核，本次未修改任何代码）**

> 日期：2026-09-01

---

## 1. 需求

业务监控页任务面板列表栏调整：

1. **状态列中文显示**：活跃任务（当前状态 current_state）与历史任务（DB 状态 status）均显示中文；
2. **操作栏调整**：任务产生（进入活跃实例）后，行内提供 **取消（cancelTask）** 与 **继续（continueTask）** 两个操作，调用 RCS 对外接口（经 `rcs_client` 组件与既有 `/api/task/control` 链路）。

---

## 2. 现状梳理

### 2.1 RCS 接口与 rcs_client 封装（取消/继续已具备）

| 接口 | RCS 文档 | rcs_client 封装 | 说明 |
|---|---|---|---|
| 取消任务 | 2.1.3 cancelTask | `RCSHttpClient.cancel_task(task_code, force_cancel="1")` → POST `/cancelTask`，body `{taskCode, forceCancel}`（rcs_http_client.py:101-112） | forceCancel="1" 软取消（叉车背货回库），"0" 硬取消 |
| 继续任务 | 2.1.2 continueTask | `RCSHttpClient.continue_task(task_code)` → POST `/continueTask`，body `{taskCode}`（rcs_http_client.py:93-99） | 继续执行暂停/中断的任务 |

上层调用（已存在，无需新增后端接口）：
- `RCSAdapterPlugin.continue_task/cancel_task`（rcs_adapter_plugin.py:149-171）；
- `TaskController.task_control`：`cancel` → 工作流注入 `user_cancel`（task_controller.py:49，终态 failed 自动释放资源）；`continue` → 取实例 `rcs_task_no` 后调 `rcs.continue_task`（task_controller.py:103-111）；
- Web 路由：`POST /api/task/control`（web_server.py:1324 起）。

## 3. 技术方案

### 3.1 状态中文映射（前端新增映射表）

新增两组映射（dashboard.js 顶部，与 `STATUS_BADGE_MAP` 并列）：

```js
// 活跃实例 current_state → 中文
var STATE_CN = {
    'calling_rcs':         '下发中',
    'monitoring':          '执行中',
    'compensating_query':  '补偿查询',
    'warn_pause':          '警告暂停',
    'releasing':           '释放中',
    'releasing_and_done':  '释放中',
    'manual_intervention': '人工介入',
    'auto_recovery':       '自动恢复',
    'completed':           '已完成',
    'failed':              '失败',
    'cancelled':           '已取消',
};

// 历史/DB status → 中文
var STATUS_CN = {
    'SUCCESS':     '已完成',
    'FAILED':      '失败',
    'RUNNING':     '执行中',
    'DISPATCHING': '下发中',
    'MANUAL':      '人工介入',
    'PENDING':     '待处理',
    'CANCELLED':   '已取消',
};
```

应用点：
- 活跃 Tab 状态列（dashboard.js:342）：`STATE_CN[t.current_state] || STATE_CN[t.status] || t.status || '--'`；
- 历史 Tab 状态列（dashboard.js:417）：`STATUS_CN[t.status] || t.status || '--'`；
- 徽章样式扩展：`STATUS_BADGE_MAP` 补充 `compensating_query/releasing/manual_intervention/warn_pause/auto_recovery/cancelled`（沿用既有 running/warn/manual 等色系，或新增 class）。

### 3.2 操作栏：行内“取消 / 继续”（活跃实例）

`renderActiveTasks` 行内操作列（dashboard.js:349-353）由“仅查询”改为“查询 + 继续 + 取消”：

```js
var tid = (t.task_id || '');
var op = '<button class="btn btn-outline btn-sm" style="font-size:10px;padding:1px 6px;" ' +
         'onclick="queryTask(\'' + tid + '\')" title="查询"><i class="fas fa-search"></i></button>';
if (t.rcs_task_no) {   // 任务已下发 RCS（产生 rcs_task_no）才可“继续”
    op += '<button class="btn btn-outline btn-sm" style="font-size:10px;padding:1px 6px;color:var(--accent-green);" ' +
          'onclick="continueTaskInline(\'' + tid + '\')" title="继续执行（RCS continueTask）"><i class="fas fa-play"></i></button>';
}
op += '<button class="btn btn-outline btn-sm" style="font-size:10px;padding:1px 6px;color:var(--accent-red);" ' +
      'onclick="cancelTaskInline(\'' + tid + '\')" title="取消任务（释放资源）"><i class="fas fa-times"></i></button>';
```

新增行内全局函数（复用既有确认弹窗与 `API.taskControl`，不依赖输入框）：

```js
window.cancelTaskInline = function(tid) {
    confirmTaskControl('cancel', { task_id: tid },
        '确定取消任务 ' + tid + ' 吗？\n取消后将释放该任务占用的资源。');
};
window.continueTaskInline = function(tid) {
    confirmTaskControl('continue', { task_id: tid },
        '确定继续执行任务 ' + tid + ' 吗？\n将调用 RCS continueTask 继续该任务。');
};
```

后端链路（无需改动，均已实现）：
- 取消：`/api/task/control {operation:'cancel', task_id}` → `engine.inject_event('user_cancel')` → 工作流终态 failed（on_exit 释放资源）；
- 继续：`/api/task/control {operation:'continue', task_id}` → `task_controller` 取 `rcs_task_no` → `rcs.continue_task`。

### 3.3 按钮可用性边界

| 场景 | 取消 | 继续 |
|---|---|---|
| 活跃实例（calling_rcs/monitoring/warn_pause/manual_intervention…） | 显示（终态前可取消） | 仅 `rcs_task_no` 非空时显示（RCS 已受理） |
| 队列（待触发，未产生任务） | 不显示（操作列保持 `--`） | 不显示 |
| 历史/终态 | 不显示 | 不显示 |

> 说明：`get_active_instances` 已返回 `rcs_task_no`（engine.get_active_instances），前端可直接判断；“继续”对 RCS 已暂停/中断任务生效，对未知状态任务点击后由后端返回错误提示（task_controller 现有逻辑）。

## 4. 实施步骤

1. **前端映射**：dashboard.js 新增 `STATE_CN / STATUS_CN`，扩展 `STATUS_BADGE_MAP`（含 custom.css 补色可选）；
2. **状态列中文化**：`renderActiveTasks`（L342）与 `renderHistoryTasks`（L417）改用映射；
3. **操作栏**：`renderActiveTasks` 行内操作列增加“继续（有 rcs_task_no）/取消”，新增 `cancelTaskInline / continueTaskInline`；
4. **验证**：`node --check`；浏览器模拟活跃/历史/队列三 Tab 状态与按钮显示；点击确认弹窗 → `/api/task/control` 请求正确；WS `business_update` 刷新后状态中文更新；
5. **板端验收**：真实任务取消后资源释放、RCS 暂停任务点击“继续”调用 continueTask 成功/失败提示。

---

## 5. 测试与验收

- 前端：`node --check` 通过；活跃行状态中文（下发中/执行中/警告暂停/人工介入…）；历史行 SUCCESS→已完成、FAILED→失败；队列行“待触发”不变；
- 操作：无 `rcs_task_no` 不显示“继续”；有则显示；取消/继续均有确认弹窗；调用 `API.taskControl` 成功 toast 并 `loadAllData()` 刷新；失败提示后端 error；
- 回归：任务查询按钮、任务操作卡（取消/重试/查询）、强制触发等既有功能不破坏；
- 板端：取消后工作流 failed 释放资源（AGV/仓位回空）；继续后 RCS 任务恢复执行，状态经 WS 回到“执行中”。

---

## 6. 兼容性与回滚

- 仅前端改动（dashboard.js + 可选 custom.css），无接口/数据库变更，后端零改动；
- 状态映射缺省回退原值（`|| t.status || '--'`），未知状态不空白；
- 操作按钮为行内新增，可整体回滚（还原 renderActiveTasks 与映射表即可）。

---

## 7. 结论

1. RCS 取消/继续接口与后端控制链路已具备（`/cancelTask`、`/continueTask` + `/api/task/control`），本次为**纯前端改造**；
2. 状态列通过 `STATE_CN/STATUS_CN` 映射中文化，操作列按“任务产生且有 rcs_task_no”条件展示“继续 + 取消”，复用既有确认弹窗与刷新链路；
3. 建议按 §4 步骤实施，配合浏览器与板端验收。
