### 1.2 warnCallback 现有处理（分析）

当前 `callback_handler_plugin._on_warn_callback()` 的处理:

```python
# v0.0.7-7 现有代码流程
warnCallback 到达
  → 解析 warnCode, warnMsg, agvCode, taskCode, warnLevel
  → 发布 EventBus: rcs.warn_callback
  → WorkflowEventBridge._on_rcs_warn_callback()
      → engine.inject_event(task_code, 'callback_exception', data)
      → 工作流实例: monitoring → manual_intervention
```

**问题**: 不分告警等级，所有 warnCallback 一律注入 `callback_exception` 转入 `manual_intervention`。对于 L0(信息) 级别的告警（如"电池电量低"），转入人工介入过于激进。

### 1.3 当前工作流 YAML 的 manual_intervention 状态

```yaml
- id: manual_intervention
  final: true
  on_enter:
    - action: publish_manual_event
  transitions:
    - event: "user_retry"      → calling_rcs
    - event: "user_cancel"     → failed
```

**问题**: 
- 没有超时自动闭环机制 — 如果运维人员不操作，实例永远挂起
- 没有自动恢复检测 — RCS 侧任务可能已经恢复/完成，但客户端不知道

### 1.4 现有轮询覆盖范围

`engine.get_active_monitoring_instances()` 只返回 `monitoring` 状态的实例。`manual_intervention` 状态的实例不在轮询范围内，这意味着即使 RCS 侧任务已完成，客户端也无法自动完结。

## 3. 需求 1: 告警分级处置体系

### 3.1 告警严重程度分类

基于 RCS-2000 V3.3 `warnCallback` 接口的 `warnLevel` 字段和 `warnCode` 语义：

| 等级 | 代码 | 典型场景 | 处置策略 | 工作流动作 |
|:---|:---|:---|:---|:---|
| **L0 信息** | 0 | 电池电量低于 30%、即将到达目标 | 仅记录日志，不中断 | 记录 → 继续等待 |
| **L1 警告** | 1 | 路径阻塞(可绕行)、信号弱 | 注入 `warn_l1` 事件，暂停 60s 后自动恢复 | 记录 → 等待 → 自动恢复 |
| **L2 严重** | 2 | AGV 碰撞、机械故障、脱轨 | 注入 `callback_exception` → manual_intervention | 记录 → 人工介入 + 持续轮询 |
| **L3 紧急** | 3+ | 火灾、人员危险（RCS 扩展） | 注入 `callback_exception` → manual_intervention，同时发布全局告警 | 记录 → 人工介入 → Web 弹出 |

### 3.2 实现：告警分类器

文件路径: `app_mgr_object/components/workflow/alarm_classifier.py` **(新建)**

```python
#!/usr/bin/env python3
"""
告警分类器 — 根据 RCS warnCallback 数据判定告警等级和处置策略
"""

from enum import IntEnum
from dataclasses import dataclass
from typing import Dict, Any, Optional


class AlarmLevel(IntEnum):
    INFO     = 0   # 信息 — 仅记录
    WARNING  = 1   # 警告 — 暂定自动恢复
    SEVERE   = 2   # 严重 — 人工介入
    CRITICAL = 3   # 紧急 — 全局告警


@dataclass
class AlarmDisposition:
    """告警处置决策"""
    level: AlarmLevel
    engine_event: str          # 注入工作流的事件名
    should_pause: bool         # 是否暂停任务执行
    auto_recover_after: float  # 自动恢复等待秒数 (0=不自动恢复)
    description: str           # 可读描述


class AlarmClassifier:
    """告警分类器 — 根据 warnCode/warnLevel 判定处置策略"""

    # 预设分类规则
    RULES = {
        # warnCode (字符串/关键字匹配) → (AlarmLevel, engine_event, pause, recover_secs)
        'BATTERY_LOW':   AlarmDisposition(AlarmLevel.INFO,    'warn_info',    False, 0),
        'APPROACHING':   AlarmDisposition(AlarmLevel.INFO,    'warn_info',    False, 0),
        'PATH_BLOCKED':  AlarmDisposition(AlarmLevel.WARNING, 'warn_l1',      True,  60),
        'SIGNAL_WEAK':   AlarmDisposition(AlarmLevel.WARNING, 'warn_l1',      True,  30),
        'OBSTACLE':      AlarmDisposition(AlarmLevel.WARNING, 'warn_l1',      True,  60),
        'COLLISION':     AlarmDisposition(AlarmLevel.SEVERE,  'callback_exception', True, 0),
        'MECH_FAILURE':  AlarmDisposition(AlarmLevel.SEVERE,  'callback_exception', True, 0),
        'DERAIL':        AlarmDisposition(AlarmLevel.SEVERE,  'callback_exception', True, 0),
        'EMERGENCY':     AlarmDisposition(AlarmLevel.CRITICAL,'callback_exception', True, 0),
        'FIRE':          AlarmDisposition(AlarmLevel.CRITICAL,'callback_exception', True, 0),
    }

    # 默认处置（按 warnLevel 数值兜底）
    LEVEL_DEFAULTS = {
        0: AlarmDisposition(AlarmLevel.INFO,    'warn_info',    False, 0),
        1: AlarmDisposition(AlarmLevel.WARNING, 'warn_l1',      True,  60),
        2: AlarmDisposition(AlarmLevel.SEVERE,  'callback_exception', True, 0),
        3: AlarmDisposition(AlarmLevel.CRITICAL,'callback_exception', True, 0),
    }

    @classmethod
    def classify(cls, warn_data: Dict[str, Any]) -> AlarmDisposition:
        """根据告警数据判定处置策略

        优先按 warnCode 匹配预设规则，未匹配则按 warnLevel 兜底。

        Args:
            warn_data: callback_handler 解析后的告警事件数据
                {
                    'warn_code': str,
                    'warn_msg': str,
                    'warn_level': str,  # "0"/"1"/"2"/"3"
                    'agv_code': str,
                    'task_code': str,
                }

        Returns:
            AlarmDisposition 处置决策
        """
        warn_code = warn_data.get('warn_code', '').upper()
        warn_level_str = warn_data.get('warn_level', '0')

        # 1. 按 warnCode 模糊匹配
        for keyword, disposition in cls.RULES.items():
            if keyword in warn_code:
                return disposition

        # 2. 按 warnLevel 兜底
        try:
            level = int(warn_level_str)
        except (ValueError, TypeError):
            level = 0

        return cls.LEVEL_DEFAULTS.get(level,
            AlarmDisposition(AlarmLevel.INFO, 'warn_info', False, 0))
```

### 3.3 增强 WorkflowEventBridge —— 告警分级路由

修改 `event_bridge.py` 的 `_on_rcs_warn_callback`:

```python
# === event_bridge.py 中替换 _on_rcs_warn_callback ===

from app_mgr_object.components.workflow.alarm_classifier import (
    AlarmClassifier, AlarmLevel
)

def _on_rcs_warn_callback(self, data: Dict[str, Any]):
    """RCS warnCallback → 分级路由处置"""
    task_code = data.get('task_code', '')
    if not task_code or not self._engine:
        return

    # 检查任务实例是否存在
    instance = self._engine.get_instance(task_code)
    if not instance:
        self._logger.warning(f"收到 warnCallback 但未找到实例: {task_code}")
        return

    # === 告警分级判定 ===
    disposition = AlarmClassifier.classify(data)

    self._logger.info(
        f"RCS warnCallback → 分级: {disposition.description} "
        f"(level={disposition.level.name}, event={disposition.engine_event})"
    )

    # === 按级别执行不同策略 ===
    if disposition.level == AlarmLevel.INFO:
        # L0: 仅记录，不注入任何事件
        self._publish('rcs.alarm_logged', {
            'task_code': task_code,
            'level': disposition.level.name,
            'warn_code': data.get('warn_code', ''),
            'warn_msg': data.get('warn_msg', ''),
        })
        return

    elif disposition.level == AlarmLevel.WARNING:
        # L1: 注入 warn_l1，实例可自行决定是否暂停
        # 注入事件但不转入 manual_intervention
        self._publish('rcs.alarm_logged', data)
        self._inject_to_engine(task_code, disposition.engine_event, data)
        return

    elif disposition.level in (AlarmLevel.SEVERE, AlarmLevel.CRITICAL):
        # L2/L3: 注入 callback_exception → manual_intervention
        self._publish('rcs.alarm_logged', data)
        self._inject_to_engine(task_code, disposition.engine_event, data)

        # L3 额外发布全局告警
        if disposition.level == AlarmLevel.CRITICAL:
            self._publish('rcs.critical_alarm', {
                'task_code': task_code,
                'warn_msg': data.get('warn_msg', ''),
                'agv_code': data.get('agv_code', ''),
            })


def _inject_to_engine(self, task_code: str, event: str, data: dict):
    """安全注入事件到引擎"""
    try:
        future = asyncio.run_coroutine_threadsafe(
            self._engine.inject_event(task_code, event, data),
            self._loop
        )
        future.add_done_callback(
            lambda f: self._logger.debug(f"事件注入完成: {task_code}")
            if f.exception() is None
            else self._logger.error(f"事件注入失败: {f.exception()}")
        )
    except Exception as e:
        self._logger.error(f"注入事件异常: {task_code} → {event}: {e}")
```

## 4. 需求 2: 异常任务自动闭环

### 4.1 核心思路

`task_status_monitor` 当前只轮询 `monitoring` 状态实例。需要扩展覆盖 `manual_intervention` 状态的实例，使系统能在运维人员不操作的情况下自动完结。

**设计**:
- 扩展 `engine.get_pending_instances()` 返回 `monitoring` + `manual_intervention` 实例
- 对 `manual_intervention` 实例的轮询间隔可以更稀疏（如 30s）
- 如果轮询检测到 RCS 任务已完成(9) → 自动完结(路由到 completed)

### 4.2 引擎增强

在 `engine.py` 新增方法:

```python
def get_all_active_monitorable_instances(self) -> Dict[str, str]:
    """获取所有需要轮询监控的实例（monitoring + manual_intervention）

    Returns:
        {task_code: rcs_task_no}
    """
    result = {}
    for task_id, instance in self._instances.items():
        if not instance.is_running:
            continue
        if instance.current_state not in ('monitoring', 'manual_intervention'):
            continue
        rcs_task_no = instance.context.get('rcs_task_no', '')
        if rcs_task_no:
            result[task_id] = rcs_task_no
    return result

def get_active_monitoring_instances(self) -> Dict[str, str]:
    """仅返回 monitoring 状态的实例（保持向后兼容）"""
    return {k: v for k, v in self.get_all_active_monitorable_instances().items()
            if self._instances[k].current_state == 'monitoring'}
```

### 4.3 task_status_monitor 增强

在 `task_monitor_plugin.py` 中新增对 `manual_intervention` 实例的轮询:

```python
def _poll_once(self):
    try:
        engine = self._get_workflow_engine()
        if not engine:
            return

        # === 监控 monitoring 实例 (高频率) ===
        monitoring = engine.get_active_monitoring_instances()
        if monitoring:
            rcs = self._get_rcs_adapter()
            if rcs:
                self._monitor.poll_if_needed(rcs, monitoring)

        # === 新增: 监控 manual_intervention 实例 (低频率) ===
        if self._should_poll_manual():
            manual = engine.get_all_active_monitorable_instances()
            manual_only = {k: v for k, v in manual.items()
                           if k not in monitoring}
            if manual_only:
                rcs = self._get_rcs_adapter()
                if rcs:
                    self._poll_manual_instances(rcs, manual_only, engine)

        if not monitoring and not manual_only if 'manual_only' in dir() else True:
            if self._monitor.should_stop_timer():
                self._stop_poll_timer()

    except Exception as e:
        self.logger.warning(f"轮询执行异常: {e}")


def _should_poll_manual(self) -> bool:
    """manual_intervention 实例轮询频率控制 (每 30s 一次)"""
    now = time.time()
    if not hasattr(self, '_last_manual_poll'):
        self._last_manual_poll = 0.0
    if now - self._last_manual_poll >= 30.0:
        self._last_manual_poll = now
        return True
    return False


def _poll_manual_instances(self, rcs, manual_instances: dict, engine):
    """对 manual_intervention 实例查询 RCS 状态，检测自动恢复"""
    try:
        resp = rcs.query_task_status(list(manual_instances.keys()))
        if resp.get('code') != '0':
            return

        for item in resp.get('data', []):
            task_code = item.get('taskCode', '')
            task_status = str(item.get('taskStatus', ''))

            if task_code not in engine._instances:
                continue

            instance = engine._instances[task_code]
            if instance.current_state != 'manual_intervention':
                continue

            if task_status == '9':
                # RCS 侧任务已完成 → 自动完结
                self.logger.info(f"自动闭环: {task_code} RCS 已完成(9), 自动完结")
                import asyncio
                asyncio.run_coroutine_threadsafe(
                    engine.inject_event(task_code, 'auto_resolved', {
                        'task_status': task_status,
                        'source': 'task_monitor_auto_closure',
                    }), self.node.asyncio_loop
                )

            elif task_status in ('7', '8'):
                # RCS 侧已失败/取消 → 自动完结
                self.logger.info(f"自动闭环: {task_code} RCS 已终结({task_status}), 自动完结")
                import asyncio
                asyncio.run_coroutine_threadsafe(
                    engine.inject_event(task_code, 'auto_failed', {
                        'task_status': task_status,
                        'source': 'task_monitor_auto_closure',
                    }), self.node.asyncio_loop
                )

    except Exception as e:
        self.logger.warning(f"manual_intervention 轮询异常: {e}")
```

## 5. 需求 3: 运维手动操作接口

### 5.1 ROS2 Service 设计

定义统一的运维操作服务:

**服务名**: `/task_control`  
**服务类型**: 自定义 `app_mgr_object/srv/TaskControl`

```
# TaskControl.srv (ROS2 自定义服务)

string operation     # force_trigger / cancel / retry / query
string task_id       # 任务 ID (query 时可选)
# --- 以下字段 force_trigger 时使用 ---
string src_bay       # 起始仓位
string dst_bay       # 终点仓位
int32  robot_id      # 指定 AGV 编号
int32  cargo_type    # 货物类型 1~6
---
bool   success       # 操作是否成功
string message       # 返回消息
string task_status   # 任务当前状态 (query 时有效)
```

### 5.2 实现

在 `workflow_engine_plugin.py` 的 `_activate_impl()` 中注册:

```python
def _activate_impl(self) -> bool:
    # ... 原有激活逻辑 ...

    # === 新增: 注册 ROS2 Service ===
    self._task_control_srv = self.node.create_service(
        TaskControl, '/task_control', self._on_task_control
    )
    self.logger.info("运维操作服务已注册: /task_control (force_trigger/cancel/retry/query)")

    return True


def _on_task_control(self, request, response):
    """处理运维操作请求"""
    op = request.operation
    task_id = request.task_id

    try:
        if op == 'force_trigger':
            ctx = {
                'task_id': f"MANUAL_{int(time.time())}",
                'src_bay': request.src_bay,
                'dst_bay': request.dst_bay,
                'robot_id': request.robot_id,
                'cargo_type': request.cargo_type,
            }
            asyncio.run_coroutine_threadsafe(
                self._engine.create_instance('agv_transport_atomic', ctx),
                self._loop
            )
            response.success = True
            response.message = f"强制任务已下发: {ctx['task_id']}"

        elif op == 'cancel':
            asyncio.run_coroutine_threadsafe(
                self._engine.cancel_instance(task_id),
                self._loop
            )
            response.success = True
            response.message = f"任务已取消: {task_id}"

        elif op == 'retry':
            asyncio.run_coroutine_threadsafe(
                self._engine.inject_event(task_id, 'user_retry', {}),
                self._loop
            )
            response.success = True
            response.message = f"任务已重试: {task_id}"

        elif op == 'query':
            instance = self._engine.get_instance(task_id)
            if instance:
                response.success = True
                response.task_status = instance.current_state
                response.message = f"status={instance.current_state}"
            else:
                response.success = False
                response.message = f"任务不存在: {task_id}"

        else:
            response.success = False
            response.message = f"不支持的操作: {op}"

    except Exception as e:
        response.success = False
        response.message = f"操作异常: {e}"

    return response
```

## 6. 需求 4: 超时自动闭环 + 告警升级

### 6.1 设计思路

`manual_intervention` 应具备"自愈窗口"机制:
- 如果 RCS 侧任务在 N 分钟内恢复(AGV 重新上线、故障清除) → 自动检测并完结
- 如果超时未恢复 → 告警升级(Web 面板弹窗、日志标记)

### 6.2 manual_intervention 增强 YAML

```yaml
  - id: manual_intervention
    description: "等待运维人员处理，具备自动恢复检测和超时升级"
    final: true
    on_enter:
      - action: log_manual_entry        # 记录进入人工介入的时间戳
      - action: publish_manual_event    # 发布给 Web 面板
    transitions:
      # === 运维手动操作 ===
      - event: "user_retry"
        target: "calling_rcs"
      - event: "user_cancel"
        target: "failed"

      # === 自动闭环 (由 task_monitor 注入) ===
      - event: "auto_resolved"          # RCS 任务自动恢复完成
        target: "auto_recovery"
      - event: "auto_failed"            # RCS 任务自动终结(失败/取消)
        target: "failed"

  # === 新增: 自动恢复状态 ===
  - id: auto_recovery
    description: "任务在人工介入期间自动恢复完成"
    final: true
    on_enter:
      - action: release_resources
    on_exit:
      - action: publish_completed_event
```

### 6.3 告警升级机制

在 `manual_intervention` 的 `on_enter` 中记录 `entered_at` 时间戳。通过 task_monitor 的定时扫描检测超时:

```python
# task_monitor_plugin.py 中新增超时检测
def _check_manual_intervention_timeout(self, engine):
    """检测 manual_intervention 实例是否超时未处理"""
    now = time.time()
    timeout_threshold = 600.0  # 10 分钟

    pending = engine.get_all_active_monitorable_instances()
    for task_id in pending:
        instance = engine.get_instance(task_id)
        if instance and instance.current_state == 'manual_intervention':
            entered_at = instance.context.get('manual_entered_at', 0)
            if entered_at and (now - entered_at) > timeout_threshold:
                self.logger.warning(
                    f"告警升级: {task_id} 在 manual_intervention 已超 {timeout_threshold}s, "
                    f"等待人工处置"
                )
                self._publish_event('rcs.alarm_escalated', {
                    'task_id': task_id,
                    'duration': now - entered_at,
                })
```

### 7.1 SQLite 表设计

```sql
CREATE TABLE IF NOT EXISTS alarm_logs (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    task_id       TEXT NOT NULL,
    alarm_level   TEXT,            -- INFO/WARNING/SEVERE/CRITICAL
    warn_code     TEXT,
    warn_msg      TEXT,

    task_id       TEXT NOT NULL,
    from_state    TEXT,
    to_state      TEXT,
    trigger_event TEXT,            -- 触发状态变更的事件
    changed_at    TIMESTAMP DEFAULT (datetime('now','localtime'))
);

-- 3. 异常事件日志 (补充 task_instances 表的终态之外的信息)
CREATE TABLE IF NOT EXISTS exception_log (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    task_id       TEXT NOT NULL,
    event_type    TEXT,            -- timeout / warn_callback / action_error / max_retry
    detail        TEXT,            -- JSON 格式的详细上下文
    logged_at     TIMESTAMP DEFAULT (datetime('now','localtime'))
);

-- 索引
CREATE INDEX IF NOT EXISTS idx_alarm_task ON alarm_logs(task_id);
CREATE INDEX IF NOT EXISTS idx_state_task ON state_change_log(task_id);
CREATE INDEX IF NOT EXISTS idx_exception_task ON exception_log(task_id);
```

### 7.4 persistence.py 新增方法

```python
def log_state_change(self, task_id: str, from_state: str,
                     to_state: str, trigger_event: str = ''):
    """记录状态变更到日志表"""
    try:
        with sqlite3.connect(self._db_path) as conn:
            conn.execute("""
                INSERT INTO state_change_log
                (task_id, from_state, to_state, trigger_event)
                VALUES (?, ?, ?, ?)
            """, (task_id, from_state, to_state, trigger_event))
            conn.commit()
    except Exception:
        pass  # 日志写入失败不影响核心流程

def log_alarm(self, task_id: str, alarm_level: str,
              warn_code: str, warn_msg: str, agv_code: str = '',
              disposition: str = ''):
    """记录告警日志"""
    try:
        with sqlite3.connect(self._db_path) as conn:
            conn.execute("""
                INSERT INTO alarm_logs
                (task_id, alarm_level, warn_code, warn_msg, agv_code, disposition)
                VALUES (?, ?, ?, ?, ?, ?)
            """, (task_id, alarm_level, warn_code, warn_msg, agv_code, disposition))
            conn.commit()
    except Exception:
        pass

def log_exception(self, task_id: str, event_type: str, detail: str = ''):
    """记录异常事件"""
    try:
        with sqlite3.connect(self._db_path) as conn:
            conn.execute("""
                INSERT INTO exception_log (task_id, event_type, detail)
                VALUES (?, ?, ?)
            """, (task_id, event_type, detail))
            conn.commit()
    except Exception:
        pass

def query_alarms_by_task(self, task_id: str, limit: int = 50) -> list:
    """按任务 ID 查询告警日志"""
    with sqlite3.connect(self._db_path) as conn:
        conn.row_factory = sqlite3.Row
        cursor = conn.execute(
            "SELECT * FROM alarm_logs WHERE task_id = ? "
            "ORDER BY logged_at DESC LIMIT ?",
            (task_id, limit)
        )
        return [dict(row) for row in cursor.fetchall()]

def query_state_changes(self, task_id: str) -> list:
    """查询任务状态变更历史"""
    with sqlite3.connect(self._db_path) as conn:
        conn.row_factory = sqlite3.Row
        cursor = conn.execute(
            "SELECT * FROM state_change_log WHERE task_id = ? "
            "ORDER BY changed_at ASC",
            (task_id,)
        )
        return [dict(row) for row in cursor.fetchall()]
```

```yaml
name: "agv_transport_atomic"

      - event: "callback_exception"   → manual_intervention   # L1 升级为 L2
      - event: "timeout"              → monitoring             # 超时自动恢复

  - id: compensating_query

    timeout: 10

      - event: "rcs_running"         → monitoring
      - event: "max_retry_reached"   → manual_intervention

  - id: releasing
    action: release_resources
```
