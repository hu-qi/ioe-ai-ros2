## 0. 审查结论（摘要）

当前 `param_manager.py` 的热加载持久化链路在**简单场景**下可用（bay_configs / dest_bay_configs / pair_overrides / cargo_priority / 顶层参数），但在以下场景存在可靠性风险：

| 风险点 | 严重程度 | 触发条件 |
|---|---|---|
| **双 YAML 编码退化** | 🔴 高 | `yaml.dump()` 嵌入 `yaml.dump()`，列表/多行值格式丢失 |
| **嵌套路径写入不完整** | 🔴 高 | 修改 `smart_trigger.work_schedule.schedules[0].start_time` 等深层路径 |
| **文件写非原子** | 🟡 中 | 进程崩溃 / 磁盘满时，params.yaml 可能写入一半 |
| **并发写竞态** | 🟡 中 | Web 端 + CLI 同时 `set_parameters` 写同一 YAML |
| **web_monitor 配置段独立** | 🟡 中 | web_monitor 参数走 `set_param_and_persist`，与 plugin_configs 热加载路径不一致 |
| **YAML 注释丢失** | 🟢 低 | `yaml.dump()` 丢弃手写注释（不阻塞功能） |

本文案给出**修复 `-5-3` 现有代码的完整技术方案**，覆盖 YAML 格式调整、参数管理器重构、原子持久化、ROS2 参数服务同步、验证测试。

## 1. 现状分析

### 1.1 当前 params.yaml 结构（问题根因）

```yaml
app_mgr_object:
  ros__parameters:
    log_level: "info"                        # ← 顶层 ROS2 简单参数
    plugin_load_order: [...]                 # ← 顶层 ROS2 数组参数

    plugin_configs: |                        # ← ⚠ YAML 块字符串（内嵌 YAML）
      plugin_load_order: [...]
      bay_status_fusion:
        bay_configs:
          A1001: 1
      ...
      smart_trigger:
        work_schedule:                       # ← ⚠ 三层嵌套
          schedules:
            - day_of_week: "mon-fri"
              start_time: "08:00"
              ...

    web_monitor: |                           # ← ⚠ 另一个 YAML 块字符串
      enabled: true
      port: 9183
      ...
```

**核心问题**：`plugin_configs` 和 `web_monitor` 的值是 **YAML 块字符串**（`|` 字面量标量）。ROS2 将其视为一个字符串参数，参数管理器在 `_declare_common_parameters` 处用 `yaml.safe_load()` 解析为 dict。但写回时需：

1. 内部 dict → `yaml.dump()` → 字符串
2. 外部 config → `yaml.dump()` → 文件

两次 `yaml.dump()` 导致**格式降级**（列表缩进、多行值换行、空字典 `{}` 变 `null`）。

### 1.2 当前热加载写回链路

```
Web API (PUT /api/config/bay)
  → web_monitor_plugin.apply_config('bay_configs', value)
    → param_manager.update_plugin_config_nested(['bay_status_fusion', 'bay_configs'], value)
      → _params['plugin_configs'] 读为 dict  →  path 遍历 → 修改
      → yaml.dump(plugin_configs) → 内层字符串  ──⚠ 双编码
      → _read_yaml(path)  → yaml.dump(config) → 写文件  ──⚠ 非原子
      → node.set_parameters(plugin_configs=string)  → 触发 _on_parameters_changed
        → _param_callbacks[plugin_configs] 分发回调
```

### 1.3 已实现的能力（保持兼容）

- ✅ `update_plugin_config_nested(path, value)` — 两层路径写入
- ✅ `update_plugin_config_section(section, new_value)` — 兼容旧接口
- ✅ `set_param_and_persist(name, value)` — 顶层参数持久化
- ✅ `_backup_and_write_yaml()` — 写前备份 `.bak`
- ✅ `_on_parameters_changed()` — 回调分发（注册于 `_param_callbacks`）
- ✅ `apply_config()` → `_apply_bay_configs / _apply_dest_configs / _apply_*` — 内存热应用
- ✅ `apply_params()` → 白名单顶层参数热加载

### 1.4 遗留缺陷清单

| ID | 缺陷描述 | 影响 |
|---|---|---|
| B1 | `update_plugin_config_nested` 只支持 2 层路径 `['section', 'key']`，不支持 `['smart_trigger', 'work_schedule', 'schedules']` 深度修改 | 工作时段编辑必须传整个 schedules 列表，单条修改无法穿透 |
| B2 | `yaml.dump(plugin_configs)` 嵌入外层 `yaml.dump(config)` 时，列表缩进/多行值被二次转义 | 重启后部分配置解析异常 |
| B3 | `_backup_and_write_yaml` 使用 `open + yaml.dump` 非原子写入，崩溃时可能写半截 | 工业环境停电/进程杀导致启动失败 |
| B4 | `update_plugin_config_nested` 和 `set_param_and_persist` 无文件锁，并发写竞争 | Web + CLI 同时修改产生交错写入 |
| B5 | `web_monitor` 参数与 `plugin_configs` 参数使用不同热加载路径，配置管理不统一 | 运维复杂度增加 |
| B6 | ROS2 声明参数时 `yaml.safe_load()` 只在启动时解析一次，后续写回文件后不会自动刷新 | 重启前修改的配置实际已生效但 params.yaml 不一致 |

## 2. 技术方案总览

### 2.1 设计原则

1. **兼容优先**：不改变 params.yaml 外部结构，不破坏现有启动/重启行为
2. **原子写入**：临时文件 + `os.replace()` 保证文件内容完整
3. **深度路径支持**：`update_plugin_config_nested` 支持任意深度路径
4. **单写者锁**：文件级 `threading.Lock` 防并发
5. **双通道同步**：写文件 + ROS2 `set_parameters` 必须事务性一致
6. **校验先行**：写前验证 YAML 结构完整性，写后回读校验

### 2.2 架构调整

```
                          ┌──────────────────────────────────┐
                          │        ParamManager (重构)        │
                          │                                  │
  Web API ────────────────┤  update_plugin_config_nested()   │
  ros2 param set ────────┤    + 深度路径支持                 │
  CLI ───────────────────┤    + 文件锁                       │
                          │    + 原子写入（临时文件+rename）  │
                          │    + 写后回读校验                 │
                          │                                  │
  ┌───────────────────┐   │  _write_yaml_atomic()            │
  │ params.yaml       │◄──┤    → params.yaml.tmp             │
  │ params.yaml.tmp   │   │    → os.replace(tmp, yaml)       │
  │ params.yaml.bak   │   │    → 回读校验                     │
  └───────────────────┘   │                                  │
                          │  set_param_and_persist()          │

                          │                                  │
                          │  _on_parameters_changed()         │
                          │    + 回调 → 插件内存热应用         │
                          └──────────────────────────────────┘
```

## 3. YAML 参数格式规范化

### 3.1 格式原则

ROS2 参数文件遵循 [ROS2 Parameter YAML 规范](https://docs.ros.org/en/humble/Tutorials/Beginner-CLI-Tools/Understanding-ROS2-Parameters/Understanding-ROS2-Parameters.html)：

1. **节点命名空间**：`/app_mgr_object` → YAML key `app_mgr_object.ros__parameters`
2. **简单参数**：`log_level: "info"` 直接 K=V
3. **数组参数**：`plugin_load_order: [...]`
4. **结构化参数**（推荐）：ROS2 Humble+ 支持 `declare_parameter` 直接嵌套 dict，无需字符串包装
5. **字符串参数**（兼容旧方式）：`plugin_configs: "..."` — 值被声明为 `String`，代码内解析

### 3.2 当前格式的合理性评估

| 参数 | 当前格式 | 合理性 | 建议 |
|---|---|---|---|
| `log_level` | 简单值 | ✅ | 保持 |
| `plugin_load_order` | 数组 | ✅ | 保持 |
| `plugin_configs` | YAML 块字符串 | ⚠️ 历史遗留 | **保持**（改动波及面大，本批仅修复写入问题） |
| `web_monitor` | YAML 块字符串 | ⚠️ 同上 | **保持**，统一热加载路径 |

> **决策**：本次不将 `plugin_configs` / `web_monitor` 从 YAML 块字符串改为 ROS2 原生嵌套参数。原因：
> - 涉及 12+ 插件配置读取代码路径改造（`_get_plugin_configs` → 多级 `get_parameter`）
> - 需回归测试全部插件的配置注入
> - YAML 块字符串仍在 ROS2 工业部署中广泛使用（简单、可读性好）
>
> **后续优化方向**（Phase 5）：拆为独立 YAML 文件 → `config/bay_fusion.yaml`、`config/smart_trigger.yaml` 等，各插件独立加载，避免巨型块字符串。

### 3.3 YAML dump 格式要求

使用 `yaml.dump()` 时必须保证：

```python
yaml.dump(
    data,
    allow_unicode=True,        # 支持中文
    default_flow_style=False,  # 块格式（非流式 JSON）
    sort_keys=False,           # 保持插入顺序
    indent=2,                  # 统一缩进
    width=120,                 # 长行不自动折行
)
```

⚠ 禁止 `default_flow_style=True`（会将嵌套 dict 转为 `{key: val}` 流格式，与手写风格冲突）。

## 4. ParamManager 重构方案

### 4.1 原子写入模块 `_write_yaml_atomic`

替换当前 `_backup_and_write_yaml`，使用**临时文件 + 系统 rename**：

```python
import os
import shutil
import tempfile
import threading

class ParamManager:
    def __init__(self, node: Node):
        # ... 现有初始化 ...
        self._yaml_lock = threading.Lock()   # 新增：文件写锁
        self._write_version = 0              # 新增：写版本号（调试用）

    def _write_yaml_atomic(self, path: str, config: dict) -> bool:
        """原子写入 YAML 文件（临时文件 + rename + 回读校验）

        写入流程：
        1. 在同一目录创建 .tmp 临时文件
        2. yaml.dump 写入临时文件 + fsync
        3. os.replace() 原子替换（同文件系统保证原子性）
        4. 回读校验 key 数量一致

        Returns:
            True 表示写入成功且校验通过
        """
        with self._yaml_lock:
            tmp_path = path + '.tmp'
            bak_path = path + '.bak'
            try:
                # Step 1: 备份现有文件
                if os.path.exists(path):
                    shutil.copy2(path, bak_path)

                # Step 2: 写入临时文件
                with open(tmp_path, 'w', encoding='utf-8') as f:
                    yaml.dump(
                        config, f,
                        allow_unicode=True,
                        default_flow_style=False,
                        sort_keys=False,
                        indent=2,
                        width=120,
                    )
                    f.flush()
                    os.fsync(f.fileno())   # 强制刷盘（工业环境关键）

                # Step 3: 原子替换（POSIX rename 在同文件系统是原子的）
                os.replace(tmp_path, path)

                # Step 4: 回读校验（可选，视性能要求开启）
                if not self._verify_yaml(path, config):
                    # 校验失败：恢复备份
                    self.logger.error("YAML 回读校验失败，尝试恢复备份")
                    if os.path.exists(bak_path):
                        os.replace(bak_path, path)
                    return False

                self._write_version += 1
                self.logger.debug(f"YAML 原子写入成功: {path} (v{self._write_version})")
                return True

            except Exception as e:
                self.logger.error(f"原子写入 YAML 失败 [{path}]: {e}")
                # 清理临时文件
                if os.path.exists(tmp_path):
                    try:
                        os.remove(tmp_path)
                    except OSError:
                        pass
                return False

    def _verify_yaml(self, path: str, expected: dict, strict: bool = False) -> bool:
        """回读校验：读回刚写入的文件并与预期对比

        Args:
            strict: True 时逐值对比；False 时仅对比顶层 key 数量与结构
        """
        try:
            actual = self._read_yaml(path)
            if actual is None:
                return False
            if strict:
                return actual == expected
            # 宽松校验：顶层 key 数量和命名空间存在
            expected_top_keys = set(expected.keys())
            actual_top_keys = set(actual.keys())
            return expected_top_keys == actual_top_keys
        except Exception:
            return False
```

### 4.2 深度路径更新 `update_plugin_config_nested` (重构)

替换当前的两层路径实现，支持任意深度：

```python
    def update_plugin_config_nested(self, path: list, value: Any) -> bool:
        """更新 plugin_configs 中任意深度嵌套路径的值并持久化。

        Args:
            path: 键路径列表，逐层导航
                  例: ['bay_status_fusion', 'bay_configs']
                  例: ['smart_trigger', 'work_schedule', 'schedules']
                  例: ['smart_trigger', 'work_schedule', 'schedules', 0, 'start_time']
            value: 新值（dict / list / 原子值）

        Returns:
            True 表示持久化成功且 ROS2 参数同步完成
        """
        if not path:
            self.logger.error("update_plugin_config_nested: path 不能为空")
            return False

        try:
            # 1. 读取当前完整 plugin_configs
            raw = self._params.get('plugin_configs', {})
            if isinstance(raw, str):
                plugin_configs = yaml.safe_load(raw) or {}
            elif isinstance(raw, dict):
                plugin_configs = raw
            else:
                plugin_configs = {}

            # 2. 克隆一份用于写入（避免修改 _params 引用）
            import copy
            plugin_configs = copy.deepcopy(plugin_configs)

            # 3. 沿路径导航到目标父节点
            target = plugin_configs
            for key in path[:-1]:
                if isinstance(target, list) and isinstance(key, int):
                    # 列表索引
                    if key < 0 or key >= len(target):
                        raise IndexError(f"列表索引越界: {key} (length={len(target)})")
                    target = target[key]
                elif isinstance(target, dict):
                    target = target.setdefault(key, {})
                else:
                    raise TypeError(
                        f"路径 {path} 在 key={key} 处类型不匹配: "
                        f"期望 dict/list，实际 {type(target).__name__}"
                    )

            # 4. 写入新值
            leaf_key = path[-1]
            if isinstance(target, list) and isinstance(leaf_key, int):
                # 列表元素替换
                if leaf_key < 0 or leaf_key >= len(target):
                    raise IndexError(f"列表索引越界: {leaf_key}")
                target[leaf_key] = value
            elif isinstance(target, dict):
                target[leaf_key] = value
            else:
                raise TypeError(
                    f"最终路径 {path} 的目标类型 {type(target).__name__} 不支持写入"
                )

            # 5. 序列化 → YAML 字符串
            new_plugin_str = yaml.dump(
                plugin_configs,
                allow_unicode=True,
                default_flow_style=False,
                sort_keys=False,
                indent=2,
                width=120,
            )

            # 6. 持久化到 params.yaml
            path_yaml = self._get_params_yaml_path()
            config = self._read_yaml(path_yaml)
            app = config.setdefault('app_mgr_object', {}) \
                        .setdefault('ros__parameters', {})
            app['plugin_configs'] = new_plugin_str

            if not self._write_yaml_atomic(path_yaml, config):
                self.logger.error(f"嵌套路径持久化失败: {' -> '.join(str(k) for k in path)}")
                return False

            # 7. 同步 ROS2 参数 + 回调分发
            self._params['plugin_configs'] = plugin_configs
            param = rclpy.Parameter('plugin_configs', value=new_plugin_str)
            self.node.set_parameters([param])
            # set_parameters 会触发 _on_parameters_changed，分发 _param_callbacks

            self.logger.info(
                f"嵌套路径热加载成功: {' -> '.join(str(k) for k in path)}"
            )
            return True

        except (IndexError, TypeError, KeyError) as e:
            self.logger.error(f"嵌套路径导航失败 [{path}]: {e}")
            return False
        except Exception as e:
            self.logger.error(f"嵌套路径更新异常 [{path}]: {e}")
            return False
```

### 4.3 顶层参数持久化 `set_param_and_persist` (增强)

统一 `plugin_configs` 和 `web_monitor` 的持久化路径：

```python
    def set_param_and_persist(self, name: str, value: Any) -> bool:
        """设置 ROS2 参数（运行时生效）并原子持久化到 params.yaml。

        支持两类参数：
        - 简单参数（log_level, network_timeout ...）：K=V 直接写
        - 字符串参数（web_monitor, plugin_configs ...）：值写入其对应的 YAML 键
        """
        try:
            # 1. ROS2 参数声明/更新（运行时生效）
            if not self.update_param(name, value):
                return False

            # 2. 持久化到 params.yaml
            path = self._get_params_yaml_path()
            config = self._read_yaml(path)
            app = config.setdefault('app_mgr_object', {}) \
                        .setdefault('ros__parameters', {})

            # 处理字符串类型的 YAML 块参数
            if name in ('web_monitor', 'plugin_configs'):
                if isinstance(value, dict):
                    app[name] = yaml.dump(
                        value,
                        allow_unicode=True,
                        default_flow_style=False,
                        sort_keys=False,
                        indent=2,
                        width=120,
                    )
                elif isinstance(value, str):
                    app[name] = value
                else:
                    app[name] = str(value)
            else:
                app[name] = value

            if not self._write_yaml_atomic(path, config):
                self.logger.error(f"参数 {name} 持久化写入失败")
                return False

            self.logger.info(f"参数持久化成功: {name}")
            return True

        except Exception as e:
            self.logger.error(f"参数持久化异常 [{name}]: {e}")
            return False
```

### 4.4 `_on_parameters_changed` 增强（插件间事件桥）

当前回调分发已正确实现，但缺少**跨插件间桥接**（如 `plugin_configs` 变更时需通知 `smart_trigger` 等插件刷新）。增强方案：

```python
    def _on_parameters_changed(self, params: List[rclpy.Parameter]):
        for param in params:
            name = param.name
            value = param.value

            # JSON/YAML 字符串预解析（保持现有逻辑）
            if isinstance(value, str) and value.startswith(('{', '[')):
                try:
                    value = json.loads(value)
                except json.JSONDecodeError:
                    pass

            self._params[name] = value

            # 分发注册的回调
            cb = self._param_callbacks.get(name)
            if cb:
                try:
                    cb(name, value)
                except Exception as e:
                    self.logger.error(f"参数回调执行失败 {name}: {e}")

            # === 新增：plugin_configs 变更 → 插件事件桥 ===
            if name == 'plugin_configs':
                self._notify_plugin_config_changed(value)

        return rclpy.SetParametersResult(successful=True)

    def _notify_plugin_config_changed(self, config: dict):
        """plugin_configs 变更时，通知已注册的插件刷新内存配置

        通过 EventBus 广播 plugin_configs.updated 事件，
        各插件在 _activate_impl 中订阅该事件，收到后执行局部 reload。
        """
        try:
            node = self.node
            if hasattr(node, 'event_bus') and node.event_bus:
                node.event_bus.publish('plugin_configs.updated', config)
                self.logger.debug("plugin_configs 变更事件已广播")
        except Exception as e:
            self.logger.warning(f"plugin_configs 变更通知失败: {e}")
```

> **注意**：若工程未启用 EventBus，此逻辑降级为仅调用已注册回调（现有行为），不影响核心链路。

## 5. web_monitor 插件适配

### 5.1 `apply_config` 深度路径支持

当前 `apply_config()` 的 `path_map` 只支持 5 个预定义段，扩展为通用路径：

```python
    def apply_config(self, section: str, value: Any, sub_path: list = None) -> dict:
        """Web 配置热加载入口

        Args:
            section: 配置段标识
                - 预定义: 'bay_configs', 'dest_bay_configs', 'work_schedule',
                          'pair_overrides', 'cargo_priority'
                - 通用路径: section 即为 plugin_configs 下的顶层 key
            value: 新值
            sub_path: 可选的子路径（用于深层更新）
                例: section='work_schedule', sub_path=['schedules', 0, 'start_time']
                    → 路径 = ['smart_trigger', 'work_schedule', 'schedules', 0, 'start_time']
        """
        try:
            # 构建完整路径
            path_map = {
                'bay_configs':      ['bay_status_fusion', 'bay_configs'],
                'dest_bay_configs': ['status_poller', 'dest_bay_configs'],
                'work_schedule':    ['smart_trigger', 'work_schedule'],
                'pair_overrides':   ['smart_trigger', 'pair_overrides'],
                'cargo_priority':   ['smart_trigger', 'cargo_priority'],
            }
            base_path = path_map.get(section, [section])
            full_path = base_path + (sub_path or [])

            # 校验
            handler = self._reload_handlers.get(section)
            if handler:
                error = self._validate_section(section, value)
                if error:
                    return {'success': False, 'error': error}

            # 持久化
            pm = getattr(self.node, 'param_manager', None)
            if pm is None:
                return {'success': False, 'error': '参数管理器未就绪'}

            if not pm.update_plugin_config_nested(full_path, value):
                return {'success': False, 'error': '配置持久化失败（已保留原值）'}

            # 内存应用
            if handler:
                handler(value)

            # WebSocket 广播
            self._publish_event('config.updated', {
                'section': section,
                'path': full_path,
            })
            self._broadcast_message({
                'type': 'config_updated',
                'section': section,
                'timestamp': time.time(),
            })

            return {
                'success': True,
                'message': f'配置段 {section} 已更新并热加载',
                'hot_reload': True,
                'path': full_path,
            }

        except Exception as e:
            self.logger.error(f"apply_config 失败 [{section}]: {e}")
            return {'success': False, 'error': str(e)}
```

## 8. 附录

### 8.1 文件锁说明

使用 `threading.Lock` 而非文件系统锁（`fcntl`）的原因：

1. **单进程内**：所有写操作通过 `ParamManager` 单例 → `threading.Lock` 足够
2. **跨进程**：当前架构下，只有 `/app_mgr_object` 一个节点进程写入 params.yaml
3. **若未来需要多进程安全**：改用 `portalocker` 或 `fcntl.flock(LOCK_EX)`

```python
# 若需跨进程安全（可选升级）
try:
    import fcntl
    def _write_yaml_atomic(self, path, config):
        with open(path, 'a') as lock_fd:
            fcntl.flock(lock_fd.fileno(), fcntl.LOCK_EX)
            # ... 写入逻辑 ...
            fcntl.flock(lock_fd.fileno(), fcntl.LOCK_UN)
except ImportError:
    # Windows 降级为 threading.Lock
    pass
```
