```
业务插件（smart_trigger/workflow）
  → business_update WS（event_bridge 防抖 + hash 变更推送）
```

## 六、v3 修订记录（2026-08-26：深色背景线条不可见反馈）

### 问题
板端运行触发任务后，**仓位区深色背景上未看到线条与线条状态**（v2 灰蓝细线 + 半透明在深色背景上不可辨）。

### 根因
1. **视觉对比不足**：v2 线条 1.5~2px、颜色 #7a93b5/#38bdf8、opacity .75，深色卡片背景（#182A47 系）上对比度低；
2. **端点圆点 bug**：pair-lines.js `_create` 创建 circle 时**未设置 r 属性**（SVG 默认 r=0）→ 端点圆点完全不可见；
3. z-index 3 虽高于卡片 hover(2)，但为更保险提升至 5。

### 修复（v3）
| 项 | v2 | v3 |
|---|---|---|
| pending 线宽/颜色 | 1.5px / #7a93b5 | **2.5px / 亮青蓝 #9db8e0**（opacity .95） |
| active 线宽/颜色 | 2px / #38bdf8 | **3.5px / 高亮蓝 #7dd3fc** |
| 衬底光晕 | 无 | **drop-shadow 双层**（深色衬底 1px + 亮色 glow 3~10px） |
| 端点圆点 | r 未设置（**不可见**） | **r=4**（JS 显式 setAttribute）+ 亮色 #e0f2fe + 蓝描边 + 光晕 |
| z-index | 3 | **5** |
| 调试 | 无 | update 时 `console.log('[P1] pair lines: N ...')`（板端数据流排查） |

### 改动文件
- static/css/custom.css：v3 样式（加粗 + 亮色 + drop-shadow 衬底 + z-index 5 + 端点光晕）；
- static/js/pair-lines.js：`_create` 补 `setAttribute('r','4')`（端点可见性修复）+ update 调试日志。

## 七、v4 修订记录（2026-08-26：板端"全程无连线"数据链路根因修复）

### 问题
v3（加粗亮色）上传板端触发任务，全程无任何连接线。任务日志显示业务链路正常（B1001→T2003 绑定→匹配→入队→出队→下发 RCS→35s 完成）。

### 根因
1. **主因**：`business_collector.get_active_instances()` 迭代 `engine.get_active_instances()` 返回的 **dict 的 key（str）** 走 snapshot 分支，而 `get_instance_snapshot()` 快照**无顶层 src_bay/dst_bay**（在 `context` 内）→ `snap.get('src_bay','')` 恒空 → 前端 `if (t.src_bay && t.dst_bay)` 全过滤 → **active 线永不渲染**；
2. **次要**：候选入队→出队仅 ~6ms（idle AGV 立即分发）+ 推送防抖 → pending 虚线几乎不可见（业务固有：候选即触发，积压时才可见）。

### 修复
- components/web/business_collector.py：`get_active_instances` 改用 `engine.get_active_instances()` **字典值**（含 src_bay/dst_bay/robot_id/cargo_type）；旧字符串列表兼容分支从 `snapshot.context` 取；
- 返回结构不变（`{'instances': [...], 'count': n}`），前端零改动。

### 验证
- `python -m py_compile business_collector.py`：PY OK；
- 规划文档新增 §十二（根因/修复/验证）+ §2.1 数据契约补充 + §8.1 排查步骤更新。

### 板端回归（待执行）
1. 部署更新后的 business_collector.py，重启 app_mgr；
2. 触发任务（B1001→T2003）→ F12 console 应见 `[P1] pair lines: 1 B1001→T2003:active`；
