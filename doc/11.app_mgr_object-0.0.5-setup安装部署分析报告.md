
## 2. setup.py data_files 分析

### 2.1 当前 data_files 配置

```python
data_files=[
    ('share/ament_index/resource_index/packages',
        ['resource/' + package_name]),
    ('share/' + package_name, ['package.xml']),
    (os.path.join('share', package_name, 'config'), 
        glob('config/*.yaml')),
    (os.path.join('share', package_name, 'launch'), 
        glob('launch/*.launch.py')),
],
```

### 2.2 glob 模式逐一分析

| glob 表达式 | 匹配到的文件 | 遗漏的文件 |
|:---|:---|:---|
| `glob('config/*.yaml')` | ✅ `config/params.yaml` | ❌ `config/db_schema.sql`（`.sql` 不匹配 `*.yaml`） |
| | | ❌ `config/workflows/agv_transport_atomic.yaml`（在子目录中，`*` 不匹配 `/`） |
| `glob('launch/*.launch.py')` | ✅ `launch/app_app.launch.py` | 无遗漏 |

### 2.3 遗漏后果

| 遗漏文件 | 后果 |
|:---|:---|
| `config/db_schema.sql` | 该 SQL 文件不会被安装到 `share/app_mgr_object/config/` 目录。数据库初始化依赖此文件时失败 |
| `config/workflows/agv_transport_atomic.yaml` | **工作流引擎启动失败**。`workflow_engine_plugin` 的 `WorkflowDefinitionLoader` 在 `definitions_dir` 目录下找不到任何 `.yaml` 或 `.yml` 文件，`load_definitions()` 返回 0，引擎无法执行任何工作流 |

### 2.4 安装后目录结构对比

**当前 data_files 产生的结构**:
```
share/app_mgr_object/
├── package.xml
├── config/
│   └── params.yaml                    ← 仅此一个文件
│   ❌ db_schema.sql                   ← 遗漏
│   ❌ workflows/                      ← 整个子目录遗漏
│       ❌ agv_transport_atomic.yaml
└── launch/
    └── app_app.launch.py
```

**应有结构**:
```
share/app_mgr_object/
├── package.xml
├── config/
│   ├── params.yaml
│   ├── db_schema.sql
│   └── workflows/
│       └── agv_transport_atomic.yaml
└── launch/
    └── app_app.launch.py
```

## 5. 修复方案

### 5.1 setup.py data_files 修复

将 `data_files` 中的 config 相关条目改为：

```python
data_files=[
    ('share/ament_index/resource_index/packages',
        ['resource/' + package_name]),
    ('share/' + package_name, ['package.xml']),

    # ── config 目录（含子目录） ──
    # 方式 A: 逐文件列出（精确控制，推荐生产环境）
    (os.path.join('share', package_name, 'config'), [
        'config/params.yaml',
        'config/db_schema.sql',
        'config/workflows/agv_transport_atomic.yaml',
    ]),

    # ── launch 目录 ──
    (os.path.join('share', package_name, 'launch'), 
        glob('launch/*.launch.py')),
],
```

**备选方式 B**（自动递归，适用于文件频繁新增的开发期）:

```python
# 递归收集 config 目录下所有文件
config_files = []
for root, dirs, files in os.walk('config'):
    for f in files:
        full_path = os.path.join(root, f)
        config_files.append(full_path)

data_files=[
    ...
    (os.path.join('share', package_name, 'config'), config_files),
    ...
],
```

> ⚠️ 方案 B 会将所有文件（包括 `.pyc`、临时文件）打包，建议加过滤只包含 `.yaml` / `.sql` / `.json`。

### 5.2 推荐最终 data_files 代码

```python
import os
from glob import glob

data_files=[
    ('share/ament_index/resource_index/packages',
        ['resource/' + package_name]),
    ('share/' + package_name, ['package.xml']),

    # config/ — 全局参数 + 数据库 schema
    (os.path.join('share', package_name, 'config'), [
        'config/params.yaml',
        'config/db_schema.sql',
    ]),

    # config/workflows/ — YAML 工作流定义
    (os.path.join('share', package_name, 'config', 'workflows'),
        glob('config/workflows/*.yaml')),

    # launch/
    (os.path.join('share', package_name, 'launch'),
        glob('launch/*.launch.py')),
],
```

**优点**: 三个目标目录分别对应三个 `data_files` 条目，安装后目录结构清晰：

```
share/app_mgr_object/
└── config/
    ├── params.yaml
    ├── db_schema.sql
    └── workflows/
        └── agv_transport_atomic.yaml
```

## 6. 运行时路径解析问题

### 6.1 当前问题

`workflow_engine_plugin.py` 中的路径解析：

```python
# 当前代码
pkg_share = self.config.get('pkg_share_dir', '')
self._definitions_dir = self.config.get(
    'definitions_dir',
    os.path.join(pkg_share, 'config', 'workflows')
)
self._db_path = self.config.get(
    'db_path',
    os.path.join(pkg_share, 'config', 'task_instances.db')
)
```

`params.yaml` 中的配置：

```yaml
workflow_engine:
  definitions_dir: "config/workflows"
  db_path: "config/task_instances.db"
```

**问题**: 这两个都是**相对路径**。如果进程不在包目录下启动（如通过 `ros2 launch` 启动），相对路径会解析到错误的目录。

### 6.2 修复：使用 ROS2 标准路径解析

```python
# workflow_engine_plugin.py _configure_impl

from ament_index_python.packages import get_package_share_directory

def _configure_impl(self) -> bool:
    try:
        # 使用 ROS2 标准方法获取包 share 目录
        pkg_share = get_package_share_directory('app_mgr_object')

        # 从 params.yaml 读取相对路径，拼接到 pkg_share
        defs_rel = self.config.get('definitions_dir', 'config/workflows')
        db_rel = self.config.get('db_path', 'config/task_instances.db')

        self._definitions_dir = os.path.join(pkg_share, defs_rel)
        self._db_path = os.path.join(pkg_share, db_rel)

        # ... 其余初始化代码
```

**类似地，`action_registry` 或任何需要访问 `config/` 下文件的组件也应使用此方法。**

### 6.3 task_instances.db 的写入位置

`task_instances.db` 是运行时创建的 SQLite 数据库文件。将其放在 `share/` 目录下存在问题：

- `share/` 是只读安装目录（`colcon build --symlink-install` 除外）
- 多用户环境下可能无权写入

**推荐方案**: 将数据库文件放在可写目录：

```python
# 优先使用环境变量，其次使用用户目录，最后 fallback 到 pkg_share
import os

def _get_db_path(self, pkg_share: str) -> str:
    db_rel = self.config.get('db_path', 'config/task_instances.db')
    # 1. 环境变量覆盖
    env_db = os.environ.get('APP_MGR_DB_PATH', '')
    if env_db:
        return env_db
    # 2. 用户数据目录
    user_data = os.path.join(os.path.expanduser('~'), '.app_mgr_object')
    os.makedirs(user_data, exist_ok=True)
    return os.path.join(user_data, 'task_instances.db')
```

| 文件 | 当前问题 | 修复 |
|:---|:---|:---|
| `setup.py` L49 | `glob('config/*.yaml')` 遗漏 `.sql` 和子目录 | 改为三个独立条目（§5.2） |
| `MANIFEST.in` | 遗漏 `.sql` 和 `workflows/` | 追加 `include config/*.sql` + `recursive-include config/workflows *.yaml` |
| `workflow_engine_plugin.py` | 相对路径不可靠 | 使用 `get_package_share_directory('app_mgr_object')` 解析 |
