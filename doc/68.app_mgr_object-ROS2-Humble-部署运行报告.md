## 三、ROS2 Humble 安装过程

### 3.1 配置 ROS2 apt 仓库 (清华 TUNA 镜像)

```bash
# 安装基础工具
apt-get update
apt-get install -y curl gnupg2 lsb-release ca-certificates software-properties-common wget

# 配置 ROS2 源 (清华镜像，arm64，trusted=yes 绕过签名验证)
echo "deb [arch=arm64 trusted=yes] https://mirrors.tuna.tsinghua.edu.cn/ros2/ubuntu jammy main" \
  > /etc/apt/sources.list.d/ros2.list

apt-get update
```

> **说明**: 原方案用 `curl https://raw.githubusercontent.com/ros/rosdistro/master/ros.key` 获取 GPG key，但 `raw.githubusercontent.com` 在该主机被墙 (curl 卡死 5+ 分钟)。改用清华 TUNA 镜像 + `trusted=yes` 绕过签名验证。此方案适用于内网测试机；生产环境建议通过代理获取官方 key 并用 `signed-by` 验证。

### 4.3 关键踩坑点

1. **fastapi 0.63 + pydantic 2.x 冲突** — 系统 apt 装的是 `python3-fastapi 0.63`，但 pip 升级把 `pydantic` 升到了 v2，导致 `PydanticUserError: Field 'type_' defined on a base class was overridden`。
   - **修复**: `apt remove python3-fastapi python3-pydantic python3-starlette` 后 `pip install fastapi>=0.100`。

2. **numpy 2.x 与系统 cv_bridge 冲突** — pip 升级 opencv 时连带把 numpy 升到 2.2.6，但系统 `cv_bridge` 是用 NumPy 1.x 编译的，报 `_ARRAY_API not found`。
   - **修复**: `pip install "numpy<2"` 降级回 1.26.4，并卸载 pip 装的 `opencv-python-headless 5.0.0`，回到系统自带 `cv2 4.5.4`。

3. **cv2.Mat 在旧 opencv 不存在** — 代码 `image_manager.py` 用了 `Optional[cv2.Mat]` 类型注解，但系统 opencv 4.5.4 没有 `Mat` 类 (新版 opencv 4.5.1+ 才有)。
   - **修复**: 将 `image_manager.py` 第 26、181 行的 `cv2.Mat` 改为 `np.ndarray`，兼容旧 opencv。

### 5.2 创建的骨架文件

#### 5.2.1 `app_mgr_object/components/trigger/__init__.py`

#### 5.2.2 `app_mgr_object/components/trigger/pairing_policy.py`

配对策略骨架，提供:

- `Lane(lane_id, floor, strategy, bay_ids)` — 巷道对象
- `StrategyPolicy` — 策略枚举 (ANY/FIFO/FILO/LIFO/NEAREST)，含 `parse(str)` 类方法
- `select_slot(strategy, empty_indices)` — 按策略从空位索引列表中选一个

骨架语义:
- `any` / `fifo` / `nearest`: 取第一个 (索引最小)
- `filo` / `lifo`: 取最后一个 (索引最大)
- 空列表返回 `None`

#### 5.2.3 `app_mgr_object/components/trigger/hot_reload.py`

配置热加载骨架，提供:

- `HotReloadRegistry(logger=None)` — 热加载注册器
  - `register(key, validator, applier)` — 注册热加载项
  - `apply(name, cfg)` — 应用配置变更
- `validate_dict(value)` — 校验器，要求值为 dict
- `validate_positive_number(value)` — 校验器，要求值为正数

#### 5.2.4 `app_mgr_object/plugins/workflow_engine_plugin.py`

工作流引擎插件骨架，继承 `BasePlugin`:

- `PLUGIN_NAME = "workflow_engine"`, `PLUGIN_VERSION = "0.1.0"`
- `_configure_impl`: 从配置加载工作流定义 (仅记录，不解析执行)
- `_activate_impl`: 激活 (骨架，无实际编排)
- `_deactivate_impl` / `_cleanup_impl`: 清理状态

#### 5.2.5 `app_mgr_object/plugins/smart_trigger_plugin.py`

智能触发器插件骨架，继承 `BasePlugin`:

- `PLUGIN_NAME = "smart_trigger"`, `PLUGIN_VERSION = "0.1.0"`

- `_activate_impl`: 激活 (骨架，无实际匹配)
- `_deactivate_impl` / `_cleanup_impl`: 清理状态

- **timeout 监控线程** — 周期检查每个实例当前 state 的 `timeout` 配置，超时注入 `timeout` 事件
- **final 终态处理** — 进入 `final: true` 状态时执行 `on_exit` actions 并标记 `finished`
- **全局异常处理** — `on_error` actions
- **内置 action handlers** — `invoke_gen_task`/`wait_for_completion`/`compensate_query`/`release_resources`/`publish_*_event`/`log_*` (空实现，可通过 `register_action` 覆盖)
- **查询接口** — `get_instance`/`list_instances`/`get_status`

支持的工作流定义格式 (参见 `config/workflows/agv_transport_atomic.yaml`):
```yaml
name: "agv_transport_atomic"
initial_state: "calling_rcs"
max_concurrent: 10
states:
  - id: calling_rcs
    action: invoke_gen_task
    retry: 2
    timeout: 10
    transitions:
      - event: "rcs_ack_ok"
        target: "monitoring"
  - id: completed
    final: true
    on_exit:
      - action: publish_completed_event
on_error:
  - action: log_error
  - action: release_resources
```

新增功能:
- **周期扫描线程** — 按 `scan_interval` (默认 2.0s) 周期扫描起始仓位

### 8.4 RCS 404 刷屏修复与验证 (2026-09-03)

#### 问题根因

`status_poller` 插件每 3 秒轮询 `/queryAgvStatus`、每 10 秒轮询 `/queryPodBerthAndMat`，这些请求打到本机 `192.168.31.249:8080`（即 `app_mgr_node` 自身的 Web 服务器），但该服务器没有 RCS 路由，返回 404。由于 RCS 服务端未部署，这些 404 会无限刷屏。

#### 修复措施

1. **禁用 `status_poller` 插件** — `config/plugin_configs/status_poller.yaml` 设置 `auto_start: false` + `enabled: false`
   - `_activate_impl` 在 `enabled: false` 时直接 `return True`，跳过轮询定时器创建
2. **禁用 `rcs_adapter` 插件** — `config/plugin_configs/rcs_adapter.yaml` 设置 `auto_start: false` + `enabled: false`
3. **禁用 OPS 集成** — `config/web_monitor.yaml` 的 `ops_integration.enabled` 改为 `false`（本机未部署 OPS 服务 `127.0.0.1:1818`）
4. **修复 `eth1` 接口不存在** — 三处 `api_network_interface` 从 `eth1` 改为 `eth0`：
   - `config/params.yaml:18`
   - `app_mgr_object/base/param_manager.py:71`
   - `config/plugin_configs/network.yaml`
5. **补齐 `workflow_engine_plugin` 缺失方法** — 消除 `'WorkflowEnginePlugin' object has no attribute 'get_engine'` 等 ERROR：
   - `get_engine()` 返回 `self`
   - `get_active_instances()` / `get_instance_snapshot()`
   - `get_active_monitoring_instances()` / `get_all_active_monitorable_instances()`
   - `count_today_completed()` / `count_today_failed()`
   - `get_all_instances_from_db()` / `cleanup_old_logs()`

### 9.6 常见故障排查速查表

| 现象 | 可能原因 | 排查命令 | 修复方法 |
|---|---|---|---|
| `systemctl status` 显示 `failed` | 编译失败或依赖缺失 | `journalctl -u app_mgr -n 50` | 检查编译输出，确认 Python 依赖已安装 |
| 8080 端口无响应 | 节点未启动或崩溃 | `pgrep -af app_mgr_node` | `systemctl restart app_mgr` |
| 9183 返回 500 | Starlette TemplateResponse 签名不兼容 | `journalctl -u app_mgr -n 50 \| grep TypeError` | 确认 `web_server.py` 使用新签名 `(request, name, context)` |
| 日志大量 404 | status_poller 轮询打到本机 | `journalctl -u app_mgr \| grep 404` | 禁用 `status_poller.yaml` 的 `enabled` |
| `eth1 不存在` 警告 | 配置引用了不存在的网卡 | `ip addr` 确认实际网卡 | 把 `api_network_interface` 改为 `eth0` |
| `get_engine` 报错 | workflow_engine_plugin 缺方法 | `journalctl -u app_mgr \| grep "no attribute"` | 确认 `workflow_engine_plugin.py` 包含 `get_engine()` 等方法 |
| 编译报 `cv2.Mat` 错误 | 旧 opencv 4.5.4 无 Mat 类 | `python3 -c "import cv2; print(cv2.__version__)"` | 把 `cv2.Mat` 改为 `np.ndarray` |
| colcon build 卡住 | 网络不通或镜像不可达 | `curl -I https://mirrors.tuna.tsinghua.edu.cn` | 检查网络、DNS、镜像源配置 |

### 9.7 回滚方案

如果新版本部署失败，需要回退到上一个可用版本:

```bash
# 1. 停止服务
systemctl stop app_mgr

# 2. 回退代码 (如果有 git)

git log --oneline -5          # 查看最近的提交
git checkout <上一个可用版本的commit-hash>

# 3. 重新编译
source /opt/ros/humble/setup.bash
cd /root/ros2_ws
colcon build --packages-select app_mgr_object --symlink-install

# 4. 重启服务
systemctl start app_mgr

# 5. 验证
systemctl status app_mgr
curl -s -o /dev/null -w "HTTP %{http_code}\n" http://192.168.31.249:9183/
```

## 十、systemd 服务管理 (开机自启 + 崩溃重启)

### 10.1 服务文件

文件路径: `/etc/systemd/system/app_mgr.service`

源文件位于本地 `deploy/app_mgr.service`，通过 SFTP 上传到远程主机。

```ini
[Unit]
Description=ROS2 Humble app_mgr_object Node
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=root
Environment=ROS_DISTRO=humble
Environment=ROS_DOMAIN_ID=0
Environment=RMW_IMPLEMENTATION=rmw_fastrtps_cpp
Environment=PYTHONUNBUFFERED=1
ExecStartPre=/bin/bash -c 'source /opt/ros/humble/setup.bash && source /root/ros2_ws/install/setup.bash && echo "ROS2 environment ready"'
ExecStart=/bin/bash -c 'source /opt/ros/humble/setup.bash && source /root/ros2_ws/install/setup.bash && exec ros2 launch app_mgr_object app_app.launch.py'
ExecStop=/bin/bash -c 'pkill -f "app_mgr_node" 2>/dev/null; pkill -f "ros2 launch app_mgr" 2>/dev/null; exit 0'
Restart=on-failure
RestartSec=5
TimeoutStartSec=30
TimeoutStopSec=10
KillMode=mixed

StandardOutput=journal
StandardError=journal
SyslogIdentifier=app_mgr

LimitNOFILE=65536
MemoryMax=2G

[Install]
WantedBy=multi-user.target
```

### 10.2 安装与启用

```bash
# 上传服务文件后，重新加载 systemd
systemctl daemon-reload

# 设置开机自启
systemctl enable app_mgr

# 启动服务
systemctl start app_mgr

# 验证状态
systemctl status app_mgr
systemctl is-active app_mgr    # 应为 active
systemctl is-enabled app_mgr   # 应为 enabled
```

### 10.4 崩溃自动重启

服务配置了 `Restart=on-failure` 和 `RestartSec=5`，当 `app_mgr_node` 进程异常退出时，systemd 会在 5 秒后自动重启服务。

模拟崩溃测试:
```bash

# 等待 5-10 秒，检查是否自动恢复
sleep 10
systemctl status app_mgr
# 应看到 "active (running)" 且 Main PID 已变化
```

## 十一、附录: 远程主机 SSH 访问方式

由于 Windows OpenSSH 不带 `sshpass`，且 bash 为非交互式无法直接输密码，本部署通过 Python `paramiko` 库实现 SSH 自动化:

```python
import paramiko
c = paramiko.SSHClient()
c.set_missing_host_key_policy(paramiko.AutoAddPolicy())
c.connect("192.168.31.249", username="root", password="Mind@123",
          timeout=15, allow_agent=False, look_for_keys=False)
# 执行命令: c.exec_command(...)
# 上传文件: c.open_sftp().put(local, remote)
```
