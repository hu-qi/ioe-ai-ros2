## 2. 发现的问题与风险

### 2.1 监控线程停止竞态（🟡 低风险）

```python
# web_monitor_plugin.py — _start_monitoring()
def monitoring_loop():
    while self._enabled:              # ← 读取布尔标志
        try:
            ...
        except Exception as e:
            ...
        time.sleep(monitor_interval)   # ← 睡眠最多 5s

# _deactivate_impl()
self._enabled = False
if hasattr(self, '_monitoring_thread'):
    self._monitoring_thread.join(timeout=5)  # ← 等 5s
```

**风险**：`_enabled` 不是线程安全标志。如果 `_deactivate_impl` 在 `monitoring_loop` 刚进入睡眠后设置 `_enabled = False`，线程最多等 `monitor_interval` 秒才退出。`join(timeout=5)` 可能在监控间隔设为 10s 时超时。

**影响**：极低。daemon 线程在主线程退出时自动终止，5s 超时足够覆盖当前默认的 5s 监控间隔。

**建议**：使用 `threading.Event` 替代布尔标志：

```python
# __init__ 中
self._stop_event = threading.Event()

# monitoring_loop 中
while not self._stop_event.is_set():
    ...
    self._stop_event.wait(monitor_interval)  # 可中断睡眠

# _deactivate_impl 中
self._stop_event.set()
self._monitoring_thread.join(timeout=5)
```

### 2.2 `broadcast()` 异常静默（🟢 设计决策）

```python
# event_bridge.py
def broadcast(self, msg_type: str, data: Any = None):
    try:
        ...
    except Exception as e:
        self.logger.debug(f"WebSocket 广播失败 [{msg_type}]: {e}")
        # ← 仅 debug 日志，不抛异常
```

**分析**：这是合理的降级设计——WebSocket 广播失败不应阻塞业务逻辑。前端客户端断开或网络波动时自动恢复。

### 2.3 `config_manager._validate_section` 只校验 5 个预定义段（🟢 设计约束）

```python
# config_manager.py
def _validate_section(self, section: str, value: Any) -> str:
    if section == 'bay_configs': ...
    if section == 'dest_bay_configs': ...
    if section == 'work_schedule': ...
    if section == 'pair_overrides': ...
    if section == 'cargo_priority': ...
    return ''  # ← 未匹配的段无校验
```

**建议**（后续优化）：当 `section` 不在预定义列表中时返回空，由调用方自行保证。当前业务范围内 5 个段已覆盖全部可热加载配置。
