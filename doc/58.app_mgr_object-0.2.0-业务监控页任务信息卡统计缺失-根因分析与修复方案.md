## 1. 问题现象

业务监控页（`templates/index.html`）底部“任务信息”卡片：应显示 **今日完成 / 执行中 / 异常 / 已锁定目的仓** 四项统计；实际表现为：

1. 卡片无统计数字（显示“暂无任务统计”占位或全 0，视觉上“没有内容”）；
2. 鼠标悬停指标卡（`.ts-item`）无任何响应动画（需求要求 hover 有反馈）。

## 4. 根因分析

### R-01（主因）后端统计“数据源不可用”与“真实为 0”无法区分，且依赖链脆弱

- `get_task_statistics` 在 **workflow_engine 插件未加载、引擎未就绪、统计异常、无历史数据** 四种情况下**全部返回全 0**（business_collector.py:225-233、285），且响应中**无任何“数据源是否就绪”的标识**；
- 常见触发：`cpp_ros2_interfaces` 未编译/未安装 → `workflow_engine_plugin` import 失败 → 插件未加载 → 统计恒为 0；或启动顺序/初始化失败导致 `wf.get_engine()` 为空；
- 前端收到全 0 后按“正常数据”渲染四项 0，用户观感为“没有统计内容”；若接口异常（业务采集器未就绪 503），前端才走 `stats.error` 占位“暂无任务统计”。

### R-02 前端占位文案样式缺失

- 占位分支使用 `.text-dim`（dashboard.js:272），但该样式只在表格作用域定义（custom.css:256），普通 `div` 下不生效 → 占位内容无颜色/弱化样式，视觉上接近空白，加深“没显示内容”的观感。

### R-03 hover 响应动画缺失（明确需求）

- `.ts-item` 无 `:hover` 规则（custom.css:463-468 仅静态样式），鼠标悬停无任何反馈；需求要求“鼠标在指标上应有响应动画”。

### R-04（次要）初始加载与 WS 数据形态不一致、字段空值处理单一

- 初始接口返回 `{success:true, ...}`，WS `business_update.task_stats` 返回裸对象；`renderTaskStats` 已兼容两种形态（`data.task_stats || data`），但字段一律 `|| 0`，无法表达“未就绪/加载中/异常”等中间态（与 R-01 同源）。

## 5. 修复技术方案

### 阶段 1：后端统计状态语义化（根因修复）

`business_collector.get_task_statistics` 返回值增加**数据源就绪标识**，让前端能区分“就绪但为 0”与“未就绪/异常”：

```python
# 目标返回值（示意）
{
    'ready': True,                    # workflow_engine 插件 + 引擎均就绪
    'by_status': {...}, 'total': 0,
    'today_completed': 0, 'executing': 0, 'failed': 0, 'locked_dest': 0,
    'source': 'workflow_engine',      # 数据源说明
    'last_error': '',                 # 未就绪/异常时给出原因，便于日志与排查
}
```

- `wf` 未加载：`{'ready': False, 'last_error': 'workflow_engine 未加载'}`；
- `engine` 未就绪：`{'ready': False, 'last_error': 'workflow_engine 未激活'}`；
- 统计异常：`{'ready': False, 'last_error': str(e)}`（保留 `empty` 字段，前端兼容）；
- 正常但无数据：`{'ready': True, ...全 0}`（明确表达“确实无数据”）；
- 同时 `logger.warning/error` 记录未就绪原因，便于运维定位（如 cpp_ros2_interfaces 缺失）。

### 阶段 2：前端三态渲染 + 占位样式

`renderTaskStats` 支持 **ready / empty / error** 三态：

```js
function renderTaskStats(data) {
    var el = document.getElementById('task-stats');
    if (!el) return;
    var stats = (data && data.task_stats) ? data.task_stats : data;
    if (!stats || typeof stats !== 'object') return;
    if (stats.ready === false) {                       // 数据源未就绪
        el.innerHTML = '<div class="ts-empty">统计初始化中…（数据源未就绪）</div>';
        return;
    }
    if (stats.error) {                                 // 接口异常
        el.innerHTML = '<div class="ts-empty">暂无任务统计</div>';
        return;
    }
    var items = [...];                                 // 正常渲染四项（0 也正常显示）
    el.innerHTML = items.map(...).join('');
}
```

custom.css 新增：

```css
.ts-empty {
    padding: 12px; text-align: center;
    color: var(--text-secondary); font-size: 12px;
}
```

（同时可为 `.text-dim` 增加全局弱化定义，作为通用占位样式。）

### 阶段 3：hover 响应动画（需求项）

```css
/* 任务信息统计卡：hover 反馈动画 */
.ts-item {
    transition: transform .15s ease, box-shadow .15s ease,
                border-color .15s ease, background .15s ease;
    cursor: default;
}
.ts-item:hover {
    transform: translateY(-2px);
    border-color: var(--accent-blue);
    box-shadow: 0 4px 14px rgba(52, 152, 219, .25);
    background: rgba(52, 152, 219, .08);
}
.ts-item:hover .ts-value { color: var(--accent-blue); }   /* 数字高亮（保留 pulse/error/locked 专属色可覆盖） */
```

- 与既有 `.ts-value.pulse` 呼吸动画互不冲突（hover 只改位移/边框/阴影/背景）；
- 浅色主题适配：在 `[data-theme="light"]` 块内补充同规则（背景用浅蓝透明度）。

### 阶段 4：一致性加固（可选）

- `business_collector.collect_business_status` 的 `task_stats` 与 `/api/task/stats` 使用同一函数输出（已一致），确保初始加载与 WS 结构统一；
- 前端字段取值增加 null 安全：`value: (stats.today_completed == null ? 0 : stats.today_completed)`（防止字符串/缺失混入）。

## 6. 测试与验收

### 6.1 单元测试（后端）

1. `get_task_statistics`：workflow_engine 未加载 → `ready=False + last_error`；引擎未就绪 → `ready=False`；正常无数据 → `ready=True + 全 0`；异常 → `ready=False + 错误信息`；
2. `count_by_date` 正常/异常回退路径保持（既有行为）。

### 6.2 前端验证

- 无 node 环境时：`node --check`（如可用）+ 人工核对 `renderTaskStats` 三态分支与 CSS 类名；
- 浏览器：分别模拟“接口 503 / ready=false / 全 0 / 正常数据”四种响应，卡片显示分别为“统计初始化中…/暂无任务统计/四项 0/四项数值”；
- hover：鼠标悬停 `.ts-item` 有上移+描边+阴影+数值高亮动画，深浅主题均正常。

### 6.3 板端回归

- 正常部署（cpp_ros2_interfaces 已编译）：任务信息卡四项统计随任务执行实时刷新（WS 路径）；
- 故障模拟（workflow 未加载）：卡片显示“统计初始化中…（数据源未就绪）”，日志输出 `last_error`；
- 无历史任务：四项显示 0（正常语义），与“未就绪”可区分。

---

## 7. 兼容性与回滚

- 后端新增 `ready/last_error` 字段为**增量**，旧前端忽略即可；旧后端无该字段时前端按 `ready` 缺省处理（undefined 视为就绪，保持现状渲染）；
- 样式与 JS 改动均为增量，可单独回滚；无接口破坏、无数据库变更；
- 建议实施顺序：阶段 1（后端语义）→ 阶段 2（前端三态）→ 阶段 3（hover）→ 阶段 4（可选加固）。

---

## 8. 结论

1. “任务信息卡无统计内容”的根因是**后端统计在“数据源未就绪/异常/无数据”三种情况下全部坍缩为全 0，且无就绪标识**，前端无法区分，配合占位样式缺失（R-02）形成“没内容”的观感；hover 动画缺失为独立需求项（R-03）；
2. 修复以**后端状态语义化 + 前端三态渲染 + hover 动画**为主线，均为增量、可回滚、向后兼容；
3. 建议审核通过后按阶段 1→4 实施，并配套单测与板端回归。
