## 2. 问题 1：前端触发/取消/重试二次确认

### 2.1 现状

`app_mgr_object/components/web/static/js/dashboard.js` 中：

```javascript
// 强制触发
document.getElementById('btn-force-trigger').addEventListener('click', function() {
    var src = document.getElementById('trigger-src').value;
    var dst = document.getElementById('trigger-dst').value;
    ...
    API.taskControl('force_trigger', { src_bay: src, dst_bay: dst }).then(...);
});

// 取消（btn-cancel-task）与重试（btn-retry-task）同理，直接 taskControl(...)
```

三个高风险操作均**无确认直接执行**。`control.html` 已有自定义确认弹窗工具 `showConfirmationModal / showCustomModal` 可参考（L1924、L2092 等），但 `index.html` 页面未引入。

### 2.2 解决方案

优先采用**原生 `confirm()`**（改动最小、无依赖、样式简单），后续如需统一风格再迁移到自定义模态框。三个操作统一封装为 `confirmTaskControl(action, params, confirmText)`。

### 2.3 代码（dashboard.js）

```javascript
/**
 * 任务控制统一入口（带二次确认）
 * @param {string} action   force_trigger / cancel / retry
 * @param {object} params   API 参数
 * @param {string} confirmText  确认文案
 */
function confirmTaskControl(action, params, confirmText) {
    if (!window.confirm(confirmText)) {
        showToast('操作已取消', 'info');
        return;
    }
    API.taskControl(action, params).then(function(r) {
        if (r.success) {
            showToast(r.message || '操作成功: ' + action, 'success');
            loadAllData();
        } else {
            showToast(r.error || '操作失败', 'error');
        }
    });
}

// 强制触发（需选择 AGV，见问题 2）
document.getElementById('btn-force-trigger').addEventListener('click', function() {
    var src = document.getElementById('trigger-src').value;
    var dst = document.getElementById('trigger-dst').value;
    var robotId = parseInt(document.getElementById('trigger-robot').value) || 0;
    var cargoType = parseInt(document.getElementById('trigger-cargo').value) || 1;
    if (!src || !dst) { showToast('请选择起始仓和目的仓', 'warning'); return; }
    if (src === dst) { showToast('起始仓和目的仓不能相同', 'warning'); return; }
    if (!robotId) { showToast('请选择可用 AGV', 'warning'); return; }

    confirmTaskControl('force_trigger', {
        src_bay: src,
        dst_bay: dst,
        robot_id: robotId,
        cargo_type: cargoType
    }, '确定下发强制任务？\n' + src + ' → ' + dst + '\nAGV: ' + robotId);
});

// 取消
document.getElementById('btn-cancel-task').addEventListener('click', function() {
    var tid = document.getElementById('ctrl-task-id').value.trim();
    if (!tid) { showToast('请输入 task_id', 'warning'); return; }
    confirmTaskControl('cancel', { task_id: tid },
        '确定取消任务 ' + tid + ' 吗？\n取消后将释放该任务占用的资源。');
});

// 重试
document.getElementById('btn-retry-task').addEventListener('click', function() {
    var tid = document.getElementById('ctrl-task-id').value.trim();
    if (!tid) { showToast('请输入 task_id', 'warning'); return; }
    confirmTaskControl('retry', { task_id: tid },
        '确定重试任务 ' + tid + ' 吗？\n将从 calling_rcs 状态重新下发。');
});
```

> 说明：`query`（查询）属只读操作，无需确认。

### 2.4 验证点

- 点击"执行触发/取消/重试"弹出确认框；取消则不发起请求；
- 确认后 Toast 显示结果；任务面板（活跃/队列/历史）自动刷新。

## 3. 问题 2：强制触发任务选择可用 AGV

### 3.1 现状与问题

**前端**：`index.html` 触发表单只有 `trigger-src` / `trigger-dst` 两个下拉；`dashboard.js` 的 `force_trigger` 请求体为 `{src_bay, dst_bay}`，**不含 robot_id**。

**后端**：`components/web/task_controller.py` 的 `force_trigger` 分支：

```python
new_id = f"WEB_{int(time.time() * 1000)}"
ctx = {'task_id': new_id, 'src_bay': src_bay, 'dst_bay': dst_bay,
       'robot_id': robot_id or 0, 'cargo_type': cargo_type or 1}
future = asyncio.run_coroutine_threadsafe(
    engine.create_instance('agv_transport_atomic', ctx), loop)
```

问题链：

```text
前端不传 robot_id → web_server task_control_api 默认 robot_id=0
  → context['robot_id']=0 → RCSPayloadBuilder agvCode = str(0)
  → RCS 收到 agvCode=0（无效 AGV）→ 下发失败或错误派车
且：未做 AGV 可用性校验、未做资源锁定（StateCoordinator.dispatch_task），
    可能与自动调度任务抢占同一 AGV/仓位。
```

### 3.2 解决思路

```text
前端：AGV 下拉（仅显示 AVAILABLE）+ 货物类型下拉（可选）
  → /api/agv/status（getAgvStatus）动态填充
  → force_trigger 请求体携带 robot_id / cargo_type

后端 TaskController.force_trigger：
  ① robot_id 为空 → 自动分配（RobotCache.get_available_robot），无可用 AGV 则报错
  ② 校验 robot_id 存在且状态 AVAILABLE
  ③ StateCoordinator.dispatch_task(robot_id, src, dst, task_id) 锁定资源
     （锁 AGV/起点/终点 + mark_in_task + set_busy）
  ④ 锁定成功后才创建实例；创建异常则回滚释放（coordinator.release_task）
  ⑤ 返回 task_id 与 robot_id，前端展示

与 P0-1 协同：强制任务同样走 StateCoordinator 统一释放，完成/失败后
  release_task 幂等释放，不会泄漏。
```

#### 3.4.1 `components/web/task_controller.py` —— force_trigger 改造

```python
if operation == 'force_trigger':
    if not src_bay or not dst_bay:
        return {'success': False, 'error': 'force_trigger 需要 src_bay 和 dst_bay'}

    # ① AGV 选择/自动分配 + 可用性校验
    poller = self._get_plugin('status_poller')
    robot_cache = poller.robot_cache if poller else None
    if not robot_cache:
        return {'success': False, 'error': 'status_poller 未加载，无法分配 AGV'}

    if robot_id and robot_id > 0:
        rinfo = robot_cache.get_robot_status(robot_id)
        if not rinfo:
            return {'success': False, 'error': f'AGV {robot_id} 不存在'}
        if rinfo.get('status') != 'AVAILABLE':
            return {'success': False, 'error':
                    f'AGV {robot_id} 不可用（当前 {rinfo.get("status")}）'}
    else:
        robot_id = robot_cache.get_available_robot()
        if not robot_id:
            return {'success': False, 'error': '无可用 AGV，无法下发强制任务'}

    new_id = f"WEB_{int(time.time() * 1000)}"
    ctx = {'task_id': new_id, 'src_bay': src_bay, 'dst_bay': dst_bay,
           'robot_id': robot_id, 'cargo_type': cargo_type or 1}

    # ② 资源锁定（幂等释放入口 StateCoordinator，与自动任务一致）
    coordinator = getattr(self.node, 'state_coordinator', None)
    locked = False
    if coordinator is not None:
        locked = coordinator.dispatch_task(robot_id, src_bay, dst_bay,
                                           task_id=new_id)
        if not locked:
            return {'success': False,
                    'error': '资源冲突：AGV/起始仓/目的仓已被占用或不可用'}

    # ③ 创建实例（失败回滚释放）
    try:
        future = asyncio.run_coroutine_threadsafe(
            engine.create_instance('agv_transport_atomic', ctx), loop)
        future.result(timeout=5)
    except Exception as e:
        if coordinator is not None and locked:
            coordinator.release_task(ctx)
        return {'success': False, 'error': f'任务创建失败: {e}'}

    return {'success': True, 'task_id': new_id,
            'operation': 'force_trigger', 'robot_id': robot_id}
```

> 说明：若未来"强制任务不锁定资源"也是合理场景（如试运行），可在 API 增加 `lock_resources` 布尔参数，默认 True。

## 4. 问题 3：任务面板"队列"不显示

### 4.1 现状核查

数据链路在 -3 已基本打通：

```text
TaskQueue.get_queue_items()          ✅ 新增（返回候选任务 dict 列表）
BusinessCollector.get_task_queue_data ✅ 已改为读取 queue_size + get_queue_items
/api/task/queue                      ✅ 路由存在
dashboard.js renderQueueTasks        ✅ 读取 data.queue 渲染
index.html 队列 Tab（tab-queue-count）✅ 存在
```

### 4.2 根因分析

1. **队列瞬时清空**：`smart_trigger` 扫描循环为"批量入队 → 立即 try_dequeue（最多 3 个）"。当存在空闲 AGV 且资源可锁时，候选任务**同一轮内即出队**，队列长期为空，面板自然"没有显示"；
2. **初始加载不拉队列**：`loadAllData()` 只加载活跃任务；队列数量 `tab-queue-count` 在切到"队列"Tab 前一直为 0；
3. **行字段缺失**：`TaskCandidate` 只有 `src_bay/dst_bay/cargo_type/bind_time/enqueue_time`，前端行却读取 `robot_id/created_at`（显示 `--`），且未展示 cargo_type/等待时长，信息不完整；
4. **无出队历史**：无法看到"刚被分发"的任务，运维观感为空。

### 4.3 解决思路

```text
① 初始加载即拉取队列并刷新 tab-queue-count；
② 队列行增强：显示 cargo_type、入队时间、等待时长；
③ 空态显示累计统计（入队/出队/老化/去重/溢出），证明队列在运转；
④ TaskQueue 增加"最近出队"环形缓冲（last_dequeued，默认 10 条），
   让面板可见"刚分发"的任务，避免"永远为空"的错觉；
⑤ WebSocket business_update 推送时同步刷新队列面板。
```

#### 4.4.1 `components/trigger/task_queue.py` —— 增加最近出队记录

```python
from collections import deque

class TaskQueue:
    def __init__(self, ...):
        ...
        # 最近出队记录（环形缓冲，供 Web 面板展示）
        self._last_dequeued = deque(maxlen=10)

    def try_dequeue(self):
        with self._lock:
            ...
                if ok:
                    self._queue.pop(i)
                    self._queued_src.discard(candidate.src_bay)
                    self._queued_dst.discard(candidate.dst_bay)
                    self._dequeue_count += 1
                    self._last_dequeued.appendleft({
                        'src_bay': candidate.src_bay,
                        'dst_bay': candidate.dst_bay,
                        'cargo_type': candidate.cargo_type,
                        'robot_id': robot_id,
                        'dequeued_at': time.time(),
                    })
                    ...
                    return (candidate, robot_id)

    def get_queue_items(self) -> List[dict]:
        """返回队列中候选任务的字典表示（仅用于监控）"""
        with self._lock:
            return [c.__dict__ for c in self._queue]

    def get_last_dequeued(self) -> List[dict]:
        """返回最近出队记录（最新在前，仅用于监控）"""
        with self._lock:
            return list(self._last_dequeued)
```

#### 4.4.2 `components/web/business_collector.py` —— 采集最近出队

```python
def get_task_queue_data(self) -> dict:
    try:
        trigger = self._get_plugin('smart_trigger')
        if not trigger:
            return {'queue': [], 'size': 0, 'stats': {}, 'last_dequeued': []}
        task_queue = getattr(trigger, '_task_queue', None)
        if task_queue:
            stats = task_queue.get_stats()
            items = task_queue.get_queue_items() if hasattr(task_queue, 'get_queue_items') else []
            last_dequeued = (task_queue.get_last_dequeued()
                             if hasattr(task_queue, 'get_last_dequeued') else [])
            return {
                'timestamp': time.time(),
                'size': stats.get('queue_size', 0),
                'queue': items,
                'stats': stats,
                'last_dequeued': last_dequeued,
            }
        return {'queue': [], 'size': 0, 'stats': {}, 'last_dequeued': []}
    except Exception as e:
        self.logger.error(f"采集任务队列失败: {e}")
        return {'queue': [], 'size': 0, 'stats': {}, 'last_dequeued': []}
```

## 5. 问题 4：任务告警接入告警显示

### 5.1 现状核查

```text
warnCallback → WorkflowEventBridge._on_rcs_warn_callback
  ├─ AlarmClassifier.classify()（L0~L3 分级）
  ├─ 注入工作流事件（warn_l1 / callback_exception）
  └─ 发布 rcs.alarm_logged（L0~L3 全量）       ← 无订阅方 ❌
  L3 额外发布 rcs.critical_alarm               ← 无订阅方 ❌

人工介入超时 → task_monitor 发布 rcs.alarm_escalated
  ├─ WorkflowEventBridge 订阅 → engine.log_alarm（alarm_logs 落库）✅
  └─ Web EventBridge 订阅 → AlarmManager.add_alarm(type=system)   ✅
     但发布方 NameError，事件实际从未发出（见问题 6）❌

AlarmManager：无 TASK 类型；/api/alarms 仅返回系统级告警
```

结论：**普通任务告警（warnCallback 全部分级）与 L3 紧急告警均未接入告警显示**；升级告警链路已接线但因 NameError 未生效。

### 5.2 解决思路

```text
① AlarmManager.AlarmType 增加 TASK = 'task'；
② WorkflowEventBridge._on_rcs_warn_callback 中直接 engine.log_alarm() 落库
   （任务告警进入 alarm_logs，可查可审计）；
③ Web EventBridge 订阅 rcs.alarm_logged + rcs.critical_alarm：
     - 按 alarm_level 映射 AlarmManager 级别
     - 稳定 message（warn_code 为核心）→ add_alarm 自带去重
     - 新增告警经 web_monitor 注册回调自动 WebSocket 推送，前端 alarms 页零改动；
④ 修复 task_monitor NameError 后，人工介入超时告警自然生效（问题 6）。
```

## 6. 问题 6：人工介入超时自动自洽（防悬空）

### 6.1 现状与根因

`plugins/task_monitor_plugin.py` 的 `_poll_manual_instances` 存在两个致命缺陷：

**缺陷 A —— NameError 阻断升级告警与后续处理**：

```python
snap = engine.get_instance_snapshot(task_code)
if not snap:
    continue
if snap['current_state'] != 'manual_intervention':
    continue
...
# 以下代码引用未定义的 instance：
entered_at = instance.context.get('manual_entered_at', 0)   # ← NameError
```

`instance` 变量从未定义，每轮 manual 轮询都会抛 `NameError: name 'instance' is not defined`，被外层 `except` 吞掉。后果：

- `rcs.alarm_escalated` 事件**从未发布** → Web 升级告警不出现、alarm_logs 无记录；
- 同一轮中后续 manual 任务全部跳过处理。

**缺陷 B —— 无强制闭环策略，任务悬空**：

```text
场景 1：RCS 持续返回 2（RUNNING）→ 只发"超时升级"（且被 A 阻断），任务永远挂起；
场景 2：RCS 返回空 data（任务已不存在/查询失败）→ for 循环不执行，无任何动作；
场景 3：任务无 rcs_task_no（下发阶段就进入 manual）→ 无法查询，永久悬空。
```

### 6.2 解决思路

```text
① 修复 NameError：使用 snap['context'] 读取 manual_entered_at / robot_id；
② 状态机自洽：
   - RCS 返回终态（9/7/8）→ 照常注入 auto_resolved / auto_failed（自动闭环）；
   - RCS 持续 RUNNING 且超过 manual_timeout + manual_force_close_after 宽限
     → 注入 auto_failed（reason=manual_force_close）强制闭环，避免悬空；
   - RCS 无数据/未知状态连续 N 轮（manual_unknown_max_rounds）
     → 注入 auto_failed（reason=manual_unknown）强制闭环；
   - 无 rcs_task_no 的任务无法查询 → 超过 manual_timeout + 宽限后直接强制闭环；
③ 查询键兼容：先按 taskCode 批量查询；未命中的任务按 rcs_task_no 单查回退
   （与文档 40 的 P0-3 方向一致，补齐 rcs_adapter 统一辅助方法）；
④ 所有强制闭环写入 exception_log（原因可审计），并发布 workflow.task_failed
   （P0-2 终态 on_exit 会释放资源 + 发布失败事件，资源不泄漏）。
```

#### 6.4.1 `plugins/rcs_adapter_plugin.py` —— 统一查询辅助（补齐 P0-3）

```python
def query_task_status_unified(self, task_id: str, rcs_task_no: str = '') -> dict:
    """统一查询任务状态：优先 taskCode（业务任务号），taskNo 兼容回退。"""
    keys = []
    if task_id:
        keys.append(task_id)
    if rcs_task_no and rcs_task_no not in keys:
        keys.append(rcs_task_no)
    if not keys:
        return {'code': '-1', 'msg': '缺少查询键', 'data': []}

    last_resp = {'code': '-1', 'msg': '查询失败', 'data': []}
    for key in keys:
        try:
            resp = self._client.query_task_status([key])
            last_resp = resp
            if resp.get('code') == '0' and resp.get('data'):
                self.logger.debug(f"query_task_status_unified: 键 {key} 命中")
                return resp
        except Exception as e:
            self.logger.warning(f"query_task_status_unified: 键 {key} 查询异常: {e}")
    return last_resp

def extract_task_status(self, resp: dict, task_id: str,
                        rcs_task_no: str = '') -> str:
    """从 RCS 响应中容错提取任务状态码，未命中返回 ''。"""
    data_list = resp.get('data') or []
    if not isinstance(data_list, list):
        return ''
    valid_keys = {task_id, rcs_task_no}
    for item in data_list:
        code = str(item.get('taskCode', ''))
        if code in valid_keys:
            return str(item.get('taskStatus', ''))
    if len(data_list) == 1:
        return str(data_list[0].get('taskStatus', ''))
    return ''
```

#### 6.4.2 `plugins/task_monitor_plugin.py` —— `_poll_manual_instances` 重写

```python
def _configure_impl(self) -> bool:

    # ===== 新增：强制闭环配置 =====

    # ============================
    # 每任务状态跟踪（防重复注入 / 统计未知轮数）
    self._manual_unknown_rounds: Dict[str, int] = {}
    self._manual_force_closed: set = set()
    ...

def _poll_manual_instances(self, rcs, manual_instances: dict, engine):
    """对 manual_intervention 实例查询 RCS 状态，实现自动自洽闭环。

    闭环策略（防悬空）：
      - RCS 终态 9/7/8 → auto_resolved / auto_failed
      - 超时 + 宽限后仍未终态 → auto_failed(manual_force_close)
      - RCS 无数据/未知连续 N 轮 → auto_failed(manual_unknown)
      - 无 rcs_task_no 且超时 + 宽限 → auto_failed(no_rcs_task_no)
    """
    import asyncio
    import json

    task_codes = list(manual_instances.keys())
    self.logger.debug(f"manual_intervention 轮询: {len(task_codes)} 个任务")
    if not task_codes:
        return

    try:
        # ① 批量按 taskCode 查询
        resp = rcs.query_task_status(task_codes)
        matched = {}
        if resp.get('code') == '0':
            for item in resp.get('data', []):
                code = str(item.get('taskCode', ''))
                if code in manual_instances:
                    matched[code] = str(item.get('taskStatus', ''))

        now = time.time()
        for task_code in task_codes:
            snap = engine.get_instance_snapshot(task_code)
            if not snap:
                continue
            if snap['current_state'] != 'manual_intervention':
                continue

            ctx = snap.get('context', {}) or {}
            rcs_task_no = ctx.get('rcs_task_no', '')
            entered_at = ctx.get('manual_entered_at', 0) or 0
            elapsed = now - entered_at if entered_at else 0
            robot_id = ctx.get('robot_id', '')

            # ② 状态获取：批量命中 → 直接使用；未命中 → taskNo 单查回退
            task_status = matched.get(task_code, '')
            if not task_status:
                if rcs_task_no:
                    try:
                        r2 = rcs.query_task_status_unified(
                            task_code, rcs_task_no)
                        task_status = rcs.extract_task_status(
                            r2, task_code, rcs_task_no)
                    except Exception as e:
                        self.logger.warning(
                            f"manual 回退查询失败 {task_code}: {e}")
                        task_status = ''
                else:
                    task_status = ''   # 无 rcs_task_no，无法查询

            # ③ 终态自动闭环
            if task_status == '9':
                self.logger.info(
                    f"自动闭环: {task_code} RCS 已完成(9), 注入 auto_resolved")
                self._inject_manual_event(
                    engine, task_code, 'auto_resolved',
                    {'task_status': task_status,
                     'source': 'task_monitor_auto_closure'})
                self._manual_unknown_rounds.pop(task_code, None)
                continue
            if task_status in ('7', '8'):
                self.logger.warning(
                    f"自动闭环: {task_code} RCS 已终结({task_status}), 注入 auto_failed")
                self._inject_manual_event(
                    engine, task_code, 'auto_failed',
                    {'task_status': task_status,
                     'source': 'task_monitor_auto_closure'})
                self._manual_unknown_rounds.pop(task_code, None)
                continue

            # ④ 未知/无数据轮数累计
            if not task_status:
                rounds = self._manual_unknown_rounds.get(task_code, 0) + 1
                self._manual_unknown_rounds[task_code] = rounds
            else:
                self._manual_unknown_rounds[task_code] = 0

            # ⑤ 超时升级告警（修复后的 NameError 版本）
            if entered_at and elapsed > self._manual_timeout:
                self.logger.warning(
                    f"告警升级: {task_code} 在 manual_intervention 已超 "
                    f"{int(elapsed)}s, 等待人工处置")
                self._publish_event('rcs.alarm_escalated', {
                    'task_id': task_code,
                    'duration': elapsed,
                    'agv_code': robot_id,
                })

            # ⑥ 强制闭环策略（防悬空）
            reason = None
            if entered_at and elapsed > (self._manual_timeout
                                         + self._manual_force_close_after):
                reason = 'manual_force_close'   # 超时+宽限仍未终态
            elif not rcs_task_no and entered_at and elapsed > (
                    self._manual_timeout + self._manual_force_close_after):
                reason = 'no_rcs_task_no'       # 无任务号且超期
            elif not task_status and rounds >= self._manual_unknown_max_rounds:
                reason = 'manual_unknown'       # RCS 无数据/未知连续超限

            if reason and task_code not in self._manual_force_closed:
                self._manual_force_closed.add(task_code)
                self.logger.warning(
                    f"强制闭环: {task_code} 原因={reason}, "
                    f"注入 auto_failed（防悬空）")
                try:
                    engine.log_exception(
                        task_code, 'manual_force_close',
                        json.dumps({
                            'reason': reason,
                            'rcs_status': task_status,
                            'elapsed': int(elapsed),
                            'rcs_task_no': rcs_task_no,
                        }))
                except Exception:
                    pass
                self._inject_manual_event(
                    engine, task_code, 'auto_failed',
                    {'task_status': task_status,
                     'reason': reason,
                     'source': 'task_monitor_force_close'})
                self._manual_unknown_rounds.pop(task_code, None)

    except Exception as e:
        self.logger.warning(f"manual_intervention 轮询异常: {e}")

def _inject_manual_event(self, engine, task_code: str, event: str,
                         data: dict):
    """注入事件到工作流实例（跨线程安全，失败仅记录）"""
    import asyncio
    try:
        future = asyncio.run_coroutine_threadsafe(
            engine.inject_event(task_code, event, data),
            self.node.asyncio_loop
        )
        future.add_done_callback(
            lambda f, tc=task_code, ev=event: (
                self.logger.debug(f"{ev} 注入完成: {tc}")
                if f.exception() is None
                else self.logger.error(f"{ev} 注入失败: {tc} {f.exception()}")
            )
        )
    except Exception as e:
        self.logger.error(f"注入事件异常 {task_code} → {event}: {e}")
```

> 说明：
> - `auto_failed → failed` 转移已存在于 `agv_transport_atomic.yaml` 的 `manual_intervention` 状态；P0-2 保证进入 failed 终态时执行 `release_resources + publish_failed_event`，资源释放与事件发布自动完成；
> - `engine.log_exception` 为现有公开接口（`WorkflowEngine` 已提供），无需改动；
> - `manual_force_closed` 集合防止同一任务重复注入；任务终结后实例从引擎移除，集合残留可接受（量小），也可在 `_on_task_ended` 中清理。

### 7.3 手工回归清单

1. 强制触发：选可用 AGV → 确认弹窗 → 任务创建并显示 AGV；选不可用 AGV → 后端拒绝；
2. 取消/重试：点击弹确认框，取消不请求，确认后任务状态正确变化；
3. 队列：AGV 全忙时触发自动任务 → 队列 Tab 显示候选（类型/等待时长）；出队后最近出队可见；
4. 告警：脚本推送 warnCallback（L0~L3）→ 告警页出现对应级别任务告警；重复推送去重；可确认/解决；
5. 人工介入：任务进入 manual → 修改 `manual_timeout: 30`（测试值）→ 30s 后出现升级告警；持续 RUNNING 超过宽限 → 自动闭环 failed，资源释放；
6. 重启恢复：存在 manual 实例时重启 → 恢复校准按 taskCode 查询，终态任务自动闭环。

### 7.4 风险与回滚

- 前端改动均为独立文件（index.html / dashboard.js / api.js 无需改），可单独回滚；
- 后端改动集中在 `task_monitor_plugin / rcs_adapter_plugin / task_controller / event_bridge / alarm_manager / task_queue / business_collector`，无 SQLite schema 变更；
- 强制闭环策略默认宽限较长（1800s），不会误杀仍在执行的任务；可通过 `manual_force_close_after` 调大或设为 0 关闭（0 表示不强制闭环，仅告警升级）；
- `manual_force_closed` 为内存态，重启后失效——配合 `_validate_and_recover` 的恢复校准，重启后仍能按 RCS 最新状态闭环。
