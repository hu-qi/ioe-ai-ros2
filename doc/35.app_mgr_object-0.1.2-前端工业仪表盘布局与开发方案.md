### 0.2 后端 API 就绪清单（19 个端点）

| 类 | 端点 | 用途 |
|---|---|---|
| 配置 | `GET/PUT /api/config/{bay,dest,schedule,pairs,params}` | 6 组读写 |
| 配置 | `GET /api/config/all` | 聚合查询 |
| 业务 | `GET /api/bay/status` | 起始仓位 24 格 |
| 业务 | `GET /api/dest/status` | 终点仓位 18 格 |
| 业务 | `GET /api/agv/status` | AGV 卡片 |

| 告警 | `GET /api/alarms{/stats}` + `POST /api/alarms/{acknowledge,resolve,clear}` | 告警 CRUD |

### 0.3 WebSocket 事件

| 事件类型 | 数据体 | 推送场景 |
|---|---|---|
| `business_update` | `{data: {...bay, dest, agv, task...}}` | 仓位/AGV/任务变化 |
| `config_updated` | `{section, timestamp}` | 配置热加载完成 |
| `slot_update` | `{data: {lanes_cache}}` | 巷道状态变化 |
| `alarm_update` | `{count, new_alarms: [...]}` | 新告警产生 |
| `status_update` | `{data: {...system...}}` | 系统状态实时推送 |
| `status_periodic` | `{data: {...system...}}` | 监控线程周期推送 |

## 1. 整体布局设计（三页面体系）

### 1.1 页面导航结构

```
┌─────────────────────────────────────────────────────┐
│  TOP BAR: 天眼运维监控系统   [首页] [状态监控] [运维控制]  │ ← base.html 导航
├─────────────────────────────────────────────────────┤
│                                                      │
│  ① 首页 (/)         → 业务仪表盘 + 重点告警             │
│  ② 状态监控 (/monitor) → 运维详情（系统/节点/通道/AGV）   │
│  ③ 运维控制 (/control) → 启停操作 + 告警管理             │
│                                                      │
└─────────────────────────────────────────────────────┘
```

### 1.2 色彩体系

```
工业高级质感配色方案：

--bg-primary:    #0f1923    深色背景（卡片底色）
--bg-secondary:  #1a2736    浅深背景（面板底色）
--bg-tertiary:   #243447    悬浮态背景
--text-primary:  #e8edf2    主文字
--text-secondary:#8fa3b8    次要文字
--accent-blue:   #3498db    数据高亮蓝
--accent-green:  #27ae60    成功/正常绿
--accent-orange: #f39c12    警告橙
--accent-red:    #e74c3c    异常/告警红
--border:        #2d3f51    边框线
--card-shadow:   0 2px 8px rgba(0,0,0,0.3)
```

### 1.3 通用设计模式

- **卡片**：`border-radius: 8px`，`border: 1px solid var(--border)`，微阴影
- **KPI 数显**：大字 28px/700weight + 小标签 11px/uppercase
- **状态灯**：12px 圆点 + box-shadow 发光效果（绿=正常/橙=警告/红=异常/灰=离线）
- **进度条**：8px 高，圆角，渐变填充
- **表格**：斑马纹 + hover 高亮，13px 紧凑字体

### 2.2 各区域详细设计

#### ① 起始仓位热力图（左上，占 50% 宽）

数据源：`GET /api/bay/status` → `{bays: [...], total: 24, bound_count, in_task_count}`

布局：4 列 × 6 行 Grid

```html
<div class="bay-grid">
  <!-- 每格根据 cargo_type 着色，bind_status 决定边框样式 -->
  <div class="bay-cell bay-type-1 bay-bound">A1001</div>
  <div class="bay-cell bay-type-2 bay-idle">A1002</div>
  ...
</div>
```

视觉规则：
- cargo_type 1~6 → 6 种颜色（蓝/绿/橙/紫/青/粉）
- bind_status=1（已绑定）→ 实心填充 + 右上角 ● 标记
- bind_status=0（空闲）→ 半透明 + 虚线边框
- in_task=True → 底部进度条动画

交互：
- hover → tooltip 显示 bay_id / cargo_type / bind_duration / in_task
- click → 弹出模态框，下拉选择 cargo_type，保存（PUT /api/config/bay）

#### ② 终点仓位分区网格（左下，占 50% 宽）

数据源：`GET /api/dest/status` → `{bays: [...], by_floor: {2: {...}, 3: {...}, 4: {...}}}`

布局：按楼层分组，每层 6 格横排

```html
<div class="dest-grid">
  <div class="floor-section">
    <div class="floor-label">2F</div>
    <div class="dest-row">T2001 T2002 ... T2006</div>
  </div>
  <div class="floor-section">
    <div class="floor-label">3F</div>
    <div class="dest-row">T3001 T3002 ... T3006</div>
  </div>
  <div class="floor-section">
    <div class="floor-label">4F</div>
    <div class="dest-row">T4001 T4002 ... T4006</div>
  </div>
</div>
```

视觉规则：
- is_empty=True → 绿色（可用）
- is_empty=False → 灰色（占用）
- cargo_type 用数字角标显示

#### ③ AGV 状态卡片（左侧底部）

数据源：`GET /api/agv/status` → `{robots: [...], available_count, total}`

布局：横向卡片，每个 AGV 一个卡片


## 4. 运维控制页 (/control) — 启停操作 + 告警管理

### 4.1 新增告警管理板块

在现有运维控制页右侧增加告警管理面板：

```
┌────────────────────────────┬─────────────────────────────┐
│  ① 节点/服务启停（已有）     │  ③ 告警管理（新增）           │

│                             │    ┌─────────────────────┐  │
│  ② 快速操作（已有）          │    │ 🔴 节点离线         │  │
│    [系统检查] [清理缓存]     │    │ [确认] [解决]       │  │
│    [强制触发任务]            │    │ 🟡 通道异常         │  │
│                             │    │ [确认] [解决]       │  │
│                             │    └─────────────────────┘  │
│                             │    [一键清除已解决告警]       │
└────────────────────────────┴─────────────────────────────┘
```

告警交互：
- 点击 [确认] → POST `/api/alarms/acknowledge` → 状态变为已确认
- 点击 [解决] → POST `/api/alarms/resolve` → 状态变为已解决
- [一键清除] → POST `/api/alarms/clear` → 清除已解决告警

### 7.2 `static/js/api.js` — 统一 API 封装

```javascript
// 所有 API 调用统一封装，处理错误降级
const API = {
    base: '',
    
    async _fetch(url, options = {}) {
        try {
            const resp = await fetch(this.base + url, {
                headers: { 'Content-Type': 'application/json' },
                ...options
            });
            if (!resp.ok) {
                const err = await resp.json().catch(() => ({}));
                throw new Error(err.error || `HTTP ${resp.status}`);
            }
            return await resp.json();
        } catch (e) {
            console.warn(`API ${url} failed:`, e.message);
            return { success: false, error: e.message };
        }
    },

    // 业务数据
    getBusinessSummary()     { return this._fetch('/api/business/summary'); },
    getBayStatus()           { return this._fetch('/api/bay/status'); },
    getDestStatus()          { return this._fetch('/api/dest/status'); },
    getAgvStatus()           { return this._fetch('/api/agv/status'); },
    getTaskQueue()           { return this._fetch('/api/task/queue'); },
    getTaskInstances()       { return this._fetch('/api/task/instances'); },
    getTaskHistory(limit=5)  { return this._fetch(`/api/task/history?limit=${limit}`); },

    // 配置
    getConfigBay()           { return this._fetch('/api/config/bay'); },
    setConfigBay(mappings)   { return this._fetch('/api/config/bay',
        { method: 'PUT', body: JSON.stringify({ mappings }) }); },

    // 任务操作
    taskControl(op, params)  { return this._fetch('/api/task/control',
        { method: 'POST', body: JSON.stringify({ operation: op, ...params }) }); },

    // 告警
    getAlarms(limit=5, ack=false) {
        return this._fetch(`/api/alarms?limit=${limit}&acknowledged=${ack}`);
    },
    acknowledgeAlarm(id)     { return this._fetch('/api/alarms/acknowledge',
        { method: 'POST', body: JSON.stringify({ alarm_id: id }) }); },
    resolveAlarm(id)         { return this._fetch('/api/alarms/resolve',
        { method: 'POST', body: JSON.stringify({ alarm_id: id }) }); },
};
```

### 7.3 `static/js/websocket.js` — WebSocket 统一管理

```javascript
const WS = {
    socket: null,
    handlers: {},
    reconnectDelay: 3000,
    maxReconnectDelay: 30000,

    connect() {
        const proto = location.protocol === 'https:' ? 'wss:' : 'ws:';
        const url = `${proto}//${location.host}/ws`;
        this.socket = new WebSocket(url);
        this.socket.onopen  = () => { this.reconnectDelay = 3000; this._emit('connect'); };
        this.socket.onclose = () => { setTimeout(() => this.connect(), this.reconnectDelay);
            this.reconnectDelay = Math.min(this.reconnectDelay * 2, this.maxReconnectDelay); };
        this.socket.onmessage = (e) => {
            try { const msg = JSON.parse(e.data); this._emit(msg.type, msg); }
            catch (err) { console.warn('WS parse error:', err); }
        };
    },

    on(type, handler) {
        if (!this.handlers[type]) this.handlers[type] = [];
        this.handlers[type].push(handler);
    },

    _emit(type, data) {
        (this.handlers[type] || []).forEach(h => { try { h(data); } catch(e) { console.warn(e); } });
    }
};
```
