## 1. 现有工程深度分析

### 1.1 插件生命周期框架

```
BasePlugin (抽象基类)
├── __init__(node, config)          # 接收 ROS2 Node + 配置字典
├── configure(config=None) → bool    # 调用 _configure_impl()
├── activate() → bool               # 调用 _activate_impl()
├── deactivate() → bool             # 调用 _deactivate_impl()
├── cleanup() → bool                # 调用 _cleanup_impl()
├── get_status() → dict             # 状态查询
├── _publish_event(type, data)      # 发布到 EventBus
└── node.event_bus                  # 通过 node 访问事件总线

PluginManager
├── discover(package_path)          # 扫描 app_mgr_object.plugins 下所有 BasePlugin 子类
├── load_plugin(name, config)       # 实例化插件
├── get_plugin(name) → instance     # 获取插件实例
└── configure_plugin(name, config)  # 运行时重配置
```

**关键约定**:
- 每个插件类必须定义 `PLUGIN_NAME` 和 `PLUGIN_VERSION` 类属性
- 插件通过 `self.node.xxx_plugin` 模式互相引用（如 `self.node.network_plugin`）
- 通过 `self.node.plugin_manager.get_plugin('xxx')` 也可获取其他插件实例
- 插件状态变更通过 `EventBus` 发布事件通知其他插件

### 1.2 可复用组件清单

| 组件 | 路径 | 功能 | 任务管理模块如何复用 |
|:---|:---|:---|:---|
| **AreaStatusFilter** | `components/device_status/area_filter.py` | 单区域状态滤波（滑动窗口 + 超时清除），判断 `has_object` 是否稳定 | **直接复用**于起始仓位 AI 检测结果的防抖滤波，替换参数：`stable_threshold=3`, `timeout=2.0` |
| **SignalMonitor** | `components/device_status/signal_monitor.py` | 信号状态监控（滤波 + 超时 + 连续错误 + 自动恢复） | **直接复用**于监控叉车在线状态、RCS 连接状态等信号类数据 |
| **DeviceStatusManager** | `components/device_status/device_manager.py` | 多设备多通道状态管理器，内含 `AreaStatusFilter` 管理 | **模式参考**：其 `device_id→channel_id→area_name` 三层嵌套结构可供仓位管理参考（堆场→仓位→货物类型） |
| **CallbackReceiver** | `components/callback/receiver.py` | 基于 FastAPI + uvicorn 的通用 HTTP 回调服务器，支持动态注册路由 | **直接复用**于启动 RCS 回调监听服务（`/agvCallback`, `/warnCallback`, `/bindNotify`） |
| **CallbackHandlerPlugin** | `plugins/callback_handler_plugin.py` | 封装 CallbackReceiver，暴露 `register_route()` / `register_post()` | **直接复用**：新插件通过 `self.node.callback_handler.register_post()` 注册 RCS 回调路由 |
| **NetworkPlugin** | `plugins/network_plugin.py` | HTTP 会话管理（接口绑定、IP 获取） | **直接复用**：`RCSAdapter` 通过 `self.node.network_plugin.request()` 发送 RCS HTTP 请求 |
| **RequestQueueManager** | `components/reporting/request_queue.py` | 异步 HTTP 请求队列（去重、版本控制、重试） | **模式参考**：RCS 接口调用如需异步队列模式可参照其设计 |
| **DataManager** | `components/reporting/data_manager.py` | 数据载荷构建与格式验证 | **模式参考**：构造 RCS 接口请求体时可参照其载荷验证模式 |
| **ParamManager** | `base/param_manager.py` | 参数声明、读取、动态更新、Web 配置深度合并 | **直接复用**：新增插件通过 `self.node.param_manager.get_param()` 读取配置 |
| **EventBus** | `plugins/event_bus.py` | 插件间发布/订阅事件 | **直接复用**：全部插件间通信 |

### 1.3 params.yaml 参数管理机制

现有 `params.yaml` 结构（截取关键部分）：

```yaml
app_mgr_object:
  ros__parameters:
    # 通用参数（ParamManager._declare_common_parameters）
    log_level: "info"
    plugin_load_order: ["network", "callback_handler", "object_status", "web_monitor"]

    # 插件配置块（YAML 多行字符串 |，由 ParamManager 自动解析为 dict）
    plugin_configs: |
      network:
        auto_start: true
        ...
      object_status:
        auto_start: true
        device_list: ["dev01"]
        filter:
          stable_count_threshold: 5      # ← 滤波阈值，可被任务管理插件复用同款理念
          filter_timeout: 2.0            # ← 滤波超时
        ...
```

**扩展策略**:
- 在 `plugin_configs` 中新增 6 个新插件的配置块
- 在 `plugin_load_order` 中添加新插件名
- 利用 `ParamManager.get_param()` 在插件的 `_configure_impl()` 中读取各自配置
- 通用业务参数（如 RCS 地址、仓位定义）通过各自插件配置块管理，不污染全局参数空间

### 1.4 插件间通信模式

现有工程中插件间通信有**三种模式**：

| 模式 | 适用场景 | 示例 |
|:---|:---|:---|
| **直接引用** `self.node.xxx_plugin` | 紧耦合调用（如同一层内） | `NetworkPlugin` 挂载到 `self.node.network_plugin` |
| **EventBus 发布/订阅** | 松耦合通知（跨层） | `bay.bound` → `smart_trigger` 消费 |
| **ROS2 Service** | 外部系统调用（Web→节点） | `/task_control` Service |

本方案**优先使用 EventBus** 进行跨层通信，关键数据同步（如仓位绑定完成）通过事件驱动，避免插件间循环依赖。

组件层位于 `app_mgr_object/components/` 下，是插件的"工具箱"。插件通过调用组件完成具体业务逻辑，保持插件代码简洁。

### 3.1 滤波防抖组件（复用 `AreaStatusFilter`）

**结论：直接复用，不做修改。**

现有 `AreaStatusFilter` 已完美满足防抖需求：

```python
# AreaStatusFilter 核心逻辑（现有代码）
class AreaStatusFilter:
    def update(self, new_status: bool) -> dict:
        # 1. 超时则清空队列
        # 2. 追加新状态到 deque(maxlen=stable_threshold)
        # 3. 当队列满且 all_true → current_stable_state = True（稳定有货）
        # 4. 当队列满且 all_false → current_stable_state = False（稳定无货）
        # 5. 返回 {'changed': bool, 'current_state': bool}
```

**在 `bay_status_fusion_plugin` 中的使用方式**:

```python
# 为每个仓位创建一个 AreaStatusFilter 实例
self._bay_filters = {}  # bay_id → AreaStatusFilter

def _handle_ai_message(self, bay_id, has_cargo, cargo_type):
    if bay_id not in self._bay_filters:
        self._bay_filters[bay_id] = AreaStatusFilter(
            stable_threshold=self._debounce_count,  # 默认 3
            timeout=self._debounce_interval,         # 默认 2.0
            logger=self.logger
        )
    result = self._bay_filters[bay_id].update(has_cargo)
    if result['changed'] and result['current_state'] == True:
        # 稳定有货 → 触发绑定
        self._trigger_bind(bay_id, cargo_type)
```

**`rcs_http_client.py`** — RCS HTTP 客户端（核心）

```python
class RCSHttpClient:
    """RCS-2000 V3.3 HTTP 接口客户端
    依赖 node.network_plugin 提供的 HTTP 会话能力
    """

    def __init__(self, network_plugin, base_url: str, timeout: float = 10.0,
                 max_retries: int = 2, logger=None):
        self._network = network_plugin
        self._base_url = base_url.rstrip('/')
        self._timeout = timeout
        self._max_retries = max_retries
        self._logger = logger

    # ── 任务接口 ──
    def gen_agv_scheduling_task(self, payload: dict) -> dict:
        """2.1.1 生产任务单"""
        return self._post('/genAgvSchedulingTask', payload)

    def cancel_task(self, task_code: str, force_cancel: str = "1") -> dict:
        """2.1.3 取消任务"""
        return self._post('/cancelTask', {
            'taskCode': task_code,
            'forceCancel': force_cancel
        })

    def continue_task(self, task_code: str) -> dict:
        """2.1.2 继续执行任务"""
        return self._post('/continueTask', {'taskCode': task_code})

    # ── 查询接口 ──
    def query_agv_status(self, robot_ids: list) -> dict:
        """3.1.10 查询 AGV 状态"""
        return self._post('/queryAgvStatus', {'robotIDs': robot_ids})

    def query_task_status(self, task_codes: list) -> dict:
        """3.1.9 查询任务状态"""
        return self._post('/queryTaskStatus', {'taskCodes': task_codes})

    def query_pod_berth_and_mat(self, stg_bin_codes: list) -> dict:
        """3.1.6 查询仓位绑定关系"""
        return self._post('/queryPodBerthAndMat', {'stgBinCodes': stg_bin_codes})

    # ── 绑定接口 ──
    def bind_ctnr_and_bin(self, ctnr_code: str, ctnr_typ: str,
                          stg_bin_code: str, ind_bind: str = "1") -> dict:
        """3.1.8 容器与仓位绑定"""
        return self._post('/bindCtnrAndBin', {
            'ctnrCode': ctnr_code,
            'ctnrTyp': ctnr_typ,
            'stgBinCode': stg_bin_code,
            'indBind': ind_bind
        })

    # ── 内部方法 ──
    def _post(self, path: str, data: dict) -> dict:
        """发送 POST 请求，含重试逻辑"""
        url = f"{self._base_url}{path}"
        last_error = None
        for attempt in range(self._max_retries + 1):
            try:
                resp = self._network.request('POST', url, data=data,
                                             timeout=self._timeout)
                return resp.json()
            except Exception as e:
                last_error = e
                if attempt < self._max_retries:
                    time.sleep(0.5 * (attempt + 1))
        raise RCSClientError(f"RCS 请求失败 [{path}]: {last_error}")
```

```python
class WorkflowInstance:
    """单个工作流实例，实现 YAML 状态机的执行"""

    def __init__(self, instance_id: str, definition: WorkflowDefinition,
                 context: dict, action_registry: ActionRegistry,
                 persistence: WorkflowPersistence):
        self.id = instance_id
        self.definition = definition
        self.context = context
        self.current_state = definition.initial_state
        self._action_registry = action_registry
        self._persistence = persistence
        self._event_queue = asyncio.Queue()  # 外部事件注入通道
        self._retry_count = 0

    async def run(self):
        """执行工作流直到到达终态"""
        while not self._is_final_state():
            state_def = self._get_current_state_def()
            # 1. 执行 on_enter actions
            for action in state_def.get('on_enter', []):
                await self._execute_action(action)
            # 2. 执行主 action（带超时控制）
            event = await self._execute_with_timeout(state_def)
            # 3. 根据事件转移状态
            self._transition(event)
            # 4. 持久化当前状态
            await self._persistence.save(self)
        # 终态处理
        await self._execute_on_exit()
```

```python
class TriggerEngine:
    """触发器引擎 — 扫描多源缓存，匹配条件，生成任务上下文"""

    def __init__(self, bay_cache, dest_cache, robot_cache, config_cache):
        self._bay_cache = bay_cache
        self._dest_cache = dest_cache
        self._robot_cache = robot_cache
        self._config_cache = config_cache
        self._locker = ResourceLocker()
        self._schedule_checker = ScheduleChecker()

    def scan(self, cargo_type: int) -> Optional[TaskContext]:
        """扫描指定货物类型，返回可执行的任务上下文或 None"""
        if not self._schedule_checker.is_in_working_window():
            return None

        with self._locker.acquire():
            src = self._bay_cache.get_bound_bay(cargo_type)
            if not src: return None

            dst = self._dest_cache.get_empty_bay(cargo_type)
            if not dst: return None

            robot = self._robot_cache.get_idle_robot()
            if not robot: return None

            # 原子锁定
            self._locker.lock(src, dst, robot)

            return TaskContext(
                src_bay=src.bay_id,
                dst_bay=dst.bay_id,
                robot_id=robot.robot_id,
                cargo_type=cargo_type
            )
```

### 4.1 `rcs_adapter_plugin` — RCS 接口适配器

| 属性 | 值 |
|:---|:---|

| **职责** | 订阅 AI `/bay_status` 话题 → 防抖滤波 → 触发 RCS 绑定 → 维护起始仓位缓存 |

**防抖绑定流程**:

```
每次收到 AI 消息 (bay_id, has_cargo, cargo_type):
│
├─ 获取/创建该仓位的 AreaStatusFilter 实例
│  filter = AreaStatusFilter(stable_threshold=3, timeout=2.0)
│
├─ result = filter.update(has_cargo)
│
├─ if result['changed'] and result['current_state'] == True:
│  │  → 稳定有货确认
│  │  → 调用 rcs_adapter.bind_ctnr_and_bin(bay_id, cargo_type)
│  │  → 成功后更新 BayCache.set_bound(bay_id)
│  │  → 发布 event_bus.publish('bay.bound', {...})
│  │
├─ if result['changed'] and result['current_state'] == False:
│  │  → 稳定无货确认（但绑定不主动解绑）
│  │  → 更新 BayCache
│  │
└─ 同时更新 BayCache.update_ai_result(bay_id, has_cargo, cargo_type)
```

| **使用的组件** | `components/task_cache/robot_cache.py`（新建）<br>`components/task_cache/dest_bay_cache.py`（新建） |
| **定时器** | 叉车状态: 3s / 终点仓位: 60s / 任务状态: 5s |

**轮询逻辑**:

```python
def _activate_impl(self) -> bool:
    # 使用 ROS2 Timer 而非 asyncio.sleep（与现有工程模式一致）
    self._robot_timer = self.node.create_timer(3.0, self._poll_robot_status)
    self._dest_timer = self.node.create_timer(60.0, self._poll_dest_bays)
    return True

def _poll_dest_bays(self):
    """补偿查询终点仓位状态"""
    all_dest_codes = self._dest_cache.get_all_bay_ids()
    try:
        resp = self.node.rcs_adapter.query_pod_berth_and_mat(all_dest_codes)
        for item in resp.get('data', []):
            is_empty = (item.get('ctnrCode') is None or item.get('ctnrCode') == '')
            self._dest_cache.update(item['stgBinCode'], is_empty, source='polling')
    except Exception as e:
        self.logger.warning(f"终点仓位轮询失败: {e}")
```

| **使用的组件** | `components/trigger/trigger_engine.py`（新建）<br>`components/trigger/schedule_checker.py`（新建）<br>`components/trigger/resource_locker.py`（新建） |
| **发布事件** | `trigger.task_created` |

**扫描循环**:

```python
class SmartTriggerPlugin(BasePlugin):
    PLUGIN_NAME = "smart_trigger"

    def _activate_impl(self) -> bool:
        self._trigger_engine = TriggerEngine(
            bay_cache=self.node.bay_status_fusion.cache,
            dest_cache=self.node.status_poller.dest_cache,
            robot_cache=self.node.status_poller.robot_cache,
            config_cache=self._config_cache
        )
        # 启动 asyncio 定时扫描
        self._task = asyncio.ensure_future(self._scan_loop())
        # 订阅事件以加速触发
        self.event_bus.subscribe('bay.bound', self._on_bay_bound)
        return True

    async def _scan_loop(self):
        while self._running:
            if self._trigger_engine.schedule_checker.is_in_working_window():
                for cargo_type in range(1, 7):
                    ctx = self._trigger_engine.scan(cargo_type)
                    if ctx:
                        self.event_bus.publish('trigger.task_created', ctx.to_dict())
            await asyncio.sleep(self._scan_interval)  # 默认 2s

    def _on_bay_bound(self, data):
        """仓位刚绑定时立即触发一次扫描"""
        asyncio.ensure_future(self._scan_once())
```

## 11. 风险与兜底

| # | 风险 | 缓解措施 |
|:---|:---|:---|
| 1 | **RCS 回调丢失** | 每步骤设 timeout → `compensating_query` 主动查询兜底 |
| 2 | **双车抢单** | `ResourceLocker` 原子锁 + 内存标记 |
| 3 | **断电恢复** | SQLite WAL 持久化 + 启动时 `recover_all()` → `queryTaskStatus` 向 RCS 核实 |
| 4 | **AI 抖动误触发** | `AreaStatusFilter`（已有）防抖 N 次 + 超时清除 |
| 5 | **SQLite 并发冲突** | WAL 模式 + `persistence.py` 统一入口加锁 |
| 6 | **RCS 不可达** | 重试 2 次后 → `manual_intervention` + Web 告警 |
| 7 | **软取消安全** | `cancelTask` 使用 `forceCancel="1"`，叉车背货回库 |
| 8 | **绑定幂等性** | 调用前检查本地 `bind_status`，已绑定则跳过 |
