## 0. 总览与通用约定

### 0.1 服务架构

| 模块 | 文件 | 挂载前缀 | 说明 |
|---|---|---|---|
| Web 底座 | `web_server.py` | `/` | 运维监控、控制、标定、配置、告警、任务等 |
| 报告接收插件 | `report_recv_plugin.py` | `/` | 端侧报告/事件/证据接收与检索（doc/dev01） |
| 教学分析插件 | `report_analysis_plugin.py` | `/` | 步骤统计、学员累计、班级汇总、诊断、教学闭环 |

| 教学看板插件 | `teaching_dashboard_plugin.py` | `/` | 今日概览、高频错误点、重点关注、实时进度 |
| 评分插件 | `scoring_plugin.py` | — | 无 HTTP 路由；评分引擎由 `POST /api/v1/config/reload` 热重载 |

### 0.2 响应包裹格式（/api/v1/* 教学域接口统一）

```json
{"code": 0, "message": "ok", "data": {...}}
```

- `code=0` 成功；非 0 失败。HTTP 状态码：2xx 业务成功；400 参数/JSON 解析失败；422 缺必填字段；404 资源不存在；500 服务端错误。
- 失败时同样返回包裹体（`data` 为空对象），便于统一解析。
- `/api/*`（运维底座旧接口）为历史格式：多数直接返回业务 JSON，错误抛 HTTPException（`{"detail": "..."}`）。

### 0.3 时间与幂等

- `ts_upload_ms`：墙钟 epoch ms；`events[].ts`、`round.*ms`、证据 `ts`：引擎单调 ms，**禁止与墙钟混算**。
- 幂等键：增量 `device_id + round_start_ms + events[].ts`；整包 `device_id + round.start_ms`；证据 `device_id + round_start_ms + sub + ts`。重复到达按幂等键去重，不拒绝。

### 0.4 页面路由（HTML，非 API）

| 路径 | 说明 |
|---|---|
| `/` `/index` | 首页（天眼运维监控） |
| `/monitor` `/control` | 状态监控 / 运维控制页 |
| `/calibration` | 标定页（打开触发 OPS 标定配置同步，防抖 30s） |
| `/diagnosis` | 教学诊断中心页（P2/P4） |
| `/reports` | 报告管理页（列表筛选 + 详情） |

| `/test` `/report_debug` | 测试页 / 报告接收联调页 |

## 1. 端侧上报域（报告接收，doc/dev01 v3）

端侧一体机（touch_ui_plugin）主动外发，平台为接收方；`realtime_gate=auto` 下**无需订阅**即可上报。本域接口由 `report_recv_plugin.py` 提供。

### 1.1 POST /api/v1/reports — 整包报告接收

- 触发：轮次结束（finish_reason = completed / manual / timeout / reset）
- Content-Type：`application/json`；幂等键：`device_id + round.start_ms`
- 请求体（核心字段，`round` 为引擎 JSON 原样）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| schema_version | str | 是 | 目前 `"1.0"` |
| device_id | str | 是 | 设备键，默认 `dev01` |
| edge_node | str | 否 | 上报节点名，如 `touch_ui_plugin` |
| ts_upload_ms | int64 | 是 | 墙钟上传时间（epoch ms） |
| student | obj | 否 | `{id, name, cls, source}` |
| round | obj | 是 | `{process_name, finish_reason, start_ms, end_ms, duration_ms, process_elapsed_ms, events[], steps[], substeps[], unexecuted[], evidence[], substep_counts[], interval_ms[]}` |

- 响应 data：`{report_id, device_id, finish_reason, evidence}`（report_id 形如 `R<ts>_dev01`）
- 处理：解析入库（reports / report_steps / report_substeps / report_events 四表），原始 JSON 落盘

### 1.2 POST /api/v1/events — 实时增量事件

- 触发：auto 模式下总闸开 + 地址就绪即报（每 `realtime_upload_sec`=2s 攒批）；轮次进行中步骤变化时
- 幂等键：`device_id + round_start_ms + events[].ts`；失败当批丢弃，下周期全量 diff 自愈
- 请求体（event_delta，schema 1.1）：

| 字段 | 类型 | 说明 |
|---|---|---|
| schema_version | str | `"1.1"` |
| type | str | `"event_delta"` |
| device_id / edge_node | str | 设备与节点 |
| ts_upload_ms | int64 | 墙钟上传时间 |
| round_start_ms | int64 | 轮次起点（引擎单调 ms） |
| process_elapsed_ms | int64 | 已进行时长 |
| student | obj | `{id, name, cls, source}` |
| events | array | `{ts, kind, step, sub}`；ts 为相对 round_start_ms 偏移；kind：0 START / 1 COMPLETE / 2 INTERRUPT / 3 TIMEOUT / 4 FINISH_EOF / 5 FINISH_EIO；step/sub 全局序号 1..M |
| progress | obj | `{done, total, current, current_sub_index}` |

- 响应 data：`{device_id, delta_events}`（入库事件条数）
- 平台侧建议：按 `device_id + round_start_ms` 追加事件流；墙钟参考 `approx_start_wall = ts_upload_ms − process_elapsed_ms`

### 1.3 POST /api/v1/evidence — 证据图上传（multipart/form-data）

| 表单字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| file | 附件 | 是 | BMP 抓拍图（rtsp BMP 直写） |
| sub | int | 是 | 子步骤序号 1..M |
| ts | int64 | 是 | 引擎单调 ms |
| device_id | str | 是 | 设备键 |
| round_start_ms | int64 | 否 | 轮次起点；缺省回退为 ts |

- 两通道：实时证据（抓拍约 1s 后）+ 整包兜底（轮次结束补发未送出的）；端侧按 file 路径去重
- 处理：BMP 落盘 `evidence/<device_id>/sub%02d_t<ts>.bmp` 并转 jpg（P3），元数据入库（幂等去重 `is_new`）
- 响应 data：`{saved, path, device_id, sub, ts, round_start_ms}`

### 1.4 GET /api/v1/reports — 报告列表检索

| 查询参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| student_id | str | 空 | 按学员过滤 |
| device_id | str | 空 | 按设备过滤 |
| finish_reason | str | 空 | completed / manual / timeout / reset |
| start_ms / end_ms | int64 | 0 | 时间范围（0 = 不限） |
| step_index | int | -1 | ≥0 时按步骤下钻过滤 |
| page | int | 1 | 页码 |
| page_size | int | 20 | 每页条数（上限 100） |

- 响应 data：分页报告元信息列表

### 1.5 GET /api/v1/reports/{report_id} — 报告详情

- 响应 data：报告详情，聚合 reports + report_steps + report_substeps + report_events
- 404：报告不存在

### 1.6 证据检索

| 接口 | 参数 | 说明 |
|---|---|---|
| GET /api/v1/evidence | device_id（必填）、round_start_ms、sub、limit（默认 200） | 证据元数据列表；`jpg_path` 非空表示已转换可直接展示 |
| GET /api/v1/evidence/{evidence_id}/image | — | 返回证据图片二进制（优先 jpg，未转换回源 BMP） |

### 1.7 订阅接口（保留能力，v3 后端侧不再依赖）

| 方法 | 路径 | 请求体 | 响应 data | 说明 |
|---|---|---|---|---|
| POST | /api/v1/subscriptions | `{device_id, note?}` | `{device_id, active, subscribed_at_ms}` | 订阅/更新（重复 POST 保持 active） |
| GET | /api/v1/subscriptions/{device_id} | — | `{device_id, active, subscribed_at_ms?}` | 查询订阅状态（端侧轮询用） |
| DELETE | /api/v1/subscriptions/{device_id} | — | `{device_id, active:false, was_active}` | 退订（active 置 0） |
| GET | /api/v1/subscriptions | — | `{devices:{...}}` | 订阅设备列表 |

> 仅用于统计展示 / `realtime_gate=subscribed` 控流；不影响 auto 模式上报。

## 2. 教学分析域（report_analysis_plugin.py）

全部为 `GET`（除教学动作创建），统一包裹格式；通用过滤参数：`date_start / date_end`（int64 毫秒，0=不限）。

### 2.1 GET /api/v1/analysis/step_duration — 步骤时长统计

| 参数 | 说明 |
|---|---|
| cls | 班级 |
| device_id | 设备 |
| student_id | 学员 |
| process_name | 工序名 |
| date_start / date_end | 时间范围 |

- 响应 data：各步骤耗时统计（均值/超时分布，供报告页图表）

### 2.2 GET /api/v1/analysis/student_cumulative — 学员累计分析

| 参数 | 说明 |
|---|---|
| student_id | **必填**，缺失返回 422 |
| process_name / date_start / date_end | 可选过滤 |

### 2.3 GET /api/v1/analysis/class_summary — 班级汇总

| 参数 | 说明 |
|---|---|
| cls | **必填**，缺失返回 422 |
| process_name / date_start / date_end | 可选过滤 |

### 2.4 GET /api/v1/analysis/diagnosis — 规则驱动诊断（实时计算）

| 参数 | 默认 | 说明 |
|---|---|---|
| scope | `class` | `class` 班级维度 / `student` 学员维度（配 student_id） |
| cls / student_id / process_name | 空 | 过滤条件 |
| date_start / date_end | 0 | 时间范围 |

- 响应 data：诊断结论数组（规则来自 `config/diagnosis_rules.yaml`，由 diagnosis_engine 实时计算，P2/P4）

### 2.5 GET /api/v1/analysis/diagnoses — 诊断结果列表（入库查询）

| 参数 | 说明 |
|---|---|
| diagnosis_type | 按诊断类型过滤 |
| target_id | 按目标（班级/学员）过滤 |
| limit | 条数（默认 50，上限 200） |

### 2.6 教学闭环 /api/v1/teaching_actions

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /api/v1/teaching_actions | 创建教学调整事件。必填：`description`、`class_name`（缺返回 422）；可选：`action_date`(ms)、`target_substep`、`process_name`。响应 data：`{action_id}` |
| GET | /api/v1/teaching_actions | 列表（时间倒序）。参数：`class_name`、`process_name`、`limit`（默认 50，上限 200） |
| GET | /api/v1/teaching_actions/{action_id}/verify | 教学调整效果验证：对比调整前后的诊断指标（P5 闭环） |

## 3. 学员管理域（student_mgr_plugin.py）

### 3.1 GET /api/v1/students — 学员列表

| 参数 | 默认 | 说明 |
|---|---|---|
| keyword | 空 | 姓名/学号模糊匹配 |
| cls | 空 | 班级过滤 |
| status | `active` | 状态过滤 |
| page | 1 | 页码 |
| page_size | 0 | 0 = 不分页返回全部 |

- 响应 data：`{total, page, page_size, students:[{id, name, cls, status, source, ...}]}`（source: manual/platform）

### 3.2 GET /api/v1/students/export — 导出

- 查询参数同列表（keyword/cls/status）；返回 CSV 文件下载

### 3.3 GET /api/v1/students/{student_id} — 学员详情（404 不存在）

### 3.4 POST /api/v1/students — 新增学员

- 请求体：`{id, name, cls, ...}`；`id`、`name` 必填（空/JSON 解析失败返回 400/422）；`id` 重复返回冲突错误
- 响应 data：`{id, name, cls, source:"manual", ...}`

### 3.5 PUT /api/v1/students/{student_id} — 更新学员

- 请求体：可更新 `name / cls / status` 等字段；404 学员不存在

### 3.6 DELETE /api/v1/students/{student_id} — 删除学员（软删/硬删由实现决定，404 不存在）

### 3.7 POST /api/v1/students/import — 批量导入

- Content-Type：`multipart/form-data`，字段 `file`（CSV：id,name,cls,…）
- 响应 data：`{created, updated, skipped, errors[]}` 汇总
