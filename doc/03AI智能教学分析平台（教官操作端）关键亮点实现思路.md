## 一、产品核心关键内容

### 1.1 产品定位
AI智能教学分析平台（教官操作端）是面向机修培训的教学决策助手。通过接收边缘端（touch_ui_plugin）上报的整包报告、实时增量事件、超时抓拍证据，自动完成数据解析、统计聚合、五维诊断、单轮评分，并为教官提供行动建议、学员追踪、教学闭环验证和驾驶舱看板。

### 1.2 数据链路
```
端侧上报（4接口） → 解析入库 → 统计聚合 → YAML规则驱动的诊断/评分 → 行动建议 → 看板/详情 → 闭环验证
```

### 1.3 平台必须实现的 4 个端侧接口
| # | 接口 | 方法 | 功能 |
|---|------|------|------|
| 1 | `{base}/api/v1/reports` | POST | 接收轮次结束整包报告 |
| 2 | `{base}/api/v1/events` | POST | 接收实时增量事件（每2秒攒批） |
| 3 | `{base}/api/v1/evidence` | POST (multipart) | 接收超时抓拍证据图（BMP） |
| 4 | `{base}/api/v1/students` | GET | 提供学员台账，供端侧同步 |

### 1.4 核心功能模块
- **学员管理**：档案 CRUD、批量导入、检索、对外提供台账。
- **报告管理**：整包报告接收、解析、详情、检索、原始 JSON 留存。
- **实时事件**：接收增量事件，用于看板实时进度与整包校验。
- **证据管理**：BMP 落盘、幂等去重、异步转 JPG、缩略图、诊断关联。
- **统计分析**：步骤用时分布、学员累计、趋势计算。
- **五维诊断**：平均用时、操作错误、顺序/遗漏/重复、步骤间隔、用时标准差。
- **单轮评分**：基于子步骤用时的多系数评分模型，输出总分与等级。
- **教学闭环**：教学调整事件记录，自动对比调整前后指标，生成改进报告。
- **驾驶舱看板**：今日概览、高频错误 TOP5、需关注学员、近 7 天趋势。
- **轻量化部署**：SQLite 单文件、FastAPI 单进程、前端静态托管、每日备份。

## 二、诊断与评分 YAML 配置驱动设计

### 2.1 为什么采用 YAML 配置驱动
- **现场可调**：教官或实施人员可直接修改 YAML 文件调整诊断阈值、评分权重，无需修改代码或数据库。
- **版本管理友好**：YAML 是纯文本，便于 Git 管理、备份和对比。
- **模板化**：不同工种/班次可使用不同的诊断和评分模板，通过切换 YAML 文件即可。
- **解耦**：诊断逻辑和评分逻辑与规则数据分离，引擎只负责计算，规则由配置提供。
- **快速迭代**：调整规则无需重新部署应用，仅需重载配置（或重启服务）。

### 2.2 配置文件结构

#### 2.2.1 诊断规则 `config/diagnosis_rules.yaml`

> 【v1.1 更新】实际实现采用**按工序分组**结构（对齐技术方案 v1.2 §5.1）：
> `processes[name].rules` 为工序专属规则，`common_rules` 为通用规则，
> 解析优先级为 工序专属 → common → 内置默认；`substep_index` 为空（null）
> 表示该类型规则对该工序**所有步骤**生效。

```yaml
# 五维诊断规则配置（实现结构 v1.1）
version: "1.0"

# 工序专属规则（优先级高于 common_rules）
processes:
  - name: "拆解"
    rules:
      - type: bottleneck          # 全班性瓶颈：平均用时 > SOP×threshold
        substep_index: null       # null=所有步骤；也可指定单个步骤序号
        threshold: 1.5
        enabled: true
        suggestion: "拆解该步骤平均用时过长，建议下次课重点讲解"

      - type: error               # 顽固性错误：遗漏率 > threshold
        substep_index: null
        threshold: 0.30
        enabled: true
        suggestion: "拆解该步骤遗漏率高，需增加专项训练"

      - type: sequence            # 顺序混乱：顺序错误率 > threshold
        substep_index: null
        threshold: 0.20
        enabled: true
        suggestion: "拆解该步骤顺序混乱，需强调步骤间依赖关系"

      - type: interval            # 步骤间隔：平均间隔 > threshold (ms)
        substep_index: null
        threshold: 5000
        enabled: true
        suggestion: "拆解该步骤与下一步衔接卡壳，需明确操作逻辑"

      - type: stddev              # 用时标准差：标准差 > 平均值×threshold
        substep_index: null
        threshold: 0.5
        enabled: true
        suggestion: "拆解该步骤学员用时差异大，建议分享经验统一手法"
  # - name: "组装" ...（同结构，阈值可按工序差异化）

# 通用规则（所有工序共享，优先级低于工序专属）
common_rules:
  - type: regression              # 学员退步预警：最近3次平均分 < 前5次×threshold
    window_recent: 3
    window_history: 5
    threshold: 0.85
    enabled: true
    suggestion: "学员近期成绩退步，建议安排个别辅导"
  # bottleneck / error / sequence / interval / stddev 同样可配通用兜底
```

#### 2.2.2 评分规则 `config/scoring_rules.yaml`
```yaml
# 单轮评分规则配置
version: "1.0"
default:
  max_score: 10.0            # 每个子步骤基础分
  time_weight: 0.4
  accuracy_weight: 0.4
  sequence_weight: 0.2
  timeout_penalty: 0.5       # 超时额外扣分系数
  grade_levels:
    - min: 90
      level: "优秀"
    - min: 75
      level: "良好"
    - min: 60
      level: "合格"
    - min: 0
      level: "不合格"

substeps:
  - index: 1
    std_duration_ms: 12000   # SOP标准用时
    max_score: 10
  - index: 2
    std_duration_ms: 8000
    max_score: 10
  - index: 3
    std_duration_ms: 15000
    max_score: 10
  # ... 更多子步骤

# 整轮扣分规则
global_penalties:
  unexecuted_deduct: 2       # 每个未执行子步骤扣2分
  repeat_deduct: 1           # 每次重复操作扣1分
  timeout_total_multiplier: 0.9  # 轮次超时总分乘0.9
```

### 2.3 加载机制与实现思路

#### 2.3.1 启动加载
应用启动时，从 `config/diagnosis_rules.yaml` 和 `config/scoring_rules.yaml` 读取配置，解析为内存中的规则对象（如 `DiagnosisRule`、`ScoringRule` 数据类）。若文件不存在，使用内置默认值并生成示例文件。

```python
import yaml
from dataclasses import dataclass

@dataclass
class DiagnosisRule:
    type: str
    substep_index: int
    threshold: float
    enabled: bool
    suggestion: str

def load_diagnosis_rules(path="config/diagnosis_rules.yaml"):
    with open(path, "r", encoding="utf-8") as f:
        data = yaml.safe_load(f)
    rules = []
    for item in data.get("rules", []):
        rules.append(DiagnosisRule(**item))
    return rules
```

#### 2.3.2 热重载（可选）
提供管理接口 `POST /api/v1/config/reload`，重新读取 YAML 文件并更新内存中的规则，无需重启服务。界面上的“系统设置”页可触发。

```python
@router.post("/api/v1/config/reload")
async def reload_config():
    global diagnosis_rules, scoring_rules
    diagnosis_rules = load_diagnosis_rules()
    scoring_rules = load_scoring_rules()
    return {"code": 0, "message": "配置已重载"}
```

#### 2.3.3 与数据库的关系
- YAML 作为**规则定义源**，程序启动时加载到内存。
- 数据库中的 `diagnosis_rules` 和 `scoring_rules` 表可作为**历史版本或界面编辑的持久化**，但引擎优先使用 YAML 配置。
- 若需要界面编辑，可将编辑结果写回 YAML 文件并触发热重载，保持单一数据源。
- 简化方案：完全由 YAML 驱动，数据库不存规则，仅存报告与评分结果。

### 2.4 诊断引擎实现（配置驱动）
```python
def diagnose_class(class_name: str, db: Session, rules: List[DiagnosisRule]):
    # 查询班级报告子步骤
    substeps = query_substeps(class_name, db)
    groups = group_by_substep(substeps)
    results = []
    for idx, items in groups.items():
        avg_duration = mean([i.duration_ms for i in items])
        std_duration = stdev([i.duration_ms for i in items])
        omitted_rate = count_state(items, 0) / len(items)
        # 遍历规则
        for rule in rules:
            if not rule.enabled:
                continue
            if rule.type == "bottleneck" and rule.substep_index == idx:
                std_ref = items[0].std_duration_ms or 1
                if avg_duration > std_ref * rule.threshold:
                    results.append(build_diagnosis(rule, idx, avg_duration, items))
            elif rule.type == "error" and rule.substep_index == idx:
                if omitted_rate > rule.threshold:
                    results.append(build_diagnosis(rule, idx, omitted_rate, items))
            # ... 其他维度
    return results
```

### 2.5 评分引擎实现（配置驱动）
```python
def score_report(report_id: str, scoring_config: dict):
    default = scoring_config["default"]
    substeps_config = {s["index"]: s for s in scoring_config["substeps"]}
    penalties = scoring_config["global_penalties"]
    
    total = 0.0
    for sub in substeps:
        cfg = substeps_config.get(sub.substep_index, {})
        std_ms = cfg.get("std_duration_ms", default.get("std_duration_ms", 10000))
        max_score = cfg.get("max_score", default["max_score"])
        time_factor = min(1.0, std_ms / max(sub.duration_ms, 1))
        acc_factor = {0:0.0, 1:0.5, 2:1.0, 3:0.5}.get(sub.state, 0.0)
        seq_factor = 0.7 if sub.sequence_error else 1.0
        score = max_score * time_factor * acc_factor * seq_factor
        if sub.timeout:
            score *= default["timeout_penalty"]
        sub.score = round(score, 2)
        total += score   # 【v1.1 修正】四系数直接累加；原 score×time_weight 存在双重计权，实现已按此口径
    
    # 整轮扣分
    total -= len(report.unexecuted) * penalties["unexecuted_deduct"]
    total -= repeat_count * penalties["repeat_deduct"]
    if report.finish_reason == 3:
        total *= penalties["timeout_total_multiplier"]
    
    report.total_score = max(0, round(total, 2))
    report.grade_level = get_grade_level(report.total_score, default["grade_levels"])
```

## 三、核心功能实现思路

### 3.1 报告接收与解析
- `POST /api/v1/reports`：校验、幂等、写入 `reports` 和 `report_substeps`，原始 JSON 存 `raw_data`。触发异步评分与看板刷新。
- `POST /api/v1/events`：按 `device_id + round_start_ms + event_ts` 幂等写入 `realtime_events`，更新实时进度缓存。
- `POST /api/v1/evidence`：multipart 落盘 BMP，幂等写入 `evidence`，异步转 JPG + 缩略图。
- `GET /api/v1/students`：返回学员台账 JSON。

### 3.2 五维教学诊断
- 基于 YAML 规则，计算每个子步骤的：平均用时、遗漏率、顺序错误率、步骤间隔、用时标准差。
- 触发规则则生成诊断结论，包含问题描述、行动建议、关联证据图（缩略图）。
- 支持按班级、时间段筛选。

### 3.3 单轮评分
- 基于 YAML 评分规则，对每个子步骤计算得分，汇总为单轮总分和等级。
- 整轮扣分：未执行、重复操作、轮次超时。
- 评分结果写入 `reports` 和 `report_substeps`，供学员追踪和看板使用。

### 3.4 学员个体追踪
- 聚合考试次数、平均分、最高/最低分、趋势、薄弱步骤 TOP3。
- 退步预警：最近 3 次平均分 < 前 5 次平均分 × 0.85。
- 前端展示成长曲线、历史报告。

### 3.5 教学改进闭环
- 教官记录“教学调整”事件。
- 平台自动对比调整前后班级平均分、完成率、诊断指标变化。
- 生成改进效果报告（如“步骤3平均用时从12.3s降至9.8s，降幅20%”）。

### 3.6 教官驾驶舱看板
- APScheduler 每日凌晨预计算：今日概览、高频错误 TOP5、需关注学员、近 7 天趋势。
- 结果写入 `dashboard_cache`，前端毫秒级读取。
- 实时数据（如今日考试人数）可实时查询。

### 3.7 超时抓拍图像处理
- 两通道接收（实时/整包兜底），按 `device_id + round_start_ms + sub + ts` 幂等去重。
- BMP 落盘，异步转 JPG 并生成缩略图。
- 诊断触发时自动关联该子步骤证据图，前端课堂复盘可直接展示。
- 默认保留 90 天，定时清理。

### 3.8 操作记录与评分合并
- 实时事件用于看板进度与整包校验；整包报告为准，含完整 `events` 与 `substeps`。
- 按 `device_id + round_start_ms + event_ts` 幂等合并，去重排序。
- 生成完整时间线：每步开始/完成/超时/中断 + 关联抓拍图。
- 整包到达后立即触发评分引擎，计算总分、子步骤得分、等级。

## 四、设计亮点

| 亮点 | 说明 |
|------|------|
| **YAML 配置驱动** | 诊断阈值、评分权重全部由 YAML 文件定义，现场可调，无需改代码；支持模板化、版本管理、热重载。 |
| **从数据到行动** | 每个诊断结论都配有明确的“教官该做什么”建议，而非冷冰冰的数字。 |
| **教学闭环** | 诊断→改进→验证，形成完整的教学优化循环，改进效果可量化。 |
| **五维诊断** | 覆盖用时、错误、顺序、间隔、标准差五个维度，全面识别教学瓶颈。 |
| **单轮评分** | 基于子步骤用时的多系数评分模型，客观量化操作水平，等级划分清晰。 |
| **证据支撑** | 超时抓拍图与诊断关联，课堂复盘有据可依；BMP→JPG 转换，缩略图 + 原图分级展示。 |
| **实时+整包合并** | 实时事件用于看板进度，整包报告用于最终评分与诊断，幂等键去重，数据完整。 |
| **轻量化部署** | SQLite 单文件 + FastAPI 单进程 + 前端静态托管，内存 < 350MB，无需 Nginx/Redis/Celery。 |
| **前端轻量构建** | Vite 5 + Element Plus 按需 + ECharts 按需 + 路由懒加载 + gzip，首屏 gzip 后 < 500KB，适配低配主机与触屏一体机。 |
| **学员个体追踪** | 每位学员成长轨迹清晰可见，薄弱步骤 TOP3、退步预警，支持因材施教。 |
| **驾驶舱看板** | 预聚合缓存，毫秒级响应；今日概览、高频错误 TOP5、需关注学员一屏掌握。 |

## 五、总结

本文档说明了 AI 智能教学分析平台（教官操作端）的核心关键内容，重点阐述了**诊断与评分由 YAML 配置驱动**的技术实现思路。通过 YAML 文件定义诊断规则和评分规则，实现了规则与代码解耦、现场可调、模板化复用，同时结合五维诊断、单轮评分、教学闭环、驾驶舱看板等核心功能，为教官提供了从数据到行动建议的完整教学决策助手。

设计上兼顾了功能完整性与轻量化部署，前端采用按需构建与 gzip 压缩，后端单进程 FastAPI + SQLite，整体资源占用低，适合单机 x64 Ubuntu 环境，教官开箱即用。本方案可作为开发、验收与合同交付的基准文档。
