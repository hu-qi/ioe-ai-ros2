# 取消仓位编号（名称）修改功能-技术方案

> 状态：已审批并实施（2026-08-27）

## 一、需求

取消 app_mgr 的**仓位编号（名称）修改**功能（前后端），理由：
1. 仓位名称编号 MES 系统也在使用，仓位规划固定 24 个，项目开始即固定、修改频率极低；
2. 运行中修改名称不实现（不需要）；即使项目调整需改名，也通过**修改配置后重启项目**完成（物流场景可中断调整）；
3. **保留仓位显示类型（cargo_type）编辑**（原 bayEditModal 类型选项，写 app_mgr yaml bay_configs 热加载）。

### 保留（不动）
- **类型编辑**：bayEditModal cargo_type select + `API.setConfigBay` + 后端 `reload_config` 更新 cargo_type（yaml 热加载）；
- **baySortByNum 排序**（渲染按编号排序，显示正确性，与改名无关）；
- **prune_stale 修剪**（清理真实删除/消失仓位，方案 A 保留）；
- **区域标题改名**（zone-title → localStorage 展示名，非仓位编号）；
- **calibration 页 ROI 多边形绘制/选中/删除**（deleteArea 保留）；
- api.js `getCalibrationParam/setCalibrationParam`（P4 校准代理，既有能力）。

5. bay_status_fusion_plugin.py：删 _rename_detection/_pos_map 与 _collect_pos_map/_detect_and_apply_renames；帧序还原；

## 五、边界与假设
- 名称修改仍可通过**改 OPS/rtsp 配置后重启**实现（不在本需求范围，不提供运行中改名）；
- 区域标题（zone_title localStorage）与仓位编号无关，保留；
- calibration 页仅移除「重命名」入口，ROI 编辑其余功能不受影响；
- 板端部署版本 = 工作区 app_mgr_object-0.2.0(标准版)。
