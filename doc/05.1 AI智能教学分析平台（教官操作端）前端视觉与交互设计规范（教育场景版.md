# 05.1 AI智能教学分析平台（教官操作端）
## 前端视觉与交互设计规范（教育场景版）

> 版本：v1.1（少跳转交互优化版）  
> 对应前端规划：04 前端核心界面规划方案  
> 使用环境：教官办公室台式机，**Web 浏览器（鼠标 + 键盘，非触屏）**  
> 设计目标：简洁、专业、教育场景友好，突出**实时动态**与**五维诊断**两大核心，兼顾**操作记录与评分**的完整性；以“**工作台优先、上下文保持、渐进披露、就地操作**”为交互原则，尽量减少页面级跳转，避免频繁打断教官的分析与教学决策过程。

---

## 一、设计风格定位

| 维度 | 定位 |
|------|------|
| 风格关键词 | 简洁、专业、克制、教育感、数据驱动 |
| 参考气质 | 教育管理后台 + 数据分析平台（类似学校教务系统 + BI 看板的融合） |
| 色彩基调 | 以**蓝灰**为主色，**橙色**为强调色，**绿/红**为状态色 |
| 信息密度 | 中高密度，一屏内呈现核心信息，避免过度留白 |
| 视觉层次 | 通过卡片、分割线、字号、颜色区分层级，减少装饰性元素 |
| 动效 | 克制，仅用于状态变化提示（如新事件高亮、进度条过渡） |

**为什么这样定位**：
- 教官日常使用，需要长时间注视屏幕，蓝灰主色降低视觉疲劳。
- 教育场景强调“诊断→行动”，橙色强调色用于行动建议、关键指标，引导注意力。
- 数据密集但需清晰，避免花哨装饰，突出内容本身。

## 二、核心交互原则：少跳转、不中断

### 2.1 交互设计目标

本平台面向教官办公室 PC 端高频使用场景。教官的核心任务不是“浏览页面”，而是持续完成“**发现问题 → 查看原因 → 核验证据 → 判断学员 → 采取教学行动**”的分析闭环。

因此，首页应定位为**教学分析工作台**，而不是各功能页面的导航入口。能够在当前上下文完成的查看、筛选、分析和轻量操作，原则上不进入新页面。

> **核心原则：能原地完成，就不跳转；能用 Drawer 保持上下文，就不进入独立详情页。**

### 2.2 三级交互层级

| 层级 | 交互方式 | 适用场景 | 是否改变 Route |
|------|----------|----------|----------------|
| 一级 | 原地联动 / 展开 / 筛选 | 指标筛选、图表联动、列表过滤、诊断展开 | 否 |
| 二级 | Popover / Lightbox / 右侧 Drawer | 学员摘要、报告摘要、诊断详情、证据大图 | 否 |
| 三级 | 独立页面 | 完整报告、长期学员分析、诊断中心深度分析 | 是 |

**默认优先级：一级 > 二级 > 三级。**

### 2.3 页面跳转控制规则

- 一个典型教学分析任务中，页面级 Route 切换应尽量控制在 **≤ 1 次**。
- 不允许仅因为“查看更多”就机械创建新页面。
- 从工作台进入独立页面时，必须保留原有**班级、工序、时间范围、筛选条件、分页状态和滚动位置**。
- 返回工作台时恢复离开前的上下文，不重新初始化页面。
- 同一对象的连续查看优先在 Drawer 内切换，例如上一位/下一位学员、上一份/下一份报告。
- Drawer 内允许继续查看二级信息，但避免 Drawer 套 Drawer；需要进一步深入时，在当前 Drawer 内切换内容或进入独立页面。

### 2.4 工作台联动原则

首页各区域不是彼此孤立的卡片，而应形成联动：

```text
指标卡片 / 趋势图 / 五维诊断
            ↓ 点击
      更新当前筛选上下文
            ↓
需关注学员 / 最近完成轮次同步过滤
            ↓ 点击对象
       右侧 Drawer 查看详情
            ↓ 必要时
       进入完整深度分析页
```

例如点击“待辅导学员 3”，不跳转列表页，而是：
1. 指标卡片进入选中态；
2. “需关注学员”区域自动过滤为对应 3 人；
3. “最近完成轮次”同步显示相关记录；
4. 必要时平滑定位至对应区域；
5. 点击具体学员后，从右侧打开学员 Drawer。

## 四、字体与排版

### 4.1 字体族
```css
font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC",
             "Hiragino Sans GB", "Microsoft YaHei", "Helvetica Neue", Arial, sans-serif;
```
- 使用系统字体栈，避免加载 web font，提升加载速度。
- 中文优先 PingFang SC / Microsoft YaHei，保证清晰度。

### 4.2 字号层级

| 层级 | 字号 | 行高 | 用途 |
|------|------|------|------|
| H1 页面标题 | 20px | 28px | 页面主标题 |
| H2 区域标题 | 16px | 24px | 卡片标题、区块标题 |
| H3 小节标题 | 14px | 22px | 表格标题、图表标题 |
| 正文 | 14px | 22px | 表格内容、说明文字 |
| 辅助文字 | 12px | 18px | 时间、备注、占位 |
| 数字强调 | 28px | 36px | 指标卡片数值 |
| 数字次级 | 20px | 28px | 报告总分、等级 |

### 4.3 排版原则
- 左对齐为主，数字右对齐（表格中）。
- 段落间距 8px / 16px，卡片内边距 16px / 20px。
- 标题与内容间距 12px，区域之间间距 20px。

## 七、报告详情与 Report Drawer 设计

**默认入口：Report Drawer；完整报告页作为深度复盘入口。**

教官从首页“最近完成轮次”、学员历史记录或诊断证据进入单次训练时，首先打开右侧 `ReportDrawer`。Drawer 建议宽度为视口的 42%~52%，最小 640px、最大 960px。Drawer 内优先呈现总分、等级、异常步骤、关键时间线、关键证据和诊断建议，使多数判断无需离开工作台即可完成。

只有在需要查看完整操作时间线、全部子步骤得分、全部证据图或进行课堂复盘时，点击“查看完整报告”进入独立报告页。

## 八、学员详情与 Student Drawer 设计

**默认入口：Student Drawer；长期个体分析页作为深度分析入口。**

## 九、诊断中心与 Diagnosis Drawer 设计

**默认入口：Diagnosis Drawer；诊断中心作为跨班级、跨时间的综合分析空间。**

## 十、交互细节规范

### 10.1 悬停（Hover）

| 元素 | 效果 |
|------|------|
| 表格行 | 背景 `#F5F7FA` |
| 卡片 | 阴影加深 `0 4px 16px rgba(0,0,0,0.10)`，轻微上浮 |
| 按钮 | 背景加深 10% |
| 链接 | 下划线 |
| 缩略图 | 放大 1.05 倍，显示“点击查看”提示 |
| 图表数据点 | 显示 tooltip |

### 10.2 点击（Click）

| 元素 | 默认行为 | 页面跳转 |
|------|----------|----------|
| 指标卡片 | 原地切换筛选状态，联动下方学员/轮次数据，必要时平滑定位 | 否 |
| 学员姓名 | 打开右侧 `StudentDrawer` | 否 |
| 诊断条目 | 原地展开摘要；继续查看时打开 `DiagnosisDrawer` | 否 |
| 缩略图 | `Lightbox` 大图查看器，支持左右切换 | 否 |
| 最近完成轮次整行 / 查看详情 | 打开 `ReportDrawer` | 否 |
| 图表数据点 | 高亮当前点并联动过滤相关明细 | 否 |
| Drawer“查看完整报告” | 进入完整报告页 | 是 |
| Drawer“查看长期分析” | 进入完整学员分析页 | 是 |
| “进入诊断中心” | 继承当前筛选条件进入综合诊断页 | 是 |

### 10.3 Drawer / 弹层规范

- **Drawer 优先于 Dialog**：需要边看原页面边查看详情时统一使用右侧 Drawer。
- **Dialog**：仅用于确认操作、短表单或必须聚焦的临时任务。
- **Lightbox**：仅用于证据图片查看，不承载复杂业务信息。
- Drawer 打开后，背景页面保持原状态，不刷新、不重置筛选。
- 关闭 Drawer 后焦点返回触发元素，键盘用户可继续原操作。
- Drawer 内顶部固定：对象名称 + 核心状态 + 关闭按钮；底部如存在关键操作，可固定操作栏。
- 禁止无必要的多层 Drawer；详情继续深入时优先在当前 Drawer 内切换内容。
- 支持 `Esc` 关闭，浏览器后退键应优先关闭当前 Drawer/浮层，而不是直接离开工作台。

### 10.4 状态保持与返回

- 工作台筛选条件写入 URL Query 或前端可恢复状态，刷新后可恢复主要筛选。
- 从独立详情页返回时恢复原滚动位置、分页、排序、筛选和选中卡片。
- Drawer 切换对象时不触发整页 Skeleton，仅 Drawer 内容局部加载。
- 用户连续查看多个学员/报告时，支持“上一条 / 下一条”，避免反复关闭再打开。
- 进入独立页面前若存在未完成编辑或教学记录，应明确提示，避免上下文丢失。

### 10.5 键盘快捷键

| 快捷键 | 功能 |
|--------|------|
| `Ctrl+F` | 全局搜索 |
| `Esc` | 关闭弹窗/抽屉 |
| `←/→` | 大图查看器切换 |
| `Enter` | 确认操作 |

### 10.6 加载与空状态

| 状态 | 设计 |
|------|------|
| 加载中 | 骨架屏（Skeleton），保持布局稳定 |
| 无数据 | 插画 + 提示文字 + 操作按钮（如“暂无诊断结果，请先完成一轮训练”） |
| 错误 | 红色提示条 + 重试按钮 |

## 十一、教育场景适配要点

| 要点 | 设计 |
|------|------|
| **专业感** | 蓝灰主色，克制装饰，突出数据与建议 |
| **清晰度** | 中高信息密度，一屏内呈现核心，避免频繁滚动 |
| **可读性** | 系统字体，正文 14px，数字突出，状态色区分 |
| **行动导向** | 每条诊断带建议，每个指标可点击，引导教官下一步操作 |
| **上下文保持** | 优先原地联动与 Drawer，避免“跳过去—看完—再返回”的反复操作 |
| **少跳转** | 典型分析任务 Route 切换尽量 ≤ 1 次，完整报告等深度任务才进入独立页面 |
| **课堂复盘** | 证据图缩略图 + 大图查看，支持课堂展示 |
| **长时间使用** | 低饱和背景，避免刺眼，减少视觉疲劳 |
| **打印友好** | 诊断报告、学员报告支持导出 PDF，排版清晰 |

## 十三、总结

本视觉与交互设计规范围绕**教官核心使用场景**，以**简洁、专业、教育感**为视觉基调，以**工作台优先、上下文保持、渐进披露、就地操作**为交互基调，突出两大核心：

1. **实时训练动态**：首页左侧卡片，进度条 + 事件流 + 抓拍缩略图，一眼看清当前训练，并保持实时观察上下文。
2. **五维诊断热点**：首页核心区域，每条诊断带行动建议 + 证据缩略图，通过原地展开和 Drawer 完成大部分分析，直接指导教学。

同时完整覆盖：
- **操作记录与评分**：报告详情页时间线 + 得分明细 + 证据图墙。
- **学员个体追踪**：学员详情页趋势 + 薄弱步骤 + 退步预警。
- **教学闭环**：教学调整记录 + 改进效果对比。
- **低打断交互**：指标原地联动、图表联动明细、学员/报告/诊断 Drawer、证据 Lightbox。
- **深度任务分流**：仅完整报告、长期个体分析和综合诊断进入独立页面。
- **按工序区分**：所有界面支持工序筛选。

设计针对 PC 浏览器（鼠标 + 键盘）优化，采用悬停、原地联动、Drawer、Lightbox、键盘快捷键等交互，配合 Element Plus + ECharts 轻量构建，首屏 gzip 后 < 500KB，适合教官办公室台式机使用。

交互验收时重点检查：**是否存在不必要的页面跳转、返回后上下文是否丢失、典型任务是否能在工作台 + 单个 Drawer 内完成、页面级 Route 切换是否尽量 ≤ 1 次**。

本规范可作为前端开发、交互实现与视觉验收的统一基准文档。
