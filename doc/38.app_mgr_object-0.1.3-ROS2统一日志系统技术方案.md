## 1. 问题分类与改造策略

### 1.1 三种日志模式

| 模式 | 代码特征 | 文件数 | 改造策略 |
|---|---|---|---|
| **模式 A: ROS2 直接** | `self.logger = node.get_logger()` | 11 | ✅ 无需改动 |
| **模式 B: 混合降级** | `self.logger = logger or logging.getLogger(__name__)` | 29 | 调用方注入 ROS2 logger，降级分支保留 |
| **模式 C: 纯 Python** | `logging.getLogger(__name__)` / `self._get_logger()` | 3 | 构造函数增加 `node` 参数 |
| **模式 D: print()** | `print(...)` | 3 文件 / 7 处 | 替换为 `self.logger.xxx()` |

### 1.2 改造原则

1. **不破坏现有降级机制**：模式 B 的 `logger or logging.getLogger(__name__)` 模式保留，确保无 ROS2 环境也能运行
2. **调用方注入 logger**：所有插件的 `_configure_impl()` 或 `__init__()` 中创建组件时，传入 `node.get_logger()`
3. **零 print()**：全部 `print()` → `self.logger.info()` / `self.logger.error()`
4. **子 logger 命名**：web 层组件使用 `node.get_logger().get_child('Name')` 区分来源

## 2. 分模式改造方案

### 2.1 模式 B 改造：调用方注入 ROS2 logger（29 个文件）

**当前代码**（以 `trigger/trigger_engine.py` 为例）：
```python
class TriggerEngine:
    def __init__(self, ..., logger=None):
        self.logger = logger or logging.getLogger(__name__)
```

**组件侧无需改动**。改造集中在**调用方** — 各插件在创建组件实例时注入 ROS2 logger。

#### 2.1.1 调用方改造清单

以下是需要注入 logger 的插件（扫描 `plugins/` 下所有 `*_plugin.py` 文件确认调用点）：

| 插件 | 创建的组件 | 注入方式 |
|---|---|---|
| `bay_status_fusion_plugin.py` | `AreaStatusFilter`, `DeviceManager` | `logger=self.node.get_logger()` |
| `callback_handler_plugin.py` | `CallbackReceiver` | `logger=self.node.get_logger()` |
| `network_plugin.py` | `NetworkInterfaceManager` | `logger=self.node.get_logger()` |
| `rcs_adapter_plugin.py` | `RcsHttpClient` | `logger=self.node.get_logger()` |
| `status_poller_plugin.py` | `RobotCache`, `DestBayCache` | `logger=self.node.get_logger()` |
| `smart_trigger_plugin.py` | `TriggerEngine`, `TaskQueue`, `BatchMatcher`, `ScheduleChecker`, `ResourceLocker` | `logger=self.node.get_logger()` |
| `workflow_engine_plugin.py` | `WorkflowEngine`, `PersistenceManager` | `logger=self.node.get_logger()` |
| `object_status_plugin.py` | `SignalMonitor`, `StatusQuery` | `logger=self.node.get_logger()` |
| `task_monitor_plugin.py` | `TaskMonitor`（如存在） | `logger=self.node.get_logger()` |
| `web_monitor_plugin.py` | `AlarmManager`, `ControlExecutor` | `logger=self.node.get_logger()` |

**统一注入代码**：

在每个插件的 `_configure_impl()` 或 `__init__()` 中，找到创建组件的位置，在构造函数参数末尾添加 `logger=self.node.get_logger()`：

```python
# 示例：bay_status_fusion_plugin.py
self.area_filter = AreaStatusFilter(
    stable_threshold=...,
    timeout=...,
    logger=self.node.get_logger()      # ← 新增
)
```

### 2.3 模式 D 改造：print() 替换（3 文件 / 7 处）

#### 2.3.1 plugins/bay_status_fusion_plugin.py

```diff
- print(f"[DEBUG] 成功导入 BayStatus 自定义消息")
+ self.logger.debug(f"成功导入 BayStatus 自定义消息")

- print(f"[DEBUG] 导入 BayStatus 失败: {e}")
```

#### 2.3.2 plugins/event_bus.py

```diff
- print(f"事件处理错误: {e}")
+ # event_bus 没有 node 引用，使用 Python logging 降级
+ import logging
+ _fallback_logger = logging.getLogger('EventBus')
+ # 在 except 块中：
+ _fallback_logger.error(f"事件处理错误: {e}")
```

> **注意**: `event_bus.py` 是通用事件总线，不依赖 ROS2 Node。降级使用 Python logging 但通过 `getLogger('EventBus')` 命名，可在 ROS2 的 logging 配置中统一控制。

## 7. 生产部署日志控制

```bash
# 部署前设生产级别
ros2 param set /app_mgr_object log_level warn

# 故障排查时临时开 debug（无需重启）
ros2 param set /app_mgr_object log_level debug

# 持久化（通过 Web API）
curl -X PUT http://127.0.0.1:9183/api/config/params \
  -H 'Content-Type: application/json' \
  -d '{"params": {"log_level": "warn"}}'
```

`params.yaml` 当前已配置 `log_level: "info"`，所有 ROS2 logger 自动继承此级别。
